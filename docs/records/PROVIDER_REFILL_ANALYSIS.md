**本批剩余段变化页中，没有找到可证明为“同一来源再次填充”的整页。** 点0、2、6、8的目标页均观察到来源偏移变化；点3的1888 KiB中，1832 KiB观察到来源变化，另56 KiB整页含初始未知段被首次填充的记录。现有四份记录足以排除把这些页统称为同来源重复读取的解释。

## 源码能证明哪些事

本轮实际编译的`slot_observation.rs`和`dev.rs`与成功分段构建保存源码逐字节一致，副本和核对结果留在本机目录。沿用固定AgentENV基线及已验证的GET_DATA协议，不重新构建或接触运行设备。

- `slot_observation.rs:123–145`：每次修改一段，先将代次变奇数，写来源，再变偶数；READ在调用实际读取前使前缀失效。首部的状态更新在段失效之后。
- `slot_observation.rs:148–163`：完整READ成功后，先发布前缀段来源，再增加完整读取计数，最后发布完成首部。失败或部分读取不增加完整读取数；它们仍更新首部。
- `slot_observation.rs:172–174`及`dev.rs:117–138`：内核WRITE取数前先失效，再允许复制。每次额外取数通知也会改变代次。
- `scripts/provider_slot_cache.py:snapshot`：每个采集侧先读段表，再读物理映射，再读段表。一次配对共有四份段记录，但没有保存中间每个请求。

据此，来源判断只使用同一采集侧两份一致、代次为偶数的段；奇数代次或侧内变化继续记为证据不足。首部计数推断还要求：同一分配、两侧各自首部一致、代次为偶数、状态为完整READ且长度有效，计数没有回绕。

在这些条件下，单次完整READ使首部代次增加4、完整读取计数增加1；被覆盖的段代次增加4，尾部不变。两侧差值满足`首部代次差=4×完整读取数差`时，才使用已有单次/多次读取判定。不能仅凭计数差就拼接所有段的中间历史。

## 相同前后来源不能排除中间改写

合成反例设只读来源A全部为`0x11`，来源B全部为`0x22`，初始缓冲已保存A。比较两段历史：

```text
第一次历史：读取A，再读取A
第二次历史：读取B，再读取A
```

两段历史的前后四份段表、最后请求偏移和长度、完整读取数差2、首部代次差8、段代次差8全部相同，但第二次历史中间确实保存过B。因此，“前后来源相同＋代次按完整读取增加”不够证明期间字节始终不变。

恰好一次完整READ时，可在额外核对请求前缀长度、每段代次差和来源偏移后，证明该段历史是同来源再次填充；本批目标页没有满足此条件的实例。这个诊断也不替代guest缓存身份、物理驻留及版本检查，本轮没有将它接入准入规则。

## 推荐缩短host配对读取区间，不增加同来源例外

当前`scripts/live_task_cache.py:158–180`的顺序是：

```text
guest前表 → VMM第一次 → 缓冲前读
→ 后端/原始层前查 → VMM第二次 → guest后表
→ 后端/原始层后查 → VMM第三次 → 缓冲后读
```

缓冲两次观测之间夹着后端查询、guest发布等步骤，相关槽位最多完成59次READ。这是更值得缩小的采样区间；同来源例外在本批没有可补齐的整页。

建议仅在私有分段观测路径改为：

```text
guest前表 → VMM第一次 → 后端/原始层前查
→ 缓冲前读 → VMM第二次 → 缓冲后读
→ guest后表 → 后端/原始层后查 → VMM第三次
```

只移动两次缓冲观测，其他查询的相对顺序、次数和内容保持。缓冲观测同时位于guest前后表及VMM第一次/第三次检查之间，仍用四份段记录和原一致性条件；不暂停guest、不等待后端、不延迟设备请求，也不延长内容有效期。未启用分段观测的原路径保持。

现有文件只保存每次缓冲查询自身耗时，没有保存查询起止时刻，不能据此计算原配对区间或预报收益。最小新增记录是host单调时钟的查询开始、结束时间，用于报告实际配对区间；无需读更多负载数据或改Rust段表。

本次离线核对结束时，该顺序调整尚未实现。随后按新授权完成了[紧邻配对及一次短恢复](PROVIDER_COMPACT_PAIR.md)。更短的观测区间可能留下更多稳定记录，但确认量和任务阶段有关，不以“新增量一定上升”作为成功条件。
