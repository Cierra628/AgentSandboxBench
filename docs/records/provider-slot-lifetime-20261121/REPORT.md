## 改动
- 写入端增量补丁 `patches/agentenv-provider-slot-lifetime.patch` 接在 provider-segments 补丁后。每次创建槽位，以排他创建的唯一 .bin 文件名区分代；JSON 先写临时文件，写完才以匹配的唯一名发布，不覆盖已有文件。SlotObservation 持有自己发布的 JSON 路径和 .bin 的 TempPath。Drop 只撤下这份 JSON、标记释放、解除映射并释放自己的 .bin，不遍历目录。异常退出时仍可能留下文件；新代不用旧文件名。此次没有修改既有 daemon 或快照。
- 读取端 `scripts/provider_slot_cache.py` 将 VMM maps 中的设备路径、所在文件系统和节点 inode 与当前节点 stat 核对，并在打开槽位后重新核对含 st_rdev 的身份。对当前镜像及 dev_id 的每个候选，再以唯一文件路径、文件系统设备号和 inode 核对 provider 的实际映射，打开后复核。只有完整的槽位组才可读。保留原有进程身份、归属、队列覆盖和协议检查；不同读法的原有检查仍按原条件适用。无需向 JSON 补写宿主设备号；仅 dev_id 相同而文件未映射，不足以通过验证。
- 读数计算、PFN 去重、归属与阈值没有修改。变化是选哪些槽位、何时报无结果，以及初始化与释放时的工作；未测真实耗时或页数，不承诺数值不变。诊断文件在正常释放后不再保留，依赖收尾后扫描目录的历史审计不能直接用于新批次。
