2. 在`run_c4_sampling_controls.py`增加显式Cython任务选项。复用原两对顺序、资源检查和清理，不新建另一套驱动。Cython使用`input`目录、105份业务输入及原runner；不得套用Django的语法验收或C4的9898文件验收。`syntax_validation`保持`NOT_REQUESTED_ORIGINAL_EXTENSION_CHECK`，隔离检查使用`external_fixed_tools_and_extensions_and_tests`。
3. 复用原`validate_cython_outputs`，核对原退出、NumPy示例、双目录各18 passed、三个`.so`导入及实际提交。固定镜像证据使用已有成功Cython记录，7层、压缩303,214,315字节、linux/amd64，不重新联网只为重复核对。
4. 报告增加Cython名称和83步说明，保留每对带符号变化、逐步用时、各窗口及开启组采样成本／曲线；关闭组内存和采样CPU标为未测量，不填零。旧C4默认选项、旧计划文件解释和Django报告保持。

Cython代理准备、原HEAD、窄范围nft允许规则、命中计数及精确清理在开／关两组都必须保留。关闭采样不等于关闭网络准备或任务验收。必要检查覆盖上述分派、真实关闭、错误结果拒绝和失败清理；不重复无关完整测试。

## 资源与实际生效的超时

每次一个新私有服务／统计组和一个新8 GiB／2 vCPU guest，32 GiB自有卷，四次串行，成功清理后才进入下一次。每次分配前可用磁盘严格>58 GiB、MemAvailable>64 GiB，检查真实负载和源服务身份。失败卷保留，删除另获明确授权，不因后续轮次自动删除。

本次只读检查约61.874 GiB磁盘可用、MemAvailable约479 GiB，源容器停止，无运行容器或Firecracker；宿主Docker守护进程仍在，不停止或替换它。此快照不代替未来启动前检查。

**源码声明预算与实际生效限制不一致，不能承诺1800秒控制预算可用：**

| 位置 | 当前源码／实际限制 |
| --- | --- |
| `external_workload.budgets` | 业务900、控制1800、原生隔离2100、外层2400秒 |
| `validate-isolated-storage.sh` | 整个隔离验证在900秒触发TERM，120秒后仍未退出才强杀 |
| 隔离验证的调用预算 | 还会按剩余执行窗口夹紧，默认窗口20分钟 |
| 现有顺序驱动 | 每次外层工作流程1500秒watchdog |

900秒覆盖隔离准备、创建、业务与收尾，**不是保证业务单独能执行900秒**。旧成功控制程序287.189秒，低于当前限制，但不保证网络慢时也通过。建议本次对照沿用现有有效限制，不为做对照扩大旧入口超时；超时如实保留，核对自有清理后定位首个失败边界。

按旧控制程序估算四次累计约19.1分钟，另有每次隔离准备、报告和清理。它只是历史参考，不是运行时长承诺；每次1500秒watchdog四次合计100分钟，仍不含驱动前后工作，不把“约20分钟”写成总上限。若以后需要声明的较长Cython预算真正生效，应显式修改新路径并验证旧调用默认值，不在本次离线计划中暗改。
