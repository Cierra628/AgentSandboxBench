# host准备基线：哪些是实验开销，哪些要保留

## 结论：大基线来自准备路径，不能当作沙箱成本

离线核对2026-10-29两轮同组1→2短测后，已确认约14.5 GiB准备基线的主要来源：**整份旧卷放在RAM中，以及准备校验读取缓存文件形成的文件缓存**。7252 MiB的RAM镜像是当前实验的存储容器，不是AgentENV要求每个服务常驻的一块内存；其中镜像层文件仍是本轮服务的输入，不能直接卸掉容器后继续运行。

建议保留两种原始数据：`current`总记账，以及相对同一次准备基线的运行增量。部署总占用需要使用实际部署的存储路径再测；**不从现有current中直接扣掉整个基线，也不把文件大小当作已驻留内存扣除**。

本段只读保存的JSON／TSV、代码与配置，没有新服务、guest、任务动作、挂载、驻留查询或任务文件读取。原短测的功能、耗时和采样结论保持。

## 14804.512 MiB基线的数值分解

下面采用整轮PASS的补测；第一次有效采集用于交叉核对。

| 已采计数 | 补测基线（MiB） | 能说明什么 |
|---|---:|---|
| current | 14804.512 | 同组准备、控制程序和私有服务总记账；此时还没有guest |
| file | 14580.957 | 文件缓存总记账，已经包含下一行shmem |
| 其中shmem | 7252.000 | 与RAM准备镜像的已分配量完全一致 |
| file−shmem | 7328.957 | 其余文件缓存总量，尚无逐文件归属拆分 |
| anon | 121.324 | 控制程序和服务等匿名内存合计，尚无进程间拆分 |
| kernel | 78.469 | 组内内核记账，服务与实验准备混合 |

`current−file=223.555 MiB`，其中不仅有anon，还有kernel等；`current−file−anon−kernel=23.762 MiB`作为计数间差值保留。它不是另一个已经识别的物理对象，不能全归为匿名页或遗漏。各计数不是同步快照，现有字段不能继续解释这个差值。

首次基线current为14806.563 MiB、shmem同为7252.000 MiB、file−shmem为7329.012 MiB。两轮都保存了RAM镜像已分配字节数7604273152，与基线shmem逐字节相同；运行阶段每增加一个guest，shmem只另增0.0078125 MiB。大块shmem在guest创建前就已存在。

## 准备路径为何产生这块RAM和文件缓存

实际链路如下：

```text
旧volume.ext4.gz
  → 解压到tmpfs中的稀疏volume.ext4（逻辑20 GiB，分配7252 MiB）
  → 只读loop设备＋ext4挂载
  → 读取并校验各缓存文件
  → commits目录只读绑定到私有服务；其他选定文件复制到8 GiB可写卷
```

[`prepare_prettier6604_cache.py`](../../scripts/prepare_prettier6604_cache.py)第76～105行建立tmpfs、解压、挂载并生成全缓存清单；[`immutable_manifest`](../../scripts/validate_isolated_agentenv.py)第45～57行会读取每个普通文件进行原有完整性校验。这些读取发生在任务前，会使缓存变热。这里的`cold`只表示新建guest，不表示host文件缓存冷态。

本轮归档的`validate_isolated_agentenv.py`第764～787行没有再复制commits，第926～927行将RAM镜像中的commits只读绑定进服务。实际`prefix-roots.json`也记录了这个来源。因而**对当前入口，RAM镜像仍是活跃输入的后备存储；对普通部署，这层RAM整卷容器可以不用，但必须先改变输入路径**。

保存的`seed.json`列出下列路径大小。它们是逻辑文件长度总和，可能包含稀疏区，清单也没有保存inode身份；不是去重后的驻留量。清单覆盖整个准备种子，不等于原11步实际访问的文件集合，也不证明每项都是本任务必需。

| 文件类别 | 普通文件路径数 | 逻辑大小合计（MiB） | 当前用途 |
|---|---:|---:|---|
| commits | 31 | 6845.722 | 原始镜像层来源，仍通过只读挂载供服务使用 |
| deps | 12 | 180.298 | 内核、工具和运行依赖；选定内容还复制进可写卷 |
| configs | 10 | 0.016 | 镜像解析缓存 |
| indexes | 31 | 0.013 | 镜像索引 |
| remote-blocks | 21 | 0.341 | 已保存的远程块缓存 |
| convert-blocks | 0 | 0 | 本份种子没有普通文件 |
| 全部路径合计 | 105 | 7026.389 | 不能当作这105条路径的物理驻留并集 |

RAM镜像及其上ext4文件缓存属于不同层；逻辑内容相同也不能直接认作同一物理页。`file−shmem`还可能包含新8 GiB卷及其内文件、程序文件、元数据和日志等缓存，现有保存计数无法把7328.957 MiB全部逐项分配。

一个独立的收尾观察支持上述判断：补测成功后，guest、私有服务和8 GiB卷已全部清理，而RAM准备缓存尚未释放，host采样器最后一点仍有 **14390.680 MiB current**，其中shmem为7252.000、file−shmem为7030.117 MiB。它与源文件逻辑清单总量接近，但不能据此证明每个文件全部驻留。采样器随后才停止，再释放RAM缓存；没有释放后的同组采样，不虚构释放量。

## 用于部署密度时，各类对象怎样计入

| 对象 | 部署统计应怎样处理 | 现有证据的限制 |
|---|---|---|
| 临时RAM整卷与备份校验过程 | 作为实验准备方式单列；直接使用持久化文件可避免整卷RAM容器 | 当前入口仍依赖它，不能直接从原current减7252 MiB后宣称部署总量 |
| 实际需要的镜像层、内核和工具文件缓存 | 在服务／多个沙箱间共享，只按实际驻留物理页算一份；随默认回收变化 | 路径逻辑大小已知，逐文件驻留、唯一inode和组内／组外记账未采 |
| 原文件、复制文件、loop后备镜像及其内部缓存 | 区分实验复制和实际运行需要，不能把不同层都称为同一份共享文件 | 没有对象级驻留数据，不能计算可删除的重复内存容量 |
| 服务进程及必要内核开销 | 保留；不同guest不共享的内存也影响部署密度 | anon／kernel还混有实验控制程序，轻量模式没有进程级拆分 |
| 采样、控制程序、报告与测试日志 | 作为测量系统开销单列，部署不一定采用同样的程序 | 已有CPU／时延成本；内存没有独立记账，不能全部从anon或file扣除 |
| 原源服务、Docker等组外服务及旧共享缓存 | 节点固定开销单列；共享文件按实际归属补齐，防止跨组重复或遗漏 | 本轮current只覆盖新实验组，未证明所有共享对象都在组内 |

AgentENV当前源码的[`config/default.toml`](../../AgentENV/config/default.toml)第8～19及88～90行、[`src/cfg/image.rs`](../../AgentENV/src/cfg/image.rs)第128～140行，将文件放在home/cache目录，不要求用整卷tmpfs提供commits。它支持“不必保留实验RAM容器”的设计判断；具体生产文件系统和缓存占用仍由部署决定，不凭默认配置指定容量。

cgroup记账跟随内存对象的原分配组，不因后续读取者进入新组而自动转移；本机Linux文档`/home/yxli/linux-6.19.9-ioctl/Documentation/admin-guide/cgroup-v2.rst`的Memory Ownership节说明这一点。所以未来若直接绑定已有持久化文件，还必须处理旧缓存可能记在组外的问题，不能只去掉RAM副本然后把较小current全称为物理节省。旧实验约1.7 GiB差额不作为本轮的固定修正量。

## 本段结论与下一步

本次已完成对象分类、RAM镜像与shmem核对、准备及收尾时序核对，并明确剩余未知。当前同组1→2的运行增量574.504／1120.160 MiB及第二阶段净增545.656 MiB继续有效；它们回答的是本实验存储和准备条件下的组内净变化，包含旧guest的变化，不是扣除准备开销后的部署绝对占用或共享节省率。

后续[持久化输入离线确认](HOST_PERSISTENT_INPUT_OFFLINE.md)已确定独立方案：先恢复自有临时磁盘镜像，在新统计组中导入105条已验证路径到普通目录，清理临时来源后才创建服务。保留旧入口和完整性要求，不直接复用旧目标inode。准备前须严格超过54 GiB，后续[空间清理](STORAGE_CLEANUP_20261029.md)已达到当前门槛；后续[独立入口及模拟检查](HOST_PERSISTENT_INPUT_IMPLEMENTATION.md)已完成，真实输入恢复和实跑仍待资源及授权。

数值、分类及来源见[脱敏证据](evidence/host-current-baseline-offline-20261029.json)；本地分析脚本和日志在`.artifacts/host-current-baseline-offline-20261029/`。原始证据来自两轮的`seed.json`、`copied-input-hashes.json`、`prefix-roots.json`、阶段计数、`memory.tsv`和收尾结果；未读取已释放的镜像或任务文件。
