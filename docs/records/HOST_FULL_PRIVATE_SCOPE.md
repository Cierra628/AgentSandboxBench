# 完整GRPO／BPO文件副本对照：清单与观察阶段（2026-10-24）

**已核对十次完整运行。首轮完整对照固定为：GRPO、BPO各自比较19个共用初始系统盘层与133个独立文件；每组仍是一个私有服务、七个原角色，保留原并发、保存和恢复顺序。先做完整GRPO的一对，再做BPO的一对。**

选择初始19层作为主指标，是因为它们在十次运行中的层顺序、已有digest和文件长度完全一致；BPO本次生成的两个层每轮大小和digest均变化，不能把它们的容量差全部归因于共享。因此，BPO生成层保持原共享机制，单列驻留，不混进主收益。这是完整调度中的指定固定文件对照，不是所有共享文件的总收益。

本次范围核对只读取保存JSON元数据、原动作计数和相关源码，没有读取层文件内容、查询当前缓存、复制数据或启动服务。核对时入口尚未实现；后续[GRPO完整实跑](HOST_FULL_GRPO_PRIVATE_LIVE.md)及[BPO完整实跑](HOST_BPO_COPY_LIVE.md)均已完成。下文保留范围核对时的依据和安排，实际执行进度以上述报告为准。

19个初始层与已验证双沙箱对照使用的19文件一致，每套文件内容长度为5,565,854,720字节，约5.184 GiB。这里是文件长度，不是新测驻留容量。完整有序清单及十次运行的实际文件身份、使用者均在证据JSON。

| BPO初始19层 | 同上 | 同上 | 主对照，每guest一套 |

| BPO第24步生成层 | 1文件，主沙箱＋3晚恢复，共4使用者 | 保持同样的共享关系 | 同上 |

第11步生成层在已有五轮中的文件长度为1,175,552—10,145,792字节，第24步为614,400—9,043,968字节；两类各有5个不同的已有digest。它们不是跨运行固定不变的输入。后续若要把这两类也改成独立副本，理论上需分别7份／4份，BPO合计144文件，但必须先解决生成内容匹配，另立对照；144不是本轮安排的验收数量。

普通文件以device,inode（设备编号与文件编号）识别。原路径和仓库路径可能是同一inode的硬链接，只计一次；独立组要求真实复制后各自不同inode，不按路径、配置数或相同digest合并。禁止硬链接、符号链接或reflink替代独立副本，不改可写upper。

工具／只读盘后备、BPO快照内存设备和内存层、upper、卷槽、公共种子及归档均保留原行为，不复制、不乘实例数、不并入主容量差。两个4 GiB内存设备各供3个恢复实例使用，主沙箱不属于这两组；它们不能当作系统盘层。匿名页也不纳入。

## 同一调度内部比较，不把短实验结构搬过去

每个共享／独立组都使用**一个新私有服务、同一个实验cgroup和原七个角色**。两组用相同实验版本和固定卷大小，唯一干预是初始19层的实际文件身份；cgroup及内存／I/O记账先建立，预启动池关闭，源服务不替换。

- **GRPO：**按原入口并发创建7个新guest，全部就绪后并行执行各自完整路径。每组189实际动作：主29、3个早分支各21、两个晚分支各32、最后一个晚分支33；无保存／恢复。
- **BPO：**主沙箱先执行11步并保存，再执行至24步并保存，再完成主路径29步；随后按原顺序创建3个早恢复实例、3个晚恢复实例，最后并行执行六个原后缀。每组84实际动作：主29、早后缀各10、晚后缀8／8／9。两次保存、六次恢复；七条逻辑完整路径合计189动作，但不重新执行继承前缀。

短对照的“双服务、每服务一个新guest”不适用于这里。把BPO恢复实例分到多个服务会额外导出／导入快照，改变恢复路径；不能拿它代替原完整BPO。GRPO与BPO也不互当不共享基线。

## 最小接入位置：每个guest的最终系统盘配置

现有完整入口没有每guest独立lower的实验开关。仅换镜像标签不保证独立文件：解析器按manifest digest及仓库范围取缓存，BPO仓库还会通过已有文件或硬链接重新合并来源。

推荐只在**自有实验版本的系统盘运行配置生成位置**接入显式开关：共享模式保留一套；独立模式在P0前准备7套初始19层，每个实际guest使用其中一套。冷启动和BPO恢复都必须在提供程序打开lower前落实指向，并记录sandbox ID、运行目录、副本及来源。

并发创建顺序不等于角色顺序，不能为分配副本把原并发改成串行。可按运行目录分配独占副本套数，待sandbox创建后绑定真实角色；P1核对一套仅供一个guest、没有重用或闲置套数混入结果。BPO恢复配置可能从仓库重新指向主沙箱那套文件，必须在最终运行配置处重新指向该恢复实例的独立套数，不能以“准备时复制过”判为成功。

初始层按已确认的19个来源标识匹配，保留层字节内容与顺序；不得把BPO新生成层误当初始层复制。生成层、内存镜像、工具盘、快照提交和仓库对象均不改，不修改已打开的共享image.json，也不在并发创建时轮流改公共源配置。未启用开关时保持原行为。

观测复用现有有序lower关联、打开描述符和mincore查询。独立组单使用者文件全部查询；不能套用旧“至少两个使用者”筛选。未知或身份改变判为测量失败，不填零、不改原任务退出码。这条路线仍需离线实现和自有实验二进制准备，当前没有构建通过的结论。

## 主容量差、背景与成本分别记录

每种调度分别计算：

```text
D0 = 独立组初始19层副本的P0驻留 − 共享组初始19层的P0驻留
D1 = 独立组初始19层副本的P1驻留 − 共享组初始19层的P1驻留
结束时比例 = D1 / 独立组这批文件的P1驻留
```

差值保留正负、零分母保持未定义，并给D1−D0。BPO生成层逐步、逐组单列实际文件大小、已有digest和驻留，不把不同生成内容之差归成主共享收益。主指标不与生成层、ublk设备缓存、内存层、cgroup file或guest Cached相加，不再用7A换算。

复制／同步、P0身份准备、P0查询、P1关联、P1主查询及生成层查询分别记录起止和线程CPU。原工具累计只含原动作；原路径结束时刻仍放在P1之前，整轮继续包含新增查询所在的原计时区间。保存／恢复接口耗时不扣新增处理，复制和准备另列。本阶段没有关闭测量对照时只报告构成，不推算减速率。

## 预算与实跑顺序

沿用原完整GRPO 16 GiB、BPO 32 GiB的固定卷及写入／清理余量，再加6套初始19层文件长度，向上取整到整GiB。额外长度约31.102 GiB，不假设稀疏洞一定能减少磁盘，也不按旧观测峰值削减预算。共享组和独立组使用相同卷大小。

| 调度 | 建议每组固定卷 | 启动前可用磁盘须严格超过 | 当前约62.4 GiB |
| --- | ---: | ---: | --- |
| GRPO | 48 GiB | 74 GiB | 不足约11.6 GiB |
| BPO | 64 GiB | 90 GiB | 不足约27.6 GiB |

门槛包含原20 GiB保留和6 GiB余量；构建占用及实际负载须在实跑前重核，不能降低保留量。原RAM种子准备、卷内空间保护、超时与失败保留规则继续适用。现存16 GiB失败卷仍保留；即使以后获准删除这一份，约78.4 GiB也只够本表GRPO门槛，仍不够BPO。当前没有本轮新的删除授权，没有删除、迁移或压缩旧卷。

1. **先离线接入GRPO显式开关及清单。** 检查19来源／133独立身份、并发分配、旧默认、单使用者查询、P0／P1成本及失败清理。BPO另补仓库别名重新合并、初始层与生成层分开的用例。构建／检查按AgentENV本地规则，不安装到原服务。
2. **资源达标后，一对完整GRPO。** 共享／独立各189动作，共378；正式第一组作为必要新路径验证，不另加相近短测。每组通过才继续，失败先定位，不重跑成功任务、不自动删除失败卷。
3. **GRPO完成且BPO实现、资源就绪后，一对完整BPO。** 每组84实际动作，共168；合计4次保存、12次恢复，原进程／文件／进度检查保持。主指标必须是19／133文件，生成层保持7／4实际使用者，不改变原恢复机制。

首次两种调度各一对合计546个新原动作。旧五轮只作动作和对象关系依据，不充当新共享组的驻留观测，不把双沙箱比例外推完整任务，也不先承诺重复三对或五轮。

完成条件是同调度两组原动作、并发／批次顺序、最终补丁、原官方每实例0通过2失败保持；BPO保存／恢复有效；初始层副本身份、使用者、来源、P0／P1驻留及成本齐全，生成层和未知范围单列，原资源清理通过。官方原失败不等于重放失败。结果不要求达到85.714%，不按比例筛选或补轮。

本轮已确定离线清单和执行安排，没有可立即运行的新完整副本命令。下一步优先离线实现GRPO入口，在磁盘达标前不启动完整组；具体旧卷删除仍需单独确认。
