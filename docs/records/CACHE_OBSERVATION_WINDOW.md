## 可行的小调整及本轮不接入的理由

可将映射读取、直接偏移换算和原始层偏移换算放到第一次VMM读取前，仅用于当前私有分段provider批量路径。准备依赖guest前表、映射描述和不可变索引，不依赖第一次VMM页表结果；对应源码为`snapshot_cache_residency.py:162–206`及`snapshot_layer_metadata.py:64–87`。

该候选仍保持四次缓存查询的相对顺序；`provider前读 → VMM中读 → provider后读`不拆开；三次VMM读取仍包住全部provider及缓存查询。guest身份比较、三次映射比较、当前/旧版本、前后偏移变化失效和物理去重条件不变。其他旧调用路径不增加前提。

按已保存步骤耗时不变的排程推算，可从首末VMM观察范围移出14.901 ms准备工作，但总工作量和两次guest表之间的步骤总量不变。这是候选的时间位置变化，不是新延迟实测；现有记录也不足以确定哪张变化页会因此获得确认。

因此本轮不为该候选新增分支。更激进的重排也不采用：把guest后表提前到provider后读之前，会失去原guest身份对provider配对的覆盖；把最后VMM读取提前到后端后查询之前，会使最后查询落在VMM观察范围外；省略中间读取则会丢掉首末相同、中间变化的检查。
