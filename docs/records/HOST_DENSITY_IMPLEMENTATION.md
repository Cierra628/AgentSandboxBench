## 新入口怎样保持测量范围

新显式入口为`bash scripts/run-host-density.sh --output 新目录 --daemon 本次实验daemon`。每组新建cgroup，在输入导入及私有服务／guest创建前启用MemoryAccounting和IOAccounting，host每0.1秒读memory.current及file／anon／kernel／shmem，无PSS或周期mincore。每个guest沿用原单路径执行器和0.1秒meminfo采样；普通入口的默认值不改。

独立文件以`cp -a --reflink=never --sparse=always`准备在本次ext4卷中，检查不同设备号:inode和nlink=1；同步后用FIEMAP只查extent元数据，拒绝共享、未解析或重叠的数据extent。Docker挂载清单须没有逐目标文件／目标目录的bind替换。共用整个私有env目录的正常服务挂载不冒称为独立文件副本。

准备同步、私有服务健康之后，创建guest之前，对精确目标文件调用POSIX_FADV_DONTNEED，mincore只查一次P0并要求驻留0。运行中不清缓存、不暂停VM、不加读量或强制驻留；默认DAMON行为保持。

全部原路径及下载结束、官方检查开始前，执行器保留guest存活，由协调程序从sandbox ID绑定VMM，查询Firecracker GET /vm/config，沿实际user_rootfs配置和已打开文件核对下层inode集合；随后只查一次P1，再复核身份，放行原官方检查及正常清理。这是任务结束后的查询与收尾同步，不暂停guest。每次查询的墙钟和CPU、前后cgroup计数保存，current与mincore不相加或相减作为总物理内存。

Prettier两组统一使用80 GiB固定卷，为N=10的51.836 GiB下层文件逻辑总量及原任务写入保留空间。分配前要求严格>106 GiB可用（80 GiB卷＋20 GiB保护＋6 GiB余量），MemAvailable>64 GiB；准备输入仍沿原20／8 GiB有界路径，source释放后才分配运行卷。卷容量、卷内及host最小剩余空间按原磁盘采样保存，不降低原保护，不自动删除失败卷。
