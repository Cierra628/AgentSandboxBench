# 相同任务后缀的单／双沙箱对照设计（2026-10-20）

**执行前选定的范围：Prettier共同前缀11步保存一次，单沙箱执行`early_1`后缀10步，双沙箱各执行同样10步，共41个实际任务动作。** 本页记录当时的离线设计；随后已按新授权实现并完成一对，见[真实结果](HOST_FILE_MATCHED_TASK.md)。原`--restore-pair`仍只观测空闲恢复，新任务入口为独立选项`--matched-task`。下文保留设计依据和验收口径。

## 为什么不能直接使用现有两组数据

[最新短恢复](HOST_FILE_EXPANDED_RESTORE.md)验证了共享设备身份、采集和清理，但没有执行任务后缀。其N=2窗口内file增量为325.590–830.031 MiB，变化原因未确认，不能拿这段空闲数据代替任务缓存或性能结果。

离线逐段读取冻结动作清单和原采样的预期退出码，得到：

| 路径 | 共同前缀 | 后缀 | 全路径动作数 |
| --- | ---: | ---: | ---: |
| backbone | 5+6 | 7+6+5 | 29 |
| early_1 | 5+6 | 4+6 | 21 |
| early_2 | 5+6 | 4+6 | 21 |

`early_1`与`early_2`虽然同为10步后缀，动作清单并不相同；现有最终检查还要求前者保留修复补丁，后者没有补丁。下一轮选`early_1`重复执行，不把两个不同后缀叫作相同负载。范围是21步逻辑路径的恢复后10步，不冒充完整29步backbone。

依据：`scripts/run_prettier6604_grpo.py`的`execution_paths()`、`SampledPaths.do_bpo()`和`final_check()`；冻结输入`.artifacts/prettier6604/grpo-input-audit-20261008T120626Z/workload/`的`rollouts.json`、各段`actions.tsv`及`agent-sampling.json`。共同前缀第二个动作原预期退出127，继续原样保留；后缀10步预期均为0。[脱敏核对结果](evidence/host-file-matched-task-design-20261020.json)只列段名、数量和预期退出码，不复制命令内容。

## 各个量回答不同的问题

| 量 | 下一轮采集与用途 | 结论范围 |
| --- | --- | --- |
| host `memory.stat:file` | 每0.1秒，主曲线；同时保存shmem及file−shmem | 本测量组的文件缓存记账，包含shmem，可能延迟汇总或漏掉组外记账 |
| host anon、memory.current | 同期上下文，保存原值及各组恢复前增量 | 观察文件缓存减少时是否转为匿名内存，例如写时复制；不是精确物理并集 |
| 逐VMM及全组进程PSS | 每1秒；任务后另取一次直接读数 | 已映射内存按共享比例分摊后的占用，遗漏未映射缓存；不与file或mincore相加 |
| 共享内存设备驻留`D1`、`D2` | 后缀结束、guest仍存活时，以实际VMM映射关联的4 GiB内存ublk设备做mincore；双沙箱同一设备只计一次 | 这个设备缓存对象的全局驻留，包含组外记账；不等于guest page cache或全部host内存 |
| 原始内存层驻留 | 与上述设备同一检查阶段分项查询 | 后备层是另一缓存对象，保留各自查询时间；不与设备数值拼成同时物理并集 |
| 最终11根普通文件清单驻留 | 本轮guest及服务退出后、卸载前，保留既有查询 | 覆盖核对及净差分类，不作为N=1/N=2运行时驻留对照 |
| guest Cached、MemTotal−MemAvailable | 每个guest每0.1秒，沿用轻量采集 | guest层的缓存和内存曲线，与host file分图；不直接相减 |
| 工具用时和后缀用时 | 每个guest分别保留10步用时；双沙箱另记从放行到两者完成的墙钟时间 | 工具用时之和、并行完成用时和准备耗时分开，不用两份工作对一份工作的耗时比称减速 |

mincore使用现有不读取内容的查询，不预读、锁页或暂停采集。普通文件元数据稳定不代表缓存集合在查询期间不变；结果是带起止时间的扫描读数，不是瞬时冻结快照。现有设备扫描曾用3.287／4.820 CPU秒，因此放在任务计时结束后，不在命令执行中做重型扫描；扫描成本另列，后台回收仍可能在此期间改变驻留。

guest采样时钟与host时钟不直接相减。按实际会话和任务标记划分窗口，保留host调用开始／返回边界；没有校时证据的guest点继续使用各自采样程序的存活时间，不能贴上虚假的host精确时间。

## 公共准备只算一次，两个恢复前基线都保留

新统计组仍先于所有准备、新私有服务和guest创建，开启内存及I/O记账，关闭预启动池，不移动旧VMM。记录以下同步读数和单调时间：

1. `Fprep`：输入准备及服务就绪、还没有父guest。它包含公共输入、依赖和服务成本。
2. `F0_1`：共同11步保存完成、父guest删除、没有活动VMM，第一次恢复前。
3. `F0_2`：第一组任务、检查和删除完成，确认本组内存设备释放后，第二次恢复前。

主图保留原始file，辅助图分别画`F1(t)−F0_1`和`F2(t)−F0_2`，anon与current同样处理。负增量照实保留；两次基线差也报告，不解释成负的沙箱内存。不将输入准备、快照和固定服务开销乘二计作共享收益。此前7.082 GiB输入tmpfs镜像只是已测的一轮准备量，不能充当下一轮常数。

设备`D1`／`D2`是各组新恢复后实际存在的缓存对象，恢复前该设备尚不存在；它不包含上述公共准备总量。每组仍重新核对实际设备身份、容量及快照配置来源，不能沿用上轮设备号。N=2两个VMM必须映射同一设备；两组之间设备号可以不同。

固定顺序采用N=1后N=2，同一真实快照保留。第一组会影响第二组的原始层及服务缓存，第二组先恢复的guest也会多等待；两次基线不能消除这些影响。记录这些时间和各次原始层驻留，不清全局缓存，不额外填充，也不为数值接近而增加等待。此最小范围用于描述一次任务对照，不给稳定性能或共享因果百分比。

## 最小执行顺序与实现差别

1. 沿用普通guest内核、2 CPU/4096 MiB、现有后台回收默认状态及轻量采样配置。运行前检查实际负载、源服务身份和磁盘；24 GiB卷启动前须超过50 GiB可用，保留20 GiB保护量及6 GiB余量，原失败卷不删。
2. 执行共同11步，原生保存一次快照并删除父guest。保存原有暂停语义，测量不增加暂停。
3. N=1恢复一个guest，原边界和探针连续性检查通过后执行`early_1`的10步；记录任务结束标记，立即读取端点PSS，再查询运行时设备及原始层，之后做原补丁、独立功能和完整官方结果检查。删除本组guest，按已有有限超时确认设备释放，保存`F0_2`。
4. N=2从同一快照逐个恢复两个guest；全部恢复检查通过后并行执行相同的`early_1`后缀。每个实例保留独立输出和计时；两者均结束时按同样顺序取端点PSS和驻留，再分别做原功能与官方结果检查，随后删除。较早完成者的等待时长单列。
5. 按原流程停止自有服务，在卸载前查询最终11根清单并清理本次资源。失败卷和日志保留；不替换原服务，不改变udev或全机缓存策略。

不再固定增加5秒空闲窗口，不为凑齐周期PSS点而延长任务。短后缀若没有完整周期PSS，就使用明确标注的端点直接观察；端点仍不完整则记录缺口，不能补零。

最小代码改动是新增显式“相同后缀任务对照”模式，复用现有恢复、采样、设备查询、功能检查及清理。把**实例标识**与**原轨迹角色**分开：例如三个实例分别为`N1-a`、`N2-a`、`N2-b`，均引用`early_1`原动作和预期结果，但输出、会话、VMM身份及报告不能覆盖。不能只把`early_2`的清单替换成`early_1`，否则当前`final_check()`仍会错误地要求第二个实例没有补丁。旧空闲短入口、原双分支和普通29步入口的默认行为不变。

## 可以报告什么，以什么为完成标准

本轮实现前先补离线用例：三实例均绑定同一原后缀且输出独立、11+10+10+10=41实际动作、原127退出保留、两个N=2身份精确覆盖、偏离预期退出码或缺失结果不能通过、原入口保持。实跑第一组直接承担新路径验证；通过后完成双沙箱一组，总共一对，不另加空闲校准或三个完整任务。

完成条件是动作与预期结果、快照恢复、实际共享设备、两次恢复前基线、任务曲线和端点查询、采集退出及资源清理有完整证据。原官方失败结果保持原义，不能因运行器成功改成任务全通过。功能、采集覆盖、记账核对和清理分别判定；失败或缺失按对应项报告，达到范围即结束，不要求差额归零或观察到正收益。

结果按以下强度交付：

- 共同设备身份加按设备去重的mincore，可以说明两个恢复guest实际使用同一个缓存对象及其本轮驻留量；若`D2`接近`D1`，可说明这一个设备缓存对象的驻留没有随实例数成倍增长。数值增减本身仍包含任务和回收的影响。
- 可并列`2×D1`这个**假设两个独立设备各有D1驻留的线性参考**和实际`D2`。只有查询完整、D1为正时才可计算`(2×D1−D2)/(2×D1)`，负值保留，并明确标为“相对单沙箱线性参考”，不是实测不共享后端或优化因果节省率。固定顺序和不同缓存状态随结果一起保留；历史数据本次不补算比例。
- file曲线继续只描述组内记账。旧大卷1.766 MiB净不足仍未逐页解释；小镜像的udev归属不能作为大卷补偿，也不因新一轮没有正差额就判完整。**不据file输出完整物理节省率。** 已明确范围的设备mincore观察不依赖file完整记账，但不能扩展成全部host内存结论。
- anon、current和PSS揭示其他占用是否增加；它们不能和mincore拼出完整总量。本范围交付“指定设备缓存的物理驻留变化＋其他内存上下文”，不交付guest page cache精确物理对应或整host物理并集的节省百分比。

当前`report_host_file.py`的比较命令使用完整流程file峰值，会把公共准备重复外推，不用于本设计。后续新报告使用上述分阶段口径，不改写旧报告或历史结果。

设计阶段完成了动作数量、预期退出码、两个后缀清单差异及文档本地链接检查，复算脚本和回执保存在`.artifacts/host-file-matched-task-design-20261020/`。当时只改文档及脱敏核对证据，没有新增实跑；后续实现与真实结果使用独立证据目录，见结果页。
