## 默认逐项读取，显式启用才使用批量接口

`scripts/snapshot_cache_residency.py`新增`BatchEntries`和`SnapshotCache(..., batch_lookup=True)`。现有调用不传该参数，仍逐项读取，不要求批量符号、特定表布局或新增接收内存；`LiveTaskCache`本轮未改，在线入口尚未启用批量模式。

新模式复用创建时从自有bpftrace文件描述符得到的表信息，只接受普通HASH表、键8字节、值16字节、标志0，容量须为1–131072条。记录实际表信息，按容量分配一次并复用接收缓冲。两张131072容量表的键值缓冲合计6 MiB，这是接收容量，不是已测驻留量，也不加入guest缓存物理并集。

原查询号写入和全部`mincore`查询保持。`mincore`查询页是否驻留，不读取文件内容。它们完成后才调用一次只读批量接口；按本次请求偏移及查询号筛选，再按原顺序和重复次数生成结果。仅当前查询号、物理页号（PFN）非零且驻留位为1时，才返回确认页。

- `-ENOENT`表示读到表尾，仍使用其返回数量以内的数据；数量为0表示没有记录。
- 返回0表示未确认已读完整表；`ENOSPC`、`EFAULT`、不支持等错误均明确失败，不重试、不静默切回逐项读取。`EFAULT`的返回数量记为未知，不使用输出；数量超过容量也失败。
- 不读取接收缓冲未返回的尾部。旧查询号和缺失键按原输入行增加`missing_kernel_results`；查询号有效但PFN为0不增加该计数。
- 输入无文件偏移时输出0且不增加缺失计数。输出0仍表示未确认PFN，不表示物理占用为零。
- 新模式另记返回码及返回条数；原字段和默认模式的记录格式保持。

批量模式沿用当前私有单采集线程条件：一次查询返回前不开始下一次查询，同进程没有其他并发`mincore`调用。这个条件约束采集器的元数据表，不要求沙箱停止。BPF程序、查询前后次数、采集顺序、缓冲覆盖前失效及物理页准入规则均未改变。

## 一张新表，三种状态，只做一次接口验证

入口是`scripts/validate_snapshot_bpf_batch.py`，结果为`owned-map/result.json`。脚本只创建一张未固定到文件系统的自有表，不枚举或访问既有BPF表，也不挂探针。真实内核为`6.19.9+`；从这张表的文件描述符读取实际信息，得到HASH、键8/值16字节、容量8、标志0，接收缓冲192字节。

同一张表依次为空、写入4条、写满8条；没有创建三张表或重复运行实验。每个状态调用一次批量接口，并检查逐项读取在批量前后的表内容。查询号发布和驻留位在此脚本中是合成输入，实际执行的是表创建、信息、合成键值写入和读取接口，不是guest缓存采集。

| 0 | −2（ENOENT） | 0 | 与逐项读取一致 | 保持 |
| 4 | −2（ENOENT） | 4 | 与逐项读取一致 | 保持 |

合成键值包含旧查询号、PFN为0、未请求键；请求包含重复偏移、缺失偏移、无文件偏移及非驻留位。确认结果仍按原输入行计数。表未固定、未被BPF程序引用，唯一自有表文件描述符在结束时关闭，随后检查得到`EBADF`；正常和失败路径均只释放自有资源。

可复现调用如下，输出目录须尚不存在；这条命令会创建真实的自有小表：

```bash
timeout -k 5s 30s python3 -B scripts/validate_snapshot_bpf_batch.py \
  --output .artifacts/provider-bpf-batch-owned-map-recheck
```

## 回归和旧入口保持

53项相关测试通过，其中13项新增批量测试覆盖布局/容量限制、默认关闭、构造时保留实际表信息、末尾有效数据、空表、尾部旧数据、查询号、PFN为0、缺失/重复偏移和错误处理。错误用例使用模拟接口，不向实际内核传入无效地址。创建失败或读取失败均记录FAIL；读取失败仍关闭自有文件描述符，没有成功采样记录或回退。

另与本轮修改前保存的真实`SnapshotCache.query`对照，普通混合输入、空输入及全无文件偏移三组结果和原统计相同。偏移换算、归属计数、原BPF程序和在线采集顺序保持，源码比较通过。

原偏移对照脚本此前以“整份模块除offsets以外不变”限制候选；这会因本次独立查询改动而拒绝旧实验。现改为载入原采集类，只把当前`offsets`函数放进原采集的全局环境和类中，其余方法仍用采集版本；计数依赖检查及原参数、指标范围保持。新增测试确认候选不会执行新的查询方法。本轮没有重跑10点计时，也没有改写原偏移收益。

一次本地检查器错误地把AST函数调用节点当成常量，离线修正后通过；原始小表验证没有重跑。正常路径实测后仅完善验证脚本的失败阶段记录，失败清理由模拟测试核对，实际批量读取代码保持。
