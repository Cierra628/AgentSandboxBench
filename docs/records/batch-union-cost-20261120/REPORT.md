## 首次读取已在页缓存，不是磁盘冷读

输入是上轮七份角色结果，每份实际用两个文件：`process-restored-*/result.json` 和 `sets.npz`，共 **14 个文件、2,081,656 字节**。各支四来源集合已有序、支内已去重，合计 **257,466 个页号**。批级结果是 **166,440 个四来源页号**以及**独立的 19 个 provider 页号**；两集合不相加。所有对比方法均在计时外与原方法逐项核对两份集合，不只比较数量。

| 阶段 | 本轮第一次（ms / 占比） | 16 次重复均值（ms / 占比） | 成本随什么变化 |
|---|---:|---:|---|
| 打开并读完 14 个文件至内存 | 0.906 / 2.64% | 0.240 / 0.99% | 每文件一次打开/关闭，加上随字节数增加的拷贝 |

| **三段总计** | **34.275** | **24.307** | 占比用同列均值之比，不是取各段中位数相加 |

用 mincore 在首次读取文件内容**之前**检查归档文件，515/515 个文件页驻留；第一次读后仍为 515/515。重复读原始字节耗时中位 0.235 ms。旧现场是子进程刚写完文件后由父进程读取，文件后来被归档；没有保存原 inode 当时的驻留位和逐文件时钟。本轮第一次只是“本进程第一次读已驻留的归档文件”，不能还原当时的首次 I/O。未清宿主页缓存。实例结果校验包括角色名、工作 PID、沙箱 ID 和页数。

原驱动 `37531ae:scripts/paused_process_workers.py::Workers.merge` 中 `set.update(map(int,array))` **边转换边插入**，不是先建立七个支内哈希表。为计时，重放先收集 Python 整数列表，再逐支 update；已在支内去重，无需重复建集合。文件先整体读入内存，NPZ 解析另计。原代码访问 four 成员两次（第一次验长度），重放只解码一次并照常验长度。三段是这套等价分步操作的归因，不是三个可直接从历史日志提取的字段。另按原调用顺序、不拆段、不省第二次成员访问重放：重复均值 **26.843 ms**；独立新解释器首次调用的中位数 **33.888 ms**（4 次）。即使保留原写法也没复现 100.687 ms；原运行额外时间的原因未定。

## 哪一处值得改

同一批文件、同一组角色，每种方法重复 16 次，轮换顺序。下表为墙钟均值；不包括计时外逐元素比对。保留四来源与 provider 两类结果，最后能给出相同的两个并集及其页数。

| 离线方法 | 文件读取 ms | 转换和校验 ms | 求并集 ms | 合计 ms |
|---|---:|---:|---:|---:|
| 分步复现：逐页 map(int) + 哈希集合 | 0.240 | 14.830 | 9.237 | 24.307 |
| 用数组的 tolist() 转整数，仍用哈希集合 | 0.242 | 5.215 | 10.457 | 15.915 |
| **保留 uint64，分别 concatenate + numpy.unique** | **0.242** | **2.302** | **3.607** | **6.151** |

推荐第三种。相对分步复现，读取**没有节省**（多 0.003 ms，按未舍入数算），转换省 **12.528 ms**，求并集省 **5.630 ms**。它是整型数组拼接后排序去重，不是七路有序归并；即使排序的增长率并非线性，本批规模实测更快。上游已有序数组直接使用，父进程不再为每页创建 Python 整数。父进程对外只用并集大小；若后续改变接口，要求返回 Python set，必须重新计入转换成本。

其余方向：就重复热读而言，即使 I/O 完全免费也只省 0.240 ms，首次归档热读也只省 0.906 ms，不优先并行读。位图按本批最大最小页号覆盖 132,599,265 个位置，即使每位置只占 1 位，也要约 15.8 MiB，再计清零和遍历；没有实测其用时，不据此宣称更快。无需改七支写盘格式。

## 含批级结果能否进 1 秒？

原始宿主查询 **0.725250 s**；第一支开始到七份结果就绪 **0.908889 s**。推算用父进程的真实起点：从派发至合并完成 **1.010022499 s**，其中合并 **0.100686956 s**。其余部分是 **0.909335543 s**，不是简单把七份结果时间与合并时间相加。要进 1 秒，合并需低于 **90.664457 ms**，比原值节省超过 **10.022499 ms**。

- **优先用差额推算。** 在 4 对独立新解释器、文件页均驻留的首次调用中，原写法中位 **33.888 ms**，推荐写法 **12.111 ms**，差 **21.778 ms**。只移植该差额、保留旧现场未解释的时间：**1.010022499 − 0.021778 ≈ 0.988245 s**。这要求本次观察到的节省能在线上兑现，未假定那段未解释的时间会消失。
- **若真实合并能直接达到离线首次的 12.111 ms**：则为 **0.909335543 + 0.012111 ≈ 0.921446 s**。这是更强的环境假设，不作为验收结果。

**结论：有改动价值，且目标是少转整数，不是加读盘线程。** 本轮完成到离线评估。若另行授权实施，最小改动只在父进程合并处；验收保留身份检查和两份集合逐项一致，再以“派发到批级结果可用”计时。此次未运行真实查询。
