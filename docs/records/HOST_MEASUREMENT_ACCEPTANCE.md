## 每个量回答什么问题

这些分项、未知项和查询成本已[接入现有离线报告](HOST_SPECIAL_MAPPINGS.md#直接查看或离线生成汇总报告)，最新与旧轮次复算通过；旧字段值保持，新字段缺失明确标未测，不生成整体物理总量。查看报告无需启动服务或重新采样。

| 指标 | 如何取得 | 可以说明什么 |
| --- | --- | --- |
| 工具时延 | 每条原命令的单调时钟起止时间 | 工具调用用时；不含模型等待，也不是整个实验控制程序用时 |
| guest内存 | 每0.1秒读取guest的`/proc/meminfo`，计算`MemTotal − MemAvailable` | guest可用内存的变化，不是host物理驻留量 |
| guest page cache | 同次读取`Cached` | guest全局文件缓存统计；含与Shmem重叠的部分，不能再加Shmem |
| host主曲线 | 每0.1秒读取新建统计组的`memory.current` | 准备、控制程序、私有服务和全部沙箱的组内总记账量；组外页及未记账分配不包含在内 |
| host组成 | 同次读取`memory.stat`中的anon、file、kernel、shmem等 | 解释总量变化；file含shmem，不与current相加；host file不是guest Cached对应页 |
| 可选PSS | 已有普通host模式每秒读组内进程的`smaps_rollup`；共享文件模式不采 | 映射内存按共享比例分摊；未映射缓存及部分特殊映射不覆盖，不作为总量补项 |
| 指定对象全局驻留 | 清理前对文件或实际共享内存设备做`mincore`，驻留页数乘host基本页大小 | 该对象当时在host缓存中的驻留容量，包含组外页；只查页状态，不读文件内容 |
| 指定设备记账归属 | 专用探针记录缓存加入／移出字节、实际页记账组，并与mincore核对 | 分辨设备缓存的组内、组外容量，检验这一对象的事件覆盖；不等于所有host内存归属 |

host主曲线覆盖输入准备、控制程序、私有服务和后代进程。输入准备前创建新统计组，同时启用内存和I/O记账；新服务、新VMM从创建时就在组内，不迁入旧池进程。任务图另保留恢复前的直接基线，不把公共输入和快照成本按沙箱数乘算。

图注必须写明：**guest Cached是guest内部统计；host file是宿主统计组的文件缓存记账。guest RAM中的缓存内容还可能在host记为VMM匿名内存。** 两条曲线用于看各层变化，不是一一对应的同一种内存。

file、PSS和mincore是不同统计，可能覆盖同一批物理页，不能相加。两个VMM共用同一设备时，该设备驻留只计一次；设备中的内容还包括guest匿名内存、程序和内核，不仅是guest文件缓存。

Pss_File是PSS的页属性分类，不等于memory.stat:file：其中可能有映射内核页；PSS和kernel也可能重叠。PFNMAP等特殊映射还可能不进入PSS。数量级接近只能辅助核对，不能证明整体物理覆盖。

## 已有证据支持的结论

### 轻量曲线与指定设备测量可用

- 三任务的guest三指标及0.1秒采样已有[实际结果与关闭采样对照](LIGHT_MONITOR_CONTROLS.md)。这组开销结果不代表新增host采样或专用探针的成本。
- host入口已完成三个普通完整单任务：Prettier 29步，Sphinx和Xarray各35步，分别保存host曲线、PSS及最终文件清单。Sphinx／Xarray的Cached峰值111.277／343.797 MiB来自各自实跑；两份157文件清单均未检出净不足，但不证明完整记账。短恢复、指定共享设备及相同后缀对照仍只验证了Prettier。
- 此前[31动作双沙箱验证](HOST_FILE_CPU_COUNTER_LIVE.md)中，任务重现、恢复、补丁检查及清理通过；每实例原官方测试0通过／2失败保持。307783次缓存加入／移出、132个CPU／事件类型总计键全部相符，未检测到丢事件提示。
- 目标共享内存设备的事件推算与独立mincore均为**435.750000 MiB**。其中组内**434.730469 MiB**、udev组外**1.019531 MiB**；后者已包含在设备总量内，不再加一次。初始设备清单与恢复顺序支持初始量为零，查询相交时间段没有该设备事件；正式设备覆盖检查通过。

这验证的是本轮指定设备的全局缓存驻留与记账归属，不能把其PASS扩展为全部host物理内存覆盖。旧失败结果保留，新实验通过也不追溯证明旧计数差额的实际原因。

### 已有共享结果只对应指定设备

[此前同一轮N=1/N=2相同后缀对照](HOST_FILE_MATCHED_TASK.md)中，指定设备驻留分别为407.308594和398.675781 MiB。若两个独立设备都保持单沙箱的容量，线性参考为814.617188 MiB：

```text
A = 427094016字节，B = 418041856字节，N = 2
参考减少量 = N × A − B = 436146176字节
相对线性参考的减少比例 = (N × A − B) / (N × A) = 51.0597%
```

这是**指定设备缓存相对线性参考的减少**，不是实测不共享后端，更不是整体host节省51.06%。该轮固定先单后双，缓存状态和guest Cached不同；VMM匿名PSS同时由155.027增至336.086 MiB。435.750 MiB来自此前另一轮仅N=2的验证，不能拿它替换旧B或与旧A拼成新对照。

## 已修正一个实际的采集顺序问题

离线核对两轮原始数据发现：端点PSS读完后，入口先查其他64 GiB块设备，再查4 GiB共享内存设备，使目标查询分别晚1625、1643和1662毫秒。该轮N=2验证的端点匿名PSS为310.184 MiB，目标查询前后最近的周期读数为303.840／304.531 MiB，说明这段时间不能视为内存不变。另一个缺口是普通文件清单均在VMM和内存设备释放后取得，旧数据不能拼成同一运行状态的总量。

已改为先查目标设备；相同后缀模式在该次查询前后各读一次PSS，并核对实际VMM身份。记录包含匿名／文件／shmem PSS、设备身份和完整起止时间，新报告保留两次读数；缺少匿名PSS时明确标记未知。前后读数不是中间时段的上下界，不从这两个值生成总体物理节省率。普通完整任务不增加读取；原空闲恢复入口不增加PSS调用。

修正后已完成[一次41动作单／双沙箱对照](HOST_LIVE_FILE_INVENTORY.md)：端点PSS到目标查询缩短至25.888／37.019毫秒，目标查询及其PSS前后读取共183.915／198.945毫秒。两组运行中普通文件清单分别为188／194个文件，均在第一次删除该组VMM前完成；原始内存层按身份确认已在普通清单中，不重复加入。55项host相关和27项隔离存储回归、实际数据独立复算通过。旧数据没有补造新字段，原数值和判定保持。

## 还缺什么，影响哪项结论

1. **普通文件完整记账没有通过，当前归档组外归属已经查明。** [最新真实任务补采](HOST_DELETED_BACKING_LIVE.md)两组最终普通清单净不足1747.968750／1740.363281 MiB，均保持`SHORTFALL_REQUIRES_RESOLUTION`。[离线分解](HOST_FILE_SHORTFALL_ANALYSIS.md)发现恢复guest前就有相近差额，同一旧归档六次均驻留1746.109375 MiB，最终净差减归档容量为＋1.859375／−5.746094 MiB。随后[定向查询](HOST_EXISTING_CACHE_OWNER.md)已直接测得当前归档全部1746.109375 MiB记在实验父组外；这是当前时刻的归属，不能补造此前两组当时的逐页归属、改判或给全部遗漏设上限。不能以新查明的4／8 KiB后备缓存抵扣。此前特殊映射轮次1745.191406／1738.429688 MiB、共享卷最终190文件的0.480469 MiB净不足均按原范围保留。净差不是总误差上限，也不与历史设备组外量抵扣。Sphinx／Xarray普通任务最终清单未检出净不足，范围不同，不追溯修正Prettier结果。
2. **guest缓存对应的host物理页集合没有由这套轻量方案测得。** 全设备mincore包含其他guest RAM内容，整VMM PSS也不能替代这一集合。此前精细测量按其自身版本和未知量单独引用。
3. **整体物理节省没有测得。** 缺少同一比较口径下、排除重叠后的全部相关host物理量及可比参考；不能把file、设备驻留与PSS简单相加，或只用设备比例替代总体比例。 [原离线复算](HOST_TOTAL_COMPARISON_SCOPE.md)已明确公共成本、非VMM匿名内存和独立可写环境的设计。[导入后同步实跑](HOST_IMPORT_SYNC_VALIDATION.md)已将两组起始file差降至3.379 MiB，去掉了此前几GiB准备写回干扰；[物理分项及查询时差核算](HOST_PHYSICAL_BREAKDOWN.md)列举缓存合计39.441536／39.454727 GiB，含前置PSS的观察窗口跨5.167／6.821秒，期间匿名PSS变化12.688／9.910 MiB。后续明细、特殊映射和[已删除后备补采](HOST_DELETED_BACKING_LIVE.md)补齐了部分覆盖；本轮主要观察段2.229／2.257秒，全部任务后查询5.349／6.875秒，仍未建立全部物理覆盖、同时总量或可靠误差界限。
4. **新增host采集已完成一次开启／关闭对照。** 工具累计5.645／5.716秒，开启组相对关闭组−1.25%；控制程序46.023／32.397秒，相对+42.06%。开启组任务后的驻留与PSS查询直接计时11.633秒，最终外层文件查询另用1.760秒。样本为固定先开启后关闭各一次，不能把控制程序增幅当作工具减速或稳定均值。详见[开销对照](HOST_SAMPLING_CONTROL.md)。

这些缺口不推翻已经交付的曲线与指定设备检查。若报告要声称“整体物理节省”，须处理第1项涉及的遗漏，并补齐第3项的总量和可比参考；若进一步声称“guest文件缓存对应的物理节省”，还须补第2项的归属证据。第4项给出当前范围的实际成本，不替代物理量正确性检查。

## 使用现有入口，不默认增加探针

仅查看已有数据，优先使用上述结果报告及[host测量记录](HOST_FILE_MONITOR.md)。重新实验时，先核对输入、源服务和资源预算；以下是调用方法，不表示本次已重新运行。

```bash
# 已确认该源服务健康时，执行普通Prettier完整29步host采样。
export ASB_AGENTENV_SOURCE_SERVICE=asb-source-rebuilt-20261018T160925Z-2726362
bash scripts/run-host-file-monitor.sh configs/platform-prettier6604-host-file.json
```

入口不自动启动或替换源服务；上一轮结束时源服务已停止，不能把设置环境变量视为服务健康。普通任务使用8 GiB卷，启动可用磁盘须超过34 GiB，另按入口预留未就绪输入；下列恢复任务使用24 GiB卷，须超过50 GiB。沿用20 GiB停止线、6 GiB余量及定向清理规则，不自动删除旧失败卷。

同一入口的选项互斥，按问题选一个，不要逐项重复执行：

- 无附加选项：按配置执行普通完整任务，Prettier 29步，Sphinx／Xarray各35步，不挂专用事件探针；后两者用`configs/platform-sphinx7590-host-file.json`或`configs/platform-xarray6992-host-file.json`。以下恢复和对照选项的已验证任务范围为Prettier。
- `--matched-task`：共同11步、同一快照，单沙箱与双沙箱均跑相同10步后缀，共41实际动作；用于同轮指定设备比较。仅此模式可加`--host-sampling off`做计时对照，guest采样和记账条件不变，host量明确未请求。
- `--independent-matched-task`：11步快照导出后，在两组独立服务／卷上执行同一后缀；已验证。加`--resume-prefix <源结果目录>`可复用已验证归档，只新增30动作。导入后、服务及guest创建前同步自有文件系统，已验证起点改进；仍不保证所有缓存状态相同，详见本轮结果。
- `--host-memory-detail`：只附加于`--independent-matched-task`，集中主要查询并补查映射文件；默认4秒子进程查询已删除后备缓存，结果单列，不改变普通轻量入口。小对象跨进程／超时及真实单／双补采均已验证；不表示完整物理覆盖。
- `--trace-dual-task`：共同11步和双沙箱相同后缀，共31实际动作；只为诊断缓存来源及指定设备覆盖，没有新单沙箱参考。
- `--restore-pair`：共同11步，单／双恢复各观测5秒，不执行后缀；它是空闲恢复检查，不是任务对照。
- `--short-pair`：只创建两个guest做自有标记检查，不建立真实共享快照；不用于计算共享节省。

每次分别读取任务重现、原任务测试、事件完整性、设备覆盖、普通文件记账和清理状态。报告或工作流程的某个PASS不替代其他检查。原始路径、数字和各阶段判定见[脱敏证据](evidence/host-file-cpu-counter-live-20261020.json)和[历史对照](HOST_FILE_MATCHED_TASK.md)。
