# 约1.7 GiB文件差额：旧归档与新统计组的范围没有对齐

**最新保存结果强烈支持：差额的主要来源是约1746 MiB旧快照归档进入了全局驻留清单，但它的已有缓存不保证记在本轮新建cgroup中。不是发现了1.7 GiB身份不明的新内存。** 尚未取得的是这些旧页的实际记账组及完整逐页分解，不能把整份归档直接作为cgroup修正值。此前笼统写“1.7 GiB仍未解释”，没有把这个主要解释与剩余证据缺口分开。

本次只核对最新一轮保存的JSON和相关本地源码，没有启动服务、沙箱、读取归档内容或再次查询缓存。[脱敏复算](evidence/host-file-shortfall-analysis-20261021.json)；脚本及日志位于`.artifacts/host-file-shortfall-analysis-20261021/`。

随后授权的[无数据访问定向查询](HOST_EXISTING_CACHE_OWNER.md)已取得当前页归属：同一归档1746.109375 MiB均记在在线会话组，全部在仍存活的实验父组`/asbhost.slice`之外，未知0。方法利用mincore内部已有缓存查找的返回引用读取元数据。以下差额和缺少逐页归属的描述对应此前任务记录，不用当前归属回填旧时刻。

## 差额不是同一集合中的丢失字节

`scripts/host_file_monitor.py`的`residency_check()`实际计算：

```text
R = 清单中普通文件的全局驻留之和，按设备号和inode去重
F = 查询前后两次cgroup memory.stat:file的较大值
报告净不足 = max(0, R − F)
```

R包含源归档、输入层、独立卷等所列对象的缓存，不论页记在哪个组；F只统计当前组及其后代的文件缓存记账，还包含清单外的对象。二者又是顺序观察。因此这项检查能发现范围或时序需要核查，不能直接给出“遗漏的沙箱内存”。

即使假定完全同时，设清单内组外页为O、清单外组内页为U，也只有：

```text
R − F = O − U
```

实际还存在统计汇总延迟和查询期间变化。净差不是全部组外页的大小，净差为零也不证明完整记账。

## 为什么新建统计组、开启I/O记账仍然没有消除它

本轮入口先创建新统计组，新服务和VMM均从创建时位于组内；但`--resume-prefix`复用了旧轮次导出的归档，没有在新组内重新创建该文件。

实际代码顺序是：

1. `run_host_file_workflow.py`创建本轮新组。
2. `run_host_independent_pair.py`引用旧目录的`checkpoint-bundle`。
3. `native_checkpoint_bundle.restore()`读取并解包旧归档。
4. `validate_isolated_agentenv.py`把原归档路径加入恢复前、运行中和最终mincore清单。

本地实际内核源码树的`Documentation/admin-guide/cgroup-v2.rst:1963–1971`明确说明：内存记在实例化它的组，直到释放；进程迁组不迁已有内存的账。同一缓存页被新组进程再次读取，也不因此按读取者重记一份。故本轮读取旧归档不能保证已有页转入本轮组。`IOAccounting=yes`保障相应新I/O的记账条件，也不会追溯迁移所有旧缓存。

原组已经停止，也不意味着其所有缓存立即消失；本地`mm/memcontrol.c:263–291`的页归属查询还处理已下线组的在线祖先。本轮没有保存归档每页的记账组，不能指定它们全在旧组、父组或某个服务组，更不能由文件创建时间证明每页从未回收重建。

## 为什么查询时差和其他补采不能直接修正这个数

普通文件查询各跨约1.96–2.04秒。恢复前两组的file前后读数均不变，大差额已经存在；最终双组file在查询期间增加2.879 MiB。时序和统计汇总值得保留，但现有数据没有显示它们足以单独解释约1746 MiB的固定差额。

后缀结束、VMM仍在时，普通清单净差暂为1330.242188／1308.316406 MiB。该清单不包含目标ublk内存设备，设备此时却全局驻留410.464844／423.492188 MiB，并可能计入F，所以清单外组内页会压低净差。清理VMM及设备之后，最终差额又回到约1746 MiB。这里说明集合为何不同，不据设备驻留反推本轮每页归属。

上一轮新增的已删除memfd／dev-zero查询解决了另一个覆盖缺项：本轮只有4／8 KiB缓存，且已在其他统计中可能重叠。它既不查询归档页记账组，也不能抵扣GiB级差额。继续补类似小对象或重复相同后缀不会取得缺少的旧页归属证据。

## 当前结论和下一步

- 主要问题是**公共旧输入的全局驻留与本轮cgroup记账范围不同**；这是有定量支持的主要解释，归档逐页组外容量仍未直接测得。
- 原`SHORTFALL_REQUIRES_RESOLUTION`保留，它表示该清单没有证明组内记账完整；不是“发现1.7 GiB无名内存”，也不是“所有任务内存少算1.7 GiB”。
- 任务分析应分列公共准备对象、恢复前基线和任务期间增量。归档的对象端点增量为零；这个事实不授权从cgroup端点减去归档，其他对象的组外变化和完整物理覆盖仍需各自证据。
- 现有轻量曲线与指定设备结果继续可用。整体物理节省仍缺完整覆盖及可比参考，不由本次净差分解生成总体节省率。

本次离线分析已完成。下一步建议先使用上述分列说明，不再重跑原30动作。只有仍要求归档的精确记账分解时，才单独研究无触页的初始页归属查询；完成条件是取得实际旧页的组内／组外容量，而不是把总差测得更接近零。
