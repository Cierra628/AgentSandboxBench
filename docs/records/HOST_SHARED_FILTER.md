# 共享文件恢复测量：离线排除独立盘扫描（2026-10-22）

**新恢复模式的查询范围已离线缩小：只查询实际共享的只读盘、映射中的快照内存设备，以及公共原始内存层。** 独立可写盘保留身份和“未查询”状态，驻留页数／字节数为null，不记为0。旧入口不传新选项，仍按原范围查询所有自有块设备。

本轮没有启动服务、沙箱或逐页探针，没有查询实验文件／设备的当前驻留，也没有读取负载内容。只修改查询选择逻辑，使用模拟设备元数据和上轮保存的真实结果验证；尚未实测过滤后的耗时。

## 查询范围怎样确定

新增`live_residency(..., shared_readonly_drives=None)`可选参数，默认None保持旧行为。只有`host_scaling.observe_files()`的恢复分支传入本轮实际共享只读驱动；冷启动及旧的短恢复、匹配任务和显式明细入口不传入该选项。

1. 通过全部活跃guest的实际驱动配置，复用`shared_drives()`找出共同使用的只读块设备，不按历史设备号或文件名猜测。
2. 通过实际进程内存映射取得共享快照内存设备，保留原内存设备身份／容量和映射范围检查。
3. 在调用块设备mincore前选择这两类对象。块设备按实际rdev去重，同设备多个驱动名或节点别名不重复查；核对自有服务中打开的设备身份，目标缺失或身份不符时失败，不静默遗漏。
4. 原始内存层仍按快照配置和自有服务实际打开的普通文件确认，以device＋inode去重，不改变原始层的查询和公共准备规则。
5. 排除设备仍保留身份、路径和所属进程记录，但没有mincore调用。记录`status=NOT_REQUESTED`、`resident_pages=null`、`resident_bytes=null`。

新结果增加`residency_scope=SHARED_FILES_ONLY`、`selected_block_identities`及`excluded_devices`，明确已查询和未查询的范围。`files`只包含实际查询对象，`resident_bytes`仅为这些对象驻留容量之和，不代表完整设备清单或整体物理并集。旧入口不增加这些选择字段，原PSS、明细回调、计时和默认范围保持。

host每0.1秒组内计数、guest每0.1秒meminfo、9个固定检查点、N=1／7查询时段及线程CPU／前后计数都保持。公共导入原始层仍只列驻留，不乘七算新增收益。
