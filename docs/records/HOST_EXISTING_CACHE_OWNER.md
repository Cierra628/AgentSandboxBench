## 利用mincore已有的缓存查找，而不是触页取得PFN

独立的mincore结果不返回页记账组，但实际内核的mincore实现已经逐个查找文件缓存索引。由此可以补上此前缺少的连接：

```text
普通文件只读打开 → 新建PROT_NONE映射，不访问映射内容
→ mincore查询已有缓存
→ filemap_get_entry返回已存在的folio及临时引用
→ 定向BPF返回探针读取folio的映射、索引及memcg元数据
→ 按实际记账组汇总，引用由原mincore路径照常释放
```

folio是内核管理一页或多页内存的单位，memcg是内核的内存记账组。BPF探针是短时附加在指定内核函数上的观察程序；本次只读取元数据，不改变函数返回值，不创建缓存页，也不通过用户页表取得物理页编号。

过滤条件同时包含查询进程、mincore系统调用以及实际文件设备号和inode。每个文件基本页索引必须恰有一次进入和返回，顺序连续；同一大folio覆盖多个索引时，每个基本页只计一次，不再把命中次数乘folio总大小。

归属按实际`memcg_data`读取，而不是用查询进程所在组代替。若原记账组已下线，代码按源码走向最近在线祖先；身份、映射、记账字段或状态变化、无法解释的字段保留未知。前后核对文件身份、大小、驻留数和参考组树；同时观察目标文件缓存加入／移出，变化或覆盖不足不输出成功容量。

本地实际`6.19.9+`源码依据：

- `mm/mincore.c:109–151`：未建立页表映射时，按文件索引调用`filemap_get_entry`，只检查已有条目及uptodate状态，再释放引用，不读取文件内容。
- `mm/filemap.c:1880–1925`：查找已有缓存条目，正常folio返回前增加引用；没有创建页或执行读取。
- `include/linux/memcontrol.h:328–406、466–503`：区分普通folio的记账指针与其他标志，并说明绑定稳定条件。
- `mm/memcontrol.c:263–291`：页归属查询采用最近在线祖先。
- `kernel/trace/bpf_trace.c:98–149`：kprobe的BPF执行处于RCU读侧保护内。RCU防止相关元数据在读取期间被回收，不把顺序查询变成原子快照。

此前“独立用户态接口无法直接拼接完整归属”的结论仍适用于那些接口本身；新增的关键是观察mincore内部已持有引用的返回点，不必另建缓存遍历接口或内核模块。
