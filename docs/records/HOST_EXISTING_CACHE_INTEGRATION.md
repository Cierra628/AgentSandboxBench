**`--host-memory-detail`现已接入旧归档缓存归属查询。** 原文件、设备和PSS观察完成后，另起有限超时子进程查询本轮导入归档，参考组为本轮实际统计组；组内、组外、未知容量及查询时间单列。默认0.1秒采样、普通任务和未加明细选项的调用保持原行为。

顺序固定为：


只查询显式导入的`host_checkpoint_bundle/repository.tar.gz`，不遍历所有文件逐个挂探针。没有该输入时为NOT_REQUESTED，不引入旧调用的新前置条件。新查询失败或超时单列，不改变原功能判定，不把功能PASS解释成新查询通过。

原`compact_inventory`及`residency`的起止时间、数值和状态不因新查询延长或重定义。旧`timing_ns.all_post_task_queries`继续对应原文件／设备查询段，报告标签明确改为“原文件／设备驻留查询段”；另加“含旧缓存归属的全部观察段”，从原主要段开始到新子进程回收结束。新成本不计入工具用时。

查询进程继承控制器的统计组，其编译、程序加载等准备成本可能进入查询后的组内计数。因此将其置于原观察段之后，不把后来最终清单差额的变化全部归给旧缓存归属的变化，也不据此追补原端点。

## 结果位置及未知含义

- 原始任务记录：`host-matched.json`中各组的`existing_cache_owner`。
- 本次子进程及日志：任务目录的`existing-cache-owner/result.json`、`worker.stdout`、`worker.stderr`；底层探针数据及原查询结果在其`observation/`子目录。
- 离线报告：`summary.json`各组的`memory_detail.existing_cache_owner`，以及`MEMORY_DETAIL.md`的“旧归档缓存归属”一节。

结果含查询文件、实际参考组及组ID集合、父进程与实际mincore查询的单调时钟起止、覆盖计数、页所有者、组内／组外／未知字节数及进程回收状态。不与file、PSS或current相加。

| 状态 | 容量含义 |
| --- | --- |
| OBSERVED | 完整观察成功，未知为实测0；组内或组外也允许实测0 |
| INCOMPLETE | 保留已识别容量与实际未知容量，不能只报已知部分的总量 |
| ERROR／TIMEOUT | 有效容量均为null，保留原错误、子进程状态及可能取得的原始观察 |
| NOT_REQUESTED | 本次没有导入归档输入，不启动子进程 |
| NOT_MEASURED | 旧记录没有本字段，不从当前文件或PID补查，不补零 |

## 超时只处理本次进程组

新查询以`start_new_session=True`启动，BPF编译和探针进程继承这个独立进程组。父进程默认等待30秒；超时后向该组发送TERM，给原查询finally最多15秒释放探针并回收子进程，必要时向同一组发送KILL并等待。记录worker是否回收、进程组是否消失；不向guest、服务或其他工作进程发信号。

真实超时验证用不访问目标文件的自有阻塞进程及其子进程代替查询和探针：1秒超时后，两个进程均退出，父进程已wait回收，进程组消失，旁边的自有对照进程仍存活。强制KILL分支另用模拟检查目标进程组。此项验证的是进程回收，不是一次新的BPF运行。
