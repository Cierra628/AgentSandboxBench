# 小loop初始化分阶段验证（2026-10-20）

**一轮128 MiB镜像实验已完成，最早的可见差额出现在格式化后、绑定loop之前。** 格式化后镜像驻留27页，测量组file仍为0；最终镜像驻留325页、file为36页，差额289页（1.129 MiB）。因此，早期差额不能全部归因于loop绑定后的设备识别；最终残余的页归属和统计汇总时机仍未确定。

本次只做[已确认的初始化定位](HOST_FILE_COVERAGE_AUDIT.md#最小改动与后续验证条件)：一个新128 MiB文件、开启内存和I/O记账、格式化、绑定loop（把镜像文件作为磁盘设备使用）、挂载及同步。没有64 MiB合成文件，没有沙箱、任务、AgentENV服务或大卷重跑，没有修改全机缓存或设备管理设置。

## 六个检查点把早期差额和最终残余分开

使用新的独有外层组及其下的测量组，在创建镜像前进入该组。实际外层和测量组均向下启用io，工作进程存在`io.stat`；systemd属性为`MemoryAccounting=yes`、`IOAccounting=yes`。host仍为`6.19.9+`，页大小4096字节。只用`mmap(PROT_NONE)`和mincore查询镜像，不访问镜像内容、不预读或锁页。

下表的file前后值在每次查询中都相同，外层file也与测量组一致。相对时间以首次空清单检查开始计，不是整个外层入口耗时。

| 检查点 | 相对时间 | 镜像驻留页 | 测量组file页 | 外层file页 | 驻留−测量组file页 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 创建文件前，空清单 | 0.000秒 | 0 | 0 | 0 | 0 |
| 预分配128 MiB后 | 0.004秒 | 0 | 0 | 0 | 0 |
| 格式化后 | 0.013秒 | **27** | 0 | 0 | **27** |
| 绑定loop后 | 0.020秒 | 27 | 0 | 0 | 27 |
| 挂载并同步后 | 0.036秒 | 325 | 0 | 0 | 325 |
| 固定等待2.2秒后的初始化基线 | 2.242秒 | 325 | **36** | 36 | **289** |

前三个非空清单检查均针对同一个镜像设备号和inode，每次查询期间身份、容量及文件元数据稳定。最后两次同样为325页驻留，但组内file从0更新为36页；不能把即时计数0理解为镜像没有占用内存，也不能单凭这次更新确定325页分别记在哪个组。

绑定后的检查仅紧随绑定操作返回，不代表host异步设备识别已经结束。后续增加的298页出现在“绑定后检查至挂载同步检查”区间，可能包含挂载及并行设备识别；现有记录不将它们全部归给某一个操作。

此前开启I/O记账的小loop最终残余为288页（1.125 MiB），本轮为289页（1.129 MiB），相差1页。两轮初始化基线的镜像驻留都为325页，当前不将页数相近当作同一批物理页的证明，也不以重复到完全相同为目标追加实验。

## 对测量方案的结论

1. **分阶段定位通过。** 首个可见差额在格式化后，早于loop绑定；“所有差额都从绑定后的设备识别产生”无法解释这个早期观测。
2. **统计与归属仍需分开。** 实际内核的统计汇总有阈值和周期工作，依据见[离线源码核对](HOST_FILE_COVERAGE_AUDIT.md#源码支持两条待区分的解释)。本轮没有采集汇总事件或同一缓存页的内存组归属，最终289页继续列为未知差额，而不是确认的组外物理页数。
3. **不改动已通过的大卷结果。** 新I/O设置下未再检出4.232 GiB不足的结论保持。两份deps未列入最终清单仍是明确缺项；本次没有补造其驻留，也没有计算共享节省比例。

host主曲线继续用`memory.stat:file`，guest Cached仍单独解释。当前已达到本轮约定的完成条件：只有一个初始化镜像，三项操作后的检查齐全，首个差额阶段及剩余证据缺口明确，资源清理通过。
