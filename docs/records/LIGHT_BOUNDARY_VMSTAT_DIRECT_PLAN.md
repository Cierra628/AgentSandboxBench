# 边界vmstat直接对照：离线核对与实跑方案

后续[保留→跳过一对真实实验](LIGHT_BOUNDARY_VMSTAT_DIRECT_PAIR.md)已完成：378动作、3663点及全部任务／报告／采样／清理通过。动作及下载窗口−13.54%、创建后窗口−10.48%；以下保留离线阶段的方案与完成条件。

## 下一对只比较是否读取边界vmstat

两组都开启0.1秒guest内存采样、保留逐动作边界内存和原峰值检查，只切换`light_skip_boundary_vmstat`。先运行保留边界vmstat的一组，再运行跳过的一组；共两次完整GRPO、14个新guest、378个原动作。每次仍先并发创建全部七个guest，再并发准备，全部准备完成后执行原七路径。

目的是回答：移除边界vmstat后，任务动作窗口及创建后的实际耗时少多少？[上一对](LIGHT_BOUNDARY_VMSTAT_PAIR.md)比较的是完全关闭采样与候选开启，创建后+8.16%反映候选剩余开销；它不能给出移除vmstat本身的收益。本次两组都重新运行，不用旧组拼成新对照。

## 配置与命令传递已离线核对

从同一份`configs/platform-prettier6604-grpo-light.json`派生两份配置，均加入`grpo_create_before_setup=true`。两份JSON只有一个字段不同：

| 项目 | 保留边界vmstat | 跳过边界vmstat |
| --- | --- | --- |
| `light_skip_boundary_vmstat` | `false` | `true` |
| guest周期meminfo | 0.1秒，七个会话 | 相同 |
| 边界内存行数 | 448 | 448 |
| 边界vmstat行数 | 448 | 0，完整表头保留 |
| 原任务动作 | 189 | 189 |
| host查询、PSS、服务指标、缓存控制 | 均不启用 | 相同 |

两组均保持AgentENV默认回收行为，不暂停、预读任务文件或强制驻留；资源继续使用每guest 2 CPU／4096 MiB、每组16 GiB卷。候选放弃的是边界页故障及页读入／写出计数，不影响本次保留的guest内存及Cached曲线；未测计数必须标为`NOT_MEASURED`，不能填0。

实际调用`configuration()`及`commands()`核对通过：两组检查命令和执行命令均包含轻量采样及先创建后准备选项；去掉候选的`--light-skip-boundary-vmstat`后，两组命令列表完全相同。只解析配置、生成命令，没有执行它们，也没有调用会读取冻结负载的`preflight()`。原配置及运行代码未修改。

现有[`run_grpo_light_pair.py`](../../scripts/run_grpo_light_pair.py)的`pair_configs()`和`summarize()`固定要求off/on两组，因此**不修改它的原含义，也不把保留边界vmstat的一组假标成off**。实跑时顺序调用现有`use-platform.sh run`单次入口；两组都复用`inspect_run(workflow, 'on')`严格审核，另按retain／skip名称保存结果和配对比较。它们都是采样开启组，`on`只表示采样状态。

`inspect_run()`已经支持候选，并复核新调度、原任务、七采集器及资源清理；配对收尾还须显式比较两组实际开关为false／true、边界行数、路径、补丁和官方结果一致。报告器已在上一轮修复漏传选项的问题，继续运行完整脚本审核，不绕过检查。

源码位置与本次核对结果见[脱敏证据](evidence/light-boundary-vmstat-direct-plan-20261027.json)。本地配置为`.artifacts/light-boundary-vmstat-direct-plan-20261027/retain.json`和`skip.json`，可用同目录的`verify-plan.py`重新生成并核对；`commands-not-executed.json`保存未执行的命令。本次新增服务、guest及原任务动作均为0。运行代码没有变化，复用上一轮10项回归及严格重报的有效证据，不重复启动验证。

## 固定计时口径，保留正负变化

主要比较原动作及下载窗口`frozen_tools_and_downloads_span`：边界采集发生在这段执行中，创建与部署等待不在其中。它包含调用及下载，不是原命令耗时之和。

同时完整保留：

- 全部创建完成至控制程序结束：衡量包含部署、任务、检查及收尾的创建后影响。
- 原控制程序整轮、七个创建请求跨度、准备窗口、清理时间：显示整轮差值来自哪里，不扣掉创建后改写原整轮。
- 原工具累计、35次采样控制调用累计及其墙钟并集：累计可重叠，不与整轮相加。
- 两组各七个采样器的实际点数、间隔、CPU时间和峰值RSS。CPU仍只统计采样器自身，不包含边界shell操作；RSS不作为host物理净增。

每项都给原始秒数、有符号秒差`跳过−保留`以及百分比`(跳过/保留−1)×100%`；负数表示本对较快，不截断较慢值。除以0时百分比留空。周期点数随运行时长变化，不要求等于上一轮1976点，也不要求两组曲线逐点一致。

理论上每组少448次边界vmstat读取和896次对应date／awk调用；耗时减少多少由新对照实测，不把这些操作的时间从旧综合差值反推出来。
