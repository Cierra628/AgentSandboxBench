# 普通输入接入多沙箱：离线核对（2026-10-30）

## 结论：先接Prettier完整GRPO，不重复已有前缀短测

三个任务的普通输入完整单任务均已验证。多沙箱中，当前只有Prettier的`--current-pair --persistent-input`可直接使用普通输入，但它只执行两份共同前缀，各11步、各观察5秒；没有完整任务或官方评测。该路径已真实通过，不需要再跑一轮证明相同事实。

**建议下一步离线接通Prettier现有完整GRPO：保留原7个独立guest、189步动作、每个实例最终检查和官方结果，改用普通输入及current轻量路径。** 这条路线复用现成完整调度和清理，不先新建通用多任务调度器，也不扩BPO。拟用入口如下，目前会被明确拒绝，尚未实现：

```bash
bash scripts/run-host-file-monitor.sh \
  configs/platform-prettier6604-grpo-light-host.json --persistent-input
```

该完整GRPO原本并发创建7个guest，**不是1→2逐个递增实验**。建议保留原调度，不为了制造固定N=1／N=2窗口而串行创建、插入等待或暂停任务。现有递增前缀结果继续单独报告；后续若需完整任务的边际增量对照，应另定同阶段对照，不能从这次7实例峰值或旧单任务数字直接换算共享率。

## 仅放开参数限制还不够

按当前GRPO标志计算实际分支，发现三个必须一起处理的差异：

1. **commits会被再复制一份。** [隔离存储代码](../../scripts/validate_isolated_agentenv.py)第791行的跳过复制条件和第946行的只读绑定条件，对普通完整GRPO都为false。仅放开种子参数，会在已导入的普通输入之外，再把镜像层复制进运行卷，产生另一组文件及其缓存。新模式应复用单任务的外部只读commits绑定，只影响新显式选项；原GRPO复制方式不改。
2. **默认还会做PSS和广泛收尾驻留查询。** [platform_tasks.py](../../scripts/platform_tasks.py)目前只有特定标志关闭PSS；原生第1496行的收尾扫描条件对普通GRPO仍为true。这两项不是本次轻量路径需要的操作。新模式关闭它们，只保留结束后一次输入查询。
3. **报告入口仍要求广泛文件清单。** 新模式应使用现有报告器的`residency=None`及服务就绪基线，另显示原输入查询。报告器当前主指标已经是`memory.current`，不用重写指标或再增加一套报告系统。

原生在`persistent_seed`下已有自有卷同步分支，所有host模式也已有服务就绪、创建guest前的同步计数；这些可以直接复用。无需增加全局sync、清缓存、暂停或额外稳定等待。

## 完整观测窗口怎样划分

1. **准备阶段：**组外恢复20 GiB来源；先建统计组，再组内首次创建普通输入。来源先释放，再分配运行卷；自有卷同步、新服务就绪后、任何guest创建前记录唯一准备基线。该基线包括输入和服务。
2. **活跃窗口：**直接复用`rollout_start_monotonic_ns`到`rollout_end_monotonic_ns`。当前源码已经在创建前开始，在全部路径、最终检查及官方评测后结束，随后才删除guest。用同一条host曲线统计该窗口的采样峰值及相对准备基线增量；不插入等待、不改变原调度。
3. **全流程与收尾：**原current全流程曲线及峰值继续保留，和活跃窗口分列。原隔离运行及自有清理结束后、普通输入删除前，只查询一次105个唯一输入对象的驻留和成本。它不是任务运行中点，也不是每个guest查一遍。

guest曲线仍逐实例显示，不能把guest Cached相加后与host file当作同一层比较。current覆盖组内准备、控制、服务和所有guest，不是单个实例独占量；mincore与current有重叠，不相加。

## 成本要按整批实例记录，不能把单任务百分比当并发结果

保存的三项单任务中，host采样CPU占单核0.293%～0.314%，guest为0.523%～0.723%，一次输入查询约0.161～0.210秒。已有双前缀短测中，两个guest采样CPU合计0.277327秒；8次采样管理调用累计0.942121秒，7次阶段检查墙钟累计0.279451秒。短窗口的guest CPU百分比分别0.721%和1.263%，也说明不同窗口的百分比不能直接套用。

新完整GRPO仍只用一个host每0.1秒采样线程，guest各自每0.1秒采样。报告须记录7个实际实例的采样收据、CPU累计、间隔和缺口，单列上传／就绪／结束／下载等管理调用，以及输入查询的墙钟和线程CPU。工具累计、并发窗口墙钟和控制程序整轮分开；没有关闭采样组时不输出任务减速率。旧并发结果不能直接充作新输入方式的开销验证。
