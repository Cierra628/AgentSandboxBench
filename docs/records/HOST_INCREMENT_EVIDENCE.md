## 归档的全局驻留增量为零，记账归属仍未知

两组的恢复前、运行中、最终清单共六次记录确认：归档是同一个设备号／inode／大小，447004个缓存页全部驻留，均为**1746.109375 MiB**。

因此，对这一个对象：

```text
全局驻留端点增量 = 运行中驻留 − 恢复前驻留 = 0
```

它在按对象计算的端点增量里抵消，部署准备成本只列一次。若准备成本记作C，两组任务增量记作X1、X2，则线性参考应为`C+2×X1`，而不是`2×(C+X1)`。本报告没有据此计算整体分母，因为C及X尚未具备全部物理覆盖。

这六次记录没有保存页记账归属。全部驻留的页也可能在两次查询之间移出、重新加入，容量相同不证明记账组未变。因此不能从cgroup的file／current直接减去整份归档，也不能把它全部再加到current上。

## 未知项是否足以改变数百MiB的结论

**现有数据不能排除未知项改变整体节省量，甚至改变整体参考差的正负；指定设备的392.602 MiB对象范围结果继续成立。**

本轮已删除后备对象在所属进程没有匹配描述符的数量为2／4个。它们的映射虚拟长度合计仅12／24 KiB，映射PSS为4／8 KiB；虚拟长度含同一对象的重复映射，也没有限制已不映射的后备范围，不能据此断言完整遗漏只有几KiB。最新数据没有对象大小、初始驻留或完整页集合，因而没有可用的整对象容量上限。

时间变化也没有误差上限。主要观察段2.160／2.177秒内，21／21个完整计数样本的current最大值减最小值为7.727／13.012 MiB，完整匿名PSS观察的变化范围为3.188／12.641 MiB。这些是实际采到的变化，不覆盖采样间隙；包含其他设备后查询跨5.259／6.840秒，不能用较短观察段限制全部变化。

可以把需要证明的条件写清楚。设实际目标物理增量为`M_n`，本轮current记账增量为`C_n`，二者差额为`E_n=M_n−C_n`。E包括归属、覆盖、统计口径和时间差，不只是普通清单净不足：

```text
整体物理参考差 = 2×M1−M2
               = 405.015625 MiB + 2×E1−E2
```

若未来证明`|E1|≤u1`、`|E2|≤u2`，且`2×u1+u2<405.015625 MiB`，则可保证这个参考差仍为正。当前u1、u2均未测得；此公式给出一个充分条件，不是已获得的置信区间，也不验证单沙箱外推能替代实际不共享对照。

## 最值得先补的是组外驻留变化，不是重新测约1.7 GiB总差

第一优先证据是：**实际普通文件、块设备和共享内存对象，在恢复前到后缀结束之间，组外驻留净变化有多少，是否已经与组内统计重复。** 归档只占其中一个对象。此项最直接区分“固定公共准备成本”和“任务产生但未记到本组的变化”。

已有`host_file_trace.py`在缓存加入／移出时读取实际页记账组，但过滤范围是组内所有者、私有卷文件、指定后备镜像和全部块设备；它不保证捕获任意组外归档／程序库／已删除shmem对象，也不枚举探针启动前的已有页。仅把当前探针重新挂一次，不能回答上述问题。

若继续实施，最小采集改动应满足以下条件，而不是重跑相同任务：

1. 明确实际对象身份及存活期；旧归档和已存在库文件要有初始驻留及归属查询，新对象只能在确认探针先于其创建时采用初始零。两组都覆盖已删除但仍存活的shmem对象。
2. 对该集合记录完整加入／移出及必要的记账归属变化，区分组内、组外和未知；只改事件过滤不能代替初始状态查询。查询必须不读负载、不使页面驻留、不暂停沙箱。
3. 验证事件完整性、实际页大小和对象去重；与相同端点的非触页驻留查询核对。采集间隙和未知容量若没有可靠上限，继续报告未测，不由净差较小改判。

这项是当前最优先补的证据，不是已证明的唯一缺项，也不独自保证全部内核物理覆盖。现有记录不足以按容量给所有未知项排序；不能先承诺只剩一个大缺项。没有满足初始归属和shmem覆盖的具体方法前，不建议再启动原30步或完整任务。
