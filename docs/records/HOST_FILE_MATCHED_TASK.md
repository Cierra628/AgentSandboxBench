## 原定一对实验完成，没有追加轮次

普通guest内核、2 CPU/4096 MiB。共同11步保存一次实际快照并删除父guest；随后先恢复一个guest执行10步，再删除，最后从同一快照恢复两个guest并行各执行相同10步。总计11+10+10+10=41实际动作，对应三个21步逻辑路径；没有执行完整29步backbone。

三个恢复实例分别为`N1-a`、`N2-a`、`N2-b`，均使用`early_1`原清单和预期退出码，输出、采样会话和VMM身份分开。原前缀预期退出127保留，三个后缀各10步均按原预期退出。恢复文件、进度、探针连续性、最终补丁与独立检查通过；每个实例的完整官方结果仍为**0通过／2失败**，原失败不改成任务全通过。

测量组在准备前创建，实际内存和I/O控制器状态通过，预启动池关闭且创建前没有Firecracker。双沙箱的两个实际VMM映射同一个4 GiB内存ublk设备。测量不新增暂停、预读或锁页，不改变后台回收；除原生快照外没有暂停沙箱，也没有增加原短验证的固定5秒空闲窗口。

## 共享设备有直接证据，整体节省仍需区分范围

实际设备身份与按设备去重的mincore说明：本次两个恢复guest使用同一个内存设备缓存，其驻留398.676 MiB，而不是为每个VMM重复记一次。

若假设两个独立设备各保持单沙箱407.309 MiB驻留，线性参考为814.617 MiB；本次共享设备比这个参考少415.941 MiB，即**51.06%**。这个比例只比较指定内存设备缓存，参考组来自换算，没有运行不共享后端。固定先单后双的顺序会改变host缓存状态，不能将它写成优化导致全部host内存减少51.06%。

其他内存并未保持不变：双沙箱匿名PSS约为单沙箱的两倍；file和current增量还更高。双沙箱file在任务前段迅速增加至约890 MiB增量，未确认各来源分别贡献多少，不能用设备驻留的近似不变覆盖这段增长。当前交付指定设备缓存的物理驻留变化及其余占用上下文，**没有得到完整host物理并集的节省百分比**。
