## 从设备创建之前接收组外事件

上一版只接收测量组内页、私有卷文件和指定loop后备镜像。共享内存设备不属于后两项，因此其组外页会被过滤。设备是在恢复过程中才创建的，等恢复完成再更新名单会留下首批请求的采集空档。

本次为专用短探针增加`$rdev!=0`条件，即先接收块设备文件缓存的加入／移出，不依赖其页记账组。结束后，使用两个VMM实际映射的设备号，以及保存的设备节点身份，选出共同的内存设备，再做覆盖核对；其他块设备不会加入目标占用。普通文件仍使用原测量组、私有卷及指定后备镜像条件，没有扩大为整机所有普通文件采集。

这个方案不改后端，不依赖设备刚创建时的异步名单更新。记录范围比上一版更大，新的采集成本和实际汇总完整性需要在下一次定向短验证中观察；不将上版的实跑通过自动沿用到新版。它仍只在`--trace-dual-task`中使用，不常驻轻量监控。

无法从页元数据解析记账组时，保留`owner=0`并标为归属未知，不丢弃、不当作根组。根组仍有自己的实际组编号。出现目标设备归属未知事件时，即使总量与mincore相符，检查也报告`OWNER_UNKNOWN`，不作为完整通过。

## 初始容量必须有依据

探针准备时只读取`/sys/dev/block`的设备元数据，保存当时存在的设备号及时间，不打开或读取块设备内容。只有同时满足以下条件，才将目标设备在追踪起点的缓存量设为零：

1. 本次实际执行的是接收所有块设备记账组的新版探针；
2. 目标设备号不在保存的初始设备清单中；
3. 清单时间早于探针就绪，实际恢复开始晚于探针就绪。

这对应本入口中“探针就绪后才执行任务和恢复”的创建顺序。已有设备、旧版本缺失清单或顺序不符，均报告`INITIAL_STATE_UNKNOWN`；不能根据第一条加入事件推定初始为零。

## 独立驻留检查已接入实际判定

`host_file_trace.py`新增`device_coverage()`和`matched_device_coverage()`，直接使用已保存的事件汇总和运行时mincore结果，不增加驻留扫描。

对目标设备，在mincore开始之前已经完整结束的0.1秒事件段，计算加入字节减移出字节。与查询相交的事件段不插值：将其全部移出量用于下界、全部加入量用于上界，再加有依据的初始量。mincore必须处于这个范围内。相符的状态名称为`MATCHES_QUERY_BOUNDS`，表示与查询时间范围一致，不表示已识别guest页类型或证明整个host覆盖完整。

缺少目标事件、设备身份冲突、查询不稳定、初始状态未知、未知记账组或超出范围的驻留量都单列。保留查询前后范围、未解释驻留字节和事件推算过多的字节，不用净差互相抵扣。

`FileCapture.stop()`分别保存事件输出状态与`coverage_status`。定向入口在清理前检查后者：未达到`MATCHES_QUERY_BOUNDS`就将`host_shared_device_event_coverage`记为FAIL，沿用原失败卷保留规则；任务结果和事件输出完整性各自保留。普通任务、原空闲恢复、原单／双对照及旧小loop入口不增加这一前置条件。
