## 新版怎样合并调用

修改仅在`scripts/sandbox_runtime_monitor.py`的轻量模式启用：

| 环节 | 原流程 | 新流程 |
| --- | --- | --- |
| 上传 | 两个Python文件各上传一次 | 复用已有目录上传，一次传两个文件 |
| 初始化 | 单独创建目录、写初始阶段 | 由采集命令在第一个样本前完成 |
| 就绪 | 独立等待首样本并核对进程身份 | 保留 |
| 任务中的阶段标记 | 原调用及guest边界更新 | 保留 |
| 收尾 | 写阶段、停止、等待宿主命令返回、再远程确认回收 | 一次`finish`写阶段、停止并等进程回收；host仍等待原采集命令返回并核对身份 |
| 下载 | 一次目录下载 | 保留 |

按旧Prettier的一个官方检查阶段计，阻塞调用10→5；另算常驻采集命令时，总调用11→6。它是调用次数减少，不表示耗时减半。新版未降低0.1秒采样频率、改采样字段、增加guest暂停或变更默认回收。

`finish`仍核对PID、启动时间和boot ID，只操作自有采集进程；僵尸进程不算回收完成。host同时确认管理该进程的命令已经结束，再接受完成回执和下载数据。旧`stop`／`reaped`入口、完整CPU／I/O模式及原显式合并模式保持原行为。轻量模式每次启动仍上传自身代码，不直接相信快照里已有文件，也不新增代码哈希检查。
