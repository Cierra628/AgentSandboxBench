# 七支暂停后，第二遍有没有筛掉页？

基线：`handoff-20261118`，`dd9ba4c9ebae59db68055da5e8ad566b87d6eb16`。本轮运行 `bash scripts/check-platform-offline.sh`，退出码 0，末行 `status=PASS scope=platform-offline`。

**上次七支暂停窗口中，直接后备和快照下层的首末证据逐行相同，第二遍因首末不一致而排除的页为 0。但现有口径下不能默认单遍。** 驱动可以少发请求，归属函数却没有接受单次宿主观测作为“前后已确认”的入口。没有用第一遍冒充第二遍，本轮未启动沙箱。七支单遍墙钟没有实测值；按上轮成本推算是 **4.53–5.03 秒量级**。

## 1. 第二遍提供的是哪份证据

- **读数在驱动层可拆，确认条件在核心层不可拆。** 七支暂停驱动（提交 `daeff18` 的 `scripts/run_seven_paused_export.py:51–72,190–205`）先读 guest 清单圈定的页，再对相同偏移读第二次；末次 RAM 映射换算的偏移若不同，会把两层末读相应条目置零。驱动恢复 guest 后另取末份清单。基线常规路径见 `scripts/live_task_cache.py:325–365`。下文的“页次减半”仅指去掉直接后备、下层的第二遍，不把省去 VMM、provider 或 guest 复核当作收益。
- **计入条件。** `scripts/provider_slot_cache.py:215–232` 先匹配前后 guest 页的生命周期标记，再检查 VMM 三次页表项的物理身份相关位。直接后备的 `dok`、下层的 `lok` 各自要求首末项相等且驻留；VMM 文件映射与有效直接后备物理页号冲突时，该候选无效。不满足某层条件就不由该层确认，其他有独立证据的层仍可确认。没有来源确认的 guest 容量另计，不能当作零驻留。
- **provider 与去重。** 同文件 `segment_sources:183–190`、`account_provider:263–285` 校验两帧槽位、分段来源和驻留物理页号；`account_observed_provider:318–344` 返回当前宿主物理页号（PFN）的并集，字段为 `host_four_segment_current_union_bytes`、`host_four_segment_unconfirmed_guest_capacity_bytes`。设备偏移用于归属，不是去重键。
- **为什么不能只删两行调用。** 核心显式取 `direct[:,2:4]`、`lower[:,2:4]` 中的首末证据；缺列不能完成确认，补零会丢失原本可确认的来源，把首读复制进末列则会让相等检查恒真。guest 前后身份匹配也不能代替宿主 PFN 首末匹配。旧 `docs/records/paused-host-cache-20261119/REPORT.md` 的七个位图只证明一个镜像文件在七个观测点的驻留偏移相同，没有测该文件 PFN，更没有覆盖所有后备、VMM 与 provider。

## 3. 单遍能否接近 4.5 秒：两个有依据的推算

| 情形 | 七支墙钟 | 折合每页次 | 依据 |
|---|---:|---:|---|
| 两遍实测 | 9.053046 秒 | 14.63 µs | 最早宿主首读到最晚宿主返回；618,684 页次 |
| 单遍：总时间随页次同比减少 | 4.526523 秒 | 14.63 µs | 同一批候选，页次减半；假定原整轮平均成本不变 |
| 单遍：只删两层末读，其他阶段历时不变 | 5.032930 秒 | 16.27 µs | 逐支从实测结束时刻扣除两段末读历时，再取七支最晚结束，减去原最早起点 |

第二种推算只扣 `rows.*.stages.direct_last/lower_last` 的结束减开始，不动首读、偏移换算、VMM、provider 等候或末次映射检查，也没有把七支重叠的时间相加。**4.53–5.03 秒是这两个假设的结果范围，不是墙钟的保证区间。** 并发调度和等候在单遍下可能改变。相比单支的 5.63 µs/页次，两种七支推算均约为其 2.6–2.9 倍；这不是对单遍 CPU 争用的测量。即使按乐观的同比例模型，也接近 4.5 秒而非 1 秒。

**判定：保留两遍作为默认。** 本次离线记录支持“上次第二遍没有改变计数”，不支持“暂停本身能代替第二遍的证据”。若今后有与本支、各宿主来源及读窗绑定的独立证据证明物理身份不变，再评估等价替代；本轮不改采集器、不新增实验。[复核脚本](replay.py) 仅从已存文件读取。
