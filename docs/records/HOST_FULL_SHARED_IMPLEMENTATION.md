**完整GRPO／BPO已增加独立的共享文件测量模式，60项相关离线检查通过，其中12项为新模式检查。** 两份快照的目标对象先统一去重，再各查一次；实际使用者、本轮保存产物、未查询项和成本分别记录。旧配置和默认PSS行为保持。本次没有启动服务、沙箱、真实设备查询或任务负载预检。

## 新模式怎样使用

下一轮获准实跑时，使用现有管理脚本的新选项：

```bash
bash scripts/run-light-rollout-pair.sh \
  --shared-files --output ".artifacts/host-full-shared-$(date -u +%Y%m%dT%H%M%SZ)"
```

它依次使用以下新配置运行完整GRPO和BPO各一次，并负责原源服务状态和自有资源收尾：

- `configs/platform-prettier6604-grpo-shared-files.json`
- `configs/platform-prettier6604-bpo-shared-files.json`

两份配置显式设置`host_shared_files: true`，并保持`light_monitor`、`host_file_monitor`开启。原命令不传`--shared-files`时仍使用原light-host配置；旧单任务、递增、完整采样和其他后端入口不改变。新模式不允许复用缺少对象测量的旧完整GRPO结果。

新模式关闭host PSS（按共享比例分摊的进程驻留内存量），不创建`pss.jsonl`，也不绘制空的PSS子图。guest meminfo和host组内计数仍每0.1秒采样，原内核与默认回收保持。

## 对象先去重，再查询

实现位于[`host_rollout_shared.py`](../../scripts/host_rollout_shared.py)：

- 只读系统／工具后备从每个活跃guest的实际驱动取得；允许只在一部分实例中共享，不要求覆盖全部七个实例。
- 快照内存后备只从六个恢复实例的实际映射取得，关联第11／24步快照及各自使用者。原冷启动主沙箱不调用恢复内存查询。
- 原始内存层从两份实际内存镜像配置取得，并核对文件身份、容量和自有服务中的打开描述符；镜像配置来源、lower清单及描述符依据一并保留，不读取层文件数据。
- 块设备按rdev、普通文件按device＋inode在整批目标中去重。两个快照共同引用同一层或同一只读盘时，只做一次mincore驻留查询；不同inode的复制文件不按内容合并。
- 本轮保存产生的原始层标为`CREATED_THIS_ROLLOUT`，即“本轮保存产物”，不扣成公共导入准备。每个对象同时保留实际使用者和所关联快照。
- 独立可写盘保留缓存身份与使用者，驻留为null、状态为`NOT_REQUESTED`；保存后尚未恢复的设备、尚未物化的配置也保留相应状态，不填零。

复用原`ram_backend`、`device_residency`和`mincore_file`，未修改旧单快照查询接口。两个内存设备先查询，再查其他选中设备；原始层按整批唯一身份各查询一次。身份、容量、映射范围或稳定性不符时记录失败，不省略目标后报成功。

## 保存期间不加驻留扫描

| 位置 | 新增观察 |
| --- | --- |
| 原准备结束、私有服务和guest创建前 | 复用自有文件系统同步；保存同步回执 |
| 原路径调度前、无guest | 组内基线计数 |
| GRPO七个根就绪／BPO主沙箱就绪 | 计数及实际驱动身份 |
| BPO第11／24步保存前后 | 计数、时刻、快照ID、设备／配置创建状态 |
| 原有两批恢复分别就绪 | 计数、实际映射、驱动和快照使用关系 |
| 全部原路径结束、官方检查及删除前 | 一次整批选中对象驻留查询 |

原并发、七条路径、两次保存、两批恢复及原动作不改成递增短测。保存前后的新增读取放在原暂停段外；没有添加暂停、清缓存、预读、锁页、延迟请求或强制保留设备。

如果最终附加查询失败，仍继续完成原官方检查，保存原动作和官方结果，最后将测量标为FAIL并按原失败规则保留现场。未将原每实例0通过、2失败改写为任务成功。

## 查询成本和任务用时分开

任务原始目录增加`host-shared-files.json`，保存各阶段的计数、身份、开始／结束、线程CPU和最终逐对象查询时段。读取时段不含随后JSON写出，整轮墙钟用时仍包含记录操作。

外层报告新增：

- `shared-files/REPORT.md`：按对象列出缓存身份、实际使用者、来源和驻留量。
- `shared-files/summary.json`：完整阶段、对象、未查询项、官方结果和成本。
- 外层`summary.json`的`shared_files`：上述报告位置及关键时长。

计时含义：

- `original_paths_elapsed_ns`：从开始创建本轮沙箱前，到全部原路径完成；包含创建和期间的元数据观察，不含随后驻留查询及官方检查。
- `query_elapsed_ns`：最终选中对象查询、核对及前后计数读取。
- `metadata_elapsed_ns`／`metadata_thread_cpu_ns`：各次阶段计数／身份读取的用时及线程CPU，逐次原值保留。
- 原整轮用时仍到全部官方检查结束，新模式包含新增观察和查询，不偷偷改成扣除查询后的数字；原工具耗时仍只来自原动作日志。

原任务清理后的普通文件清单仍按原流程保存，是另一时段和范围，不与活对象驻留、组内file或PSS相加。新模式没有输出跨缓存层的物理总和，也没有套用七份单沙箱容量参考。
