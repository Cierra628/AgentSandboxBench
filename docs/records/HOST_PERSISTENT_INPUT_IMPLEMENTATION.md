## 输入和清理顺序已接通

[`host_persistent_input.py`](../../scripts/host_persistent_input.py)负责自有磁盘来源、普通文件导入、身份校验及收尾；原[`run_host_file_workflow.py`](../../scripts/run_host_file_workflow.py)、[`run_host_scaling.py`](../../scripts/run_host_scaling.py)和隔离验证控制程序负责原运行流程。

```text
源服务／配置条件检查
→ 组外备份校验，完整预留20 GiB并恢复临时镜像，只读挂载
→ 新建统计组，组内进程首次创建和填充普通输入文件
→ 内容校验，记录新文件设备号／inode／大小／mtime和实际统计组身份
→ 仅fsync自有普通文件和目录
→ 正常卸载、分离loop并删除成功的临时镜像
→ 原8 GiB运行卷和私有服务；新commits目录只读绑定
→ 无guest基线；N=1／2各原11动作、各5秒观察
→ 一次输入文件驻留交叉核对
→ 原任务检查、报告、边界及卷检查和清理
→ 最终报告及输入文件核对通过，清理本轮普通输入
```

恢复写入使用已预留文件的`r+b`模式，不截断预留。准备和导入子进程沿用全局写盘锁、20 GiB动态磁盘保护、有限超时及进程组回收；运行卷仍沿用原固定容量保护。临时工作目录以0700创建，子进程使用077权限掩码，整卷备份和日志不向其他用户开放。源归档和原服务目录不写入。新目录已存在就拒绝，不使用或清理那份旧目录。

原`--immutable-cache-seed`仍要求只读loop种子；新隔离验证参数`--persistent-cache-seed`单独验证profile、任务／服务镜像、组身份、新文件身份及临时来源已释放，不把普通目录伪装成旧RAM种子。当前只支持默认回收、guest及host采样均开启的1→2短测，拒绝混入RAM种子、恢复模式或改变DAMON的配置。

首版仍保留原六类、105条已验证输入路径，不做未经验证的文件裁剪。commits是实际运行的只读来源；deps、索引等按原方式再复制到运行卷，其普通来源副本也保留到本轮结束，尚未消除这些较小的准备副本。完整性校验仍会使缓存变热；不声明冷缓存，不锁页或反复读取维持驻留。

## 新统计范围和一次性驻留检查

周期采样不变：host每0.1秒读取`memory.current`及原分项，guest保留轻量采样，不增加PSS或周期mincore。

只在新选项中，两次5秒观察窗口均结束后，对新输入普通文件做一次mincore核对，即查询已有缓存是否驻留而不读取文件内容：

- 用设备号＋inode去重，核对保存的文件身份，顺序查询而不读取映射内容。
- 保存每个对象驻留量、总量、实际组身份、查询起止、线程CPU和前后cgroup计数。
- 若驻留总量超过前后`file`较大值，记录差额；没有差额也不单凭这一大小关系宣称所有页归属完整。
- 没有运行旧缓存归属BPF探针，`ownership`明确为`NOT_QUERIED`，不是实测组外0。
- 查询失败时驻留量／差额为null，保留实际错误与时间／CPU成本。原任务结果保留；外层新入口记为`persistent-input-check`失败，普通输入目录保留，不把任务PASS当作核对通过，也不自动重跑。

原主曲线截止到第二次观察端点，两个窗口不会包含后来查询。`host-scaling.json`及报告中`input_file_check`单列这段数据；原来的全文件收尾驻留扫描仍未请求，不能因原字段`NOT_REQUESTED`而忽略新字段。

新输入文件在新组内首次填充，不复用旧目标inode；源恢复位于组外，并在基线前清理临时镜像。报告的`measurement_scope`及计时说明明确记录这一边界，组外准备成本在`source_preparation`收据中。不把新旧绝对current差称为物理节省，组外程序页、节点服务等覆盖限制仍保留。

## 失败时保留什么

- 恢复、导入或运行失败：仅关闭本次对应挂载／loop和进程；临时镜像若还在、部分普通输入及日志保留。清理通过精确后备文件查找loop，也覆盖附加设备后尚未写入完整收据的中断。
- 报告或一次性输入核对失败：原任务结果和已完成的服务／运行卷清理保持；普通输入保留供诊断。
- 只有最终外层报告及输入核对通过才删除本轮普通输入。源备份、原服务、其他实验文件均不删除。
- 本次创建统计组前准备失败，不会去停止尚未创建的服务单元；运行服务单元结束或停止后才处理其统计组及遗留临时来源。
