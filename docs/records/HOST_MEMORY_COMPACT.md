## 新选项只改变任务后的明细查询

普通三任务的guest及host采样参数不变：0.1秒计数、1秒PSS。新增选项只允许独立卷单／双沙箱模式；旧普通、共享卷和空闲恢复入口保持原顺序。导入后同步自有文件系统的已验证设置继续使用。

旧顺序为：

```text
目标设备及前后PSS → 其他64 GiB设备 → 原始内存层 → 普通文件清单
```

新顺序为：

```text
目标前PSS → 目标设备 → 目标后PSS
→ 普通文件清单 → 补查进程映射文件 → 全组PSS
→ 其他64 GiB设备及原始内存层
```

主要查询位于连续的一段时间内；其他设备并没有省略，而是移到这段之后。因此缩短的是主要分项之间的时间差，**不是把完整采样流程缩短到2秒**。

映射补查读取统计组内各进程的`maps`和身份元数据，通过进程根目录定位文件，核对设备号、inode，再通过`mmap(PROT_NONE)`和`mincore`查询驻留。相同文件不重复计入；名字相同但文件身份不同的库分别保留。没有读取文件内容、预读负载、强制驻留、暂停guest或修改DAMON。

实现集中在新`host_mapped_backing.py`以及原`device_residency`的可选回调；`host_file_matched_task.py`仅在新选项启用时复用这次普通清单，不再重复扫描。完整记录位于每组`compact-memory.json`，原`host-matched.json`也保留关联。

新增文件包含Python、服务与ublk提供程序、aenv，以及相应动态库和locale文件。**155 MiB是这些文件在host的全局缓存驻留，不是采样程序新增了155 MiB内存，也不全是本次任务独占。** 其中可能有其他进程共用或未被本组映射的页；不将它直接加到cgroup file上。

未解析条目主要为：

- `anon_inode:[io_uring]`：两组9／15个汇总键；
- KVM vCPU映射：两组各1个汇总键；
- 已删除的`memfd:iov_deque`：1／2个汇总键；
- 已删除的`/dev/zero`：1／2个汇总键。

这些记录没有可用于当前普通路径查询的活文件名，保留为未知，没有填入零驻留。**“键”按设备号和inode汇总，只用于组织元数据，不是独立物理对象数。** 特别是匿名inode可被多个不同映射共用；本轮双VMM的KVM条目也共用一个键，不能由此判断它们共用同一批物理页。

因此查询状态为`OBSERVED`，表示本次已执行的查询及身份检查有效；映射覆盖状态仍为`INCOMPLETE`。PSS及kernel汇总中可能已包含这些特殊映射的占用，但还没有逐项对应，不再重复加一次，也不把它们当作完全未采集的同等容量。
