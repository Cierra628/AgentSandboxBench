## 判断：最大的可测项是直接后备查询，不是导出器启动

按共同窗口内七个读者各占 1/7 的时间核算，**直接后备查询占 52.03%**，快照下层查询占 **34.19%**，两项合计 **86.22%**。每个分支两次直接后备查询实际合计 4.066–5.905 秒，含调用期间等待。导出器启动和初始身份绑定在轮前，不在这 9.9 秒内；轮内 guest 两次导出往返占 0.64%。

**成本性质：查页工作随输入增长，墙钟线性关系未被证明。** 标量查询对有效偏移去重、按连续偏移段发 mincore，再遍历输入、对有效行逐个查 BPF 结果表并验证本次 token。工作量取决于候选数、有效偏移数及其连续段数，不取决于最后留下多少确认页；每次查询也有固定的身份与线程绑定成本。这里仅有一轮、没有相同条件下改变页数的观测。各查询未分开计时 mincore、结果表查找、锁/调度等待，不能判定其中某一步占多少，更不能把缩小样本后的墙钟按比例折算。数据不支持“主要是一次性启动成本”，也不足以判定抽样是否达标。

## 476 微秒的分子与分母

用 CSV 七组实际读取时间计算，交集 = min(结束) − max(开始) = **9.904312 秒**；七支输出之和 D = **20,781**（可能重复），所以 T/D = **476.604 µs/确认页**。七支实际读窗长度各为 9.905–10.254 秒。起点错位 2.958 ms。整轮 wall_ns = 10.264852 秒，与交集不同；批级 four_unique_pages = 10,120，也与 D 不同。
仅直接后备、下层两遍就分别请求 **422,036、223,202** 个偏移页次。首遍 guest 有约三万条/分支；第二遍后备和下层仍按首遍的偏移列表重查，不因 guest 缓存衰减而自动缩短。因此 476 是七路并发墙钟按最终确认产出折算，不是执行一次页查询的成本；不能据此宣称单页查询相对 9–16 µs 实测慢了 30–50 倍。

换成实际工作量分母：完整七支查询的 Σ阶段耗时 / Σ请求页次、Σ线程 CPU / Σ请求页次，直接后备为 **85.48 / 21.05 µs**，快照下层为 **106.19 / 23.24 µs**。这里的阶段耗时包含等待，线程 CPU 不含阻塞。上述比值不是无竞争下的单页延迟。
