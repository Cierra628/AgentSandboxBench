## 新模式如何采集

仍使用每组一个新私有服务、七个guest和原189动作。共享19文件、每文件7使用者；独立133文件、每文件1使用者，按设备编号和inode区分。主容量是这些初始系统盘下层文件在host的实际缓存驻留，不包括匿名页、可写层、工具盘和其他文件。

1. 复用原副本准备和自有文件系统同步。在创建guest前，只对准备清单中的自有目标文件调用`POSIX_FADV_DONTNEED`。除第0套`image-cache/commits`，还精确覆盖第1～6套`rootfs-copy-control/copies`；缺文件、重复身份、额外文件或符号链接逃出目标范围都会拒绝。
2. 用原mincore查询P0。必须实测为0才进入七路并发创建；建议调用返回成功而仍有驻留时失败，不自动反复回收或等待。
3. 一个后台工作线程顺序查询，下一次在上次查询结束后至少5秒开始，不追补、不重叠。它与原0.1秒host计数线程分开，guest采样仍0.1秒、PSS关闭、AgentENV默认回收保持。
4. 主流程只记录创建开始、全部原准备完成、各段开始／结束和原路径及下载全部结束的host单调时间，不等待驻留查询。跨阶段的查询标为`MIXED_PHASES`，不插值成精确阶段容量。
5. 原路径结束后停止后台查询，等待当前查询退出，再执行原P1真实系统盘引用、分配记录、使用者、驻留及查询后身份核对。原官方检查和清理顺序保持。过程点在P1关联检查通过后才整体记为PASS。

这里只把指定文件的缓存起点设为0。卷后备文件、其他缓存和后端正常预读不变；原任务没有增加读文件命令、共同前缀等待或运行中主动回收。

参数已经过成对驱动、统计组包装、`member_command`、隔离后端预检查和实际任务两处参数重建，再到GRPO执行器及`FullRootfsControl`。新模式拒绝BPO、关闭驻留查询和非完整对照组合；原`--private-cold-read`仍只属于双服务短实验。汇总也拒绝把冷缓存与旧热准备结果拼成一对。

原结果目录额外保存：

各次查询保留开始／结束、墙钟和线程CPU。`worker_timing`另存后台线程整个生命周期和总CPU，包含周期查询、数据写出和等待，与查询／写出成本有重叠，不能再相加。`stop`记录等待后台线程退出的时间；数据和事件写出成本单列，数据写出合计明确截至最后完成记录写出前。整轮及原工具计时仍保留全部实际成本，不扣掉查询后重定义任务耗时。

## 失败收尾不与查询并行删除目标

正常结束、原任务失败、查询失败都会请求停止查询，确认线程退出后才删除guest。查询本身失败会使本次测量失败，即使线程已退出，也不接受为PASS。

若请求停止后30秒仍未退出，内层不删除guest、不改写工作线程正在写的状态，并返回FAIL。后台线程设为daemon线程，因此内层进程退出后它也结束；外层等待该进程返回后，才按原隔离流程停止本次自有服务、保存记录并清理挂载，失败卷按原规则保留。不会为此结束其他进程或删除旧卷。

## 离线验证回答了什么

新增14项检查及原43项相关回归，共57项不同检查通过：

- 19／133个精确目标及去重、额外对象与逃出范围拒绝，所有文件都查询；建议与mincore均模拟，只有本地临时小文件参与元数据检查。
- 非零P0或查询失败不能启动工作线程；完整入口初始失败保留FAIL。
- 用**实际`do_grpo`方法**配假guest操作：后台查询被受控阻塞时，七次创建及七条路径仍全部并发派发。实际方法去掉新增阶段记录后，与修改前语法树相同；原`start`、路径选择、动作检查、准备副本及容量函数均未变。
- 受控本地线程验证“查询结束后间隔”、无追补、等待当前查询、超时后禁止内层guest清理，以及查询错误与实际回收分开记录。
- 模拟完整P0／P1确认P1前线程已退出，七个实际角色、19×7／133×1关联与查询后核对仍执行，P1不额外查询第二遍。
- 跨阶段点、查询及写出成本、成对驱动和两处参数重建、报告字段、冷／热混用拒绝均通过。
- 原两沙箱短实验7项、副本短对照14项、完整副本11项、BPO 3项、查询开关8项回归通过。测试报告样例最初误放在raw目录内部，按原报告约束改到同级目录后通过；错误日志保留，没有修改原报告约束或重跑真实任务。
