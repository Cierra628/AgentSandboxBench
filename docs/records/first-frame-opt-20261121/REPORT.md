# 首帧慢在哪里：分段解包触发了一次长垃圾回收

基线分支 study/margin-sensitivity-20261121，提交 483f0e7；性能基准为 cad1058 的五批。本轮使用一次真实七支诊断，未重跑基线五批。**定位有结果，提速没有验收：第一批七支页数全部低于 30,000，触发止损。正常数据量下的最慢批余量仍以 40.747 ms 为准。**

## 定位：时间记在构造里，但几乎全花在回收上

诊断保留 ProviderCache.snapshot 原实现，只在两处独立的分段列表解包外分别计时，同时记录 Python 垃圾回收开始和结束、进程缺页数。每帧 16 个槽，每槽分别解包 before 和 after，各 512 条记录。**首帧七支都在 before 解包中触发一次长的第 1 代垃圾回收**（Python 扫描一组存活过先前回收的对象）。回收区间包含在 before、也包含在 record_build 内，下列各列不可相加。

|1|181.793|181.316|180.529|99.30%|0.314|
|2|172.055|171.552|170.749|99.24%|0.327|
|3|187.014|186.522|185.696|99.29%|0.323|

扣除这次回收，首帧构造每支只剩约 1.2–1.4 ms；第二帧完整构造为 1.210–1.350 ms。首帧两处解包合计每支 32,090–32,094 次次缺页、0 次主缺页；计数覆盖解包，不是对回收单独计数。现有记录未指出回收器扫描了哪些对象，也不能判断次缺页有多少来自 fork 后的写时复制。七支同现足以定位**本次**长等待；正常页数旧五批没有回收回调，不能把旧批的每一毫秒倒推为回收。

**决定：不提交生产优化。** 只改解包循环的固有成本，按本批证据能直接消掉的时间很小；关闭 GC 或改到派发前主动回收，会改变回收发生时机，不能证明消除了总成本。第一批又不满足实际页数门槛，因此既不把这类改动部署，也不继续开新批。唯一新增的运行能力是显式单批诊断开关；未开启时仍走原五批。没有改归属、分段有效条件、输出格式、阈值或 stage_timing_version=1 的七个边界。诊断记录在 snapshot 返回后写出，额外开销不算作优化收益。

## 等价性：逐条验证的是诊断版，而非尚未实现的优化

对指定的 11-21 目录全部 35 对、11-18 目录全部 5 对真实帧，分别从两侧原值重建独立元数据读数，以原顺序重放两次元数据读取和中间页表读取。原版与诊断版各自构造，在 640 对槽上逐项对照 **327,680 条分段判定**，其中 192,704 条可用；差异 0。构造出的完整记录也逐字段等于存档。结合各自真实的 guest 前后清单与三来源表，两版逐对比较四来源物理页集合、provider 集合和归属计数，均相同；35 对另与原 sets.npz 的页号逐页一致。不是只比总数。[逐对核验](equivalence.csv) · [重放脚本](equivalence.py)。

## 第 1 批页数异常，停止余下实跑

七份结果就绪 634.954 ms，父进程合并 26.741 ms，派发到批级结果可用 **661.992 ms**。7/7 支完成 16 MiB 校验、绑定、两遍查询与身份复核；无 File exists。各支依次确认 **19,514、19,498、19,535、19,553、19,546、19,550、19,509** 页，批级去重 **54,943** 页（provider 单列 0），远低于基线每支 36,102–37,918、批级 168,832–172,364。偏低在查询前已可见：七支首份 guest 清单均只有 13,605 条，基线为 28,739–30,495 条；为何导出时已少，未定位。不能把差异归给构造或合并。

**新余量：无可验收数值。** 本批算术余量为 338.008 ms，但工作集不达标。第 2–5 批未运行，没有补跑。沙箱和探针清理通过，私有容器、挂载和 loop 已撤下；平台按失败策略保留原实验卷，本轮未删除。

本地证据：私有实验目录 .artifacts/storage-isolated-service/20261121T074350Z-1581565/，其中 guest-cache/result.json 记录止损，guest-cache/try-1/result.json 记录计时与页数，shared-device 各角色的 profile.jsonl（位于 try-1 下）记录回收的成对时刻。summarize.py 接受基线目录和诊断目录两个参数。等价脚本接受任务所列 11-21、11-18 两个实验目录。

**下一步建议（未执行）：** 先离线对照本批与正常批的源快照和首次清单，查明工作集何时变小。若另行授权正常页数下的回收优化，再同时验证回收耗时、七阶段和派发到批级结果的墙钟；只有回收成本没有挪到后续阶段且整轮余量增加，才接受改动。
