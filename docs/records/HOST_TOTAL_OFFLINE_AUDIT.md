# 整体host内存离线核对：可补哪些量，还缺哪些证据（2026-10-22）

**现有轻量曲线和指定对象驻留结果继续可用；保存的数据还不能生成“memory.current加组外项”的同阶段总量。主要缺口是：归属查询仅在任务后查导入归档，基线没有对应查询；其他文件、设备和已删除后备的全局驻留没有同时取得记账归属。已知ublk命令缓冲也只有任务后分配量，不能直接当作新增量。**

本轮只读保存的JSON及相关源码，没有启动服务、沙箱或探针，没有查询当前缓存、读取归档／镜像内容或改变回收设置。完成标准是明确每个加项的来源、重叠、比较阶段和未知项，不以清单差额变成零为标准。

## 哪些量可以加入，哪些只能分列

| 量或对象 | 现有证据 | 对整体核算的处理 |
| --- | --- | --- |
| 实验组memory.current | 有任务前基线和任务后直接计数，包含本组及后代的记账 | 作为组内总记账基础；包含控制程序、私有服务和全部沙箱，不是任务进程独占量 |
| file、anon、kernel及shmem | 周期曲线与端点计数 | 已包含在总记账中或与其中类别重叠，不再相加；shmem已包含在file中 |
| 全组进程PSS及分类 | 每秒采样，显式明细另有前后读取 | 用于解释映射变化；不加到current或文件驻留上，PARTIAL不当作完整总量 |
| 普通文件清单、额外映射文件 | mincore给全局驻留；普通文件按设备号、inode去重，额外文件排除清单已有对象 | 没有逐页归属时，不能把整份驻留当作组外补充；相同内容的独立缓存也不能按内容合并 |
| 共享块设备及原始内存层 | 设备身份和全局驻留已测；原始层可能已在普通文件清单中 | 设备组内只计一次，原始层与文件清单去重；不能把整个设备驻留再加到current |
| 旧导入归档 | 独立查询已确认当时1746.109375 MiB在实验父组外；任务入口已显式接入 | 只有在同轮基线／端点、同一参考组及明确时段都取得归属后，才可形成这个对象的组外变化；现有旧数据不补造 |
| 已删除memfd、/dev/zero后备 | 真实单／双组已查询2／4对象，缓存共4／8 KiB；查询明确不提供页所有者 | 不是未知容量，但组内外归属仍未测；不能把这4／8 KiB直接加到current |
| io_uring、KVM映射页 | smaps已有记录；对应源码存在内核记账路径 | PSS与kernel可能重复，不作为额外加项；映射容量不代表这两类全部内核资源 |
| ublkc队列命令缓冲 | 实际配置及源码计算任务后12／16 KiB，PFN映射被PSS跳过，页分配没有请求memcg记账 | 是已确认的未记账分配候选补项，按设备存活期去重；基线没有实际配置清单，新增量保持未知 |
| 其他未记账内核分配、其他组外匿名／共享对象 | 未建立完整清单及容量界限 | 保留未知；不能把已查明的命令缓冲推广为全部内核缺项 |

普通文件的设备号和inode仅在该对象存活期内用于识别；跨运行设备号复用不表示同一个对象。匿名inode的汇总键也不等于独立物理对象数，不能据此去重所有KVM／io_uring映射。

## 约1.7 GiB差额：归档当前归属已查明，历史整体误差没有因此查明

保存的独立归属查询覆盖447004个4 KiB页，实际组内0、组外1830928384字节、未知0，所有页记在在线交互会话组。前中后驻留一致，查询段无该文件缓存加入／移出事件。它的参考组为仍存活的`/asbhost.slice`，不是历史任务已经结束的统计子组。

独立原始记录没有保存`query_start_monotonic_ns`／`query_end_monotonic_ns`，只有查询用时414.660801毫秒、全流程5.266816384秒；当前代码已能保存起止字段，但不能给旧记录补出时刻。对应真实任务发生在独立查询之前，任务记录也没有`existing_cache_owner`字段。因而这份结果不能用于修正过去的任务端点。

以最近一次已删除后备补采的原始数据复算，归档在两组任务前、运行中和最终清单共六次均为同一文件身份且驻留1746.109375 MiB：

| 清单阶段 | 单沙箱净不足／MiB | 双沙箱净不足／MiB |
| --- | ---: | ---: |
| 恢复前 | 1746.363281 | 1741.441406 |
| 任务后的运行中普通文件清单 | 1330.242188 | 1308.316406 |
| 最终普通文件清单 | 1747.968750 | 1740.363281 |

运行中普通清单没有包含ublk设备缓存，而file计数可能包含它；两者统计范围不同。即使归档驻留不变，净差仍会受清单外缓存及读取时差影响；本轮没有把每份净差逐页分配到具体对象，不能把它当成“实际组外缓存容量”。

最终净差减去归档容量，分别为＋1.859375／−5.746094 MiB。这仍只是容量诊断，不是剩余遗漏或误差的上限；不同对象的遗漏、组外记账和读取时差可能相互抵消。不从归档所在会话组直接读取整个current补入，因为那个组还有其他工作负载。

原`SHORTFALL_REQUIRES_RESOLUTION`和其他历史判定保持；当前已查明的归档归属也不再称为完全未知。旧归属的详细证据见[独立查询报告](HOST_EXISTING_CACHE_OWNER.md)。

## 当前代码缺的不是一个加法，而是基线和同阶段归属

当前调用关系如下：

- `host_file_matched_task.py::observe_matched`在基线前读取普通文件驻留；基线没有归属查询、映射明细或ublkc实际分配清单。任务后先执行原文件／设备／PSS观察，再调用一次`query_bounded`，目标固定为导入归档`repository.tar.gz`。
- `host_existing_cache_owner.py::query`仅接受非空普通文件，借助mincore内部已有缓存查找读取页记账元数据；它不是可直接用于块设备、匿名页和所有已删除后备的通用查询。不能仅修改入口文件名就声称这些对象的归属已经覆盖。
- 归属子进程继承控制程序统计组；BTF处理、BPF编译及程序加载可能带来新记账。当前查询没有直接读取包围自身的current计数。把较晚的归属量加到较早的任务端点，会混入时差，不能将查询后的current当成原任务端点。
- `host_memory_detail_report.py`把归属、PSS、文件驻留和命令缓冲分别报告，并保留旧数据NOT_MEASURED／null。这是正确的现有行为，本轮不改成自动求和。
- `host_file_monitor.py::counters`先读memory.stat，再读memory.current；不同文件不是一个原子快照。默认采样未建立全部swap／hugetlb覆盖，不能用未采字段证明不存在这些使用情况。

已删除后备的cachestat补查已解决所列对象的缓存容量，不再把“原进程无匹配fd”误说成容量仍完全未知；但`page_charge_owner`仍为NOT_MEASURED。最新1对7短对照则是冷启动路径，没有导入归档，不应机械地给它补查或加上旧1.7 GiB归档。

## 已知命令缓冲不能代替全部未记账内核内存

实际`6.19.9+`源码目录为`/home/yxli/linux-6.19.9-ioctl/`：

- `Documentation/admin-guide/cgroup-v2.rst:1300–1305、1961–1975`：current对应本组及后代；已有页的记账不随进程迁移而移动。
- `drivers/block/ublk_drv.c:2705–2738`：命令缓冲使用`GFP_KERNEL | __GFP_ZERO`和`alloc_pages_node`，没有`__GFP_ACCOUNT`；`mm/page_alloc.c:5275–5282`的页记账路径要求该标志。已有实际配置足以计算这一批缓冲分配。
- 同一个`ublk_init_queue`还分配队列结构及I/O描述数组，使用`kvzalloc_node(..., GFP_KERNEL, ...)`。命令缓冲的12／16 KiB不包括这类结构；现有数据未测其实际分配、slab路径或归属，不能直接按结构字节数补成物理量，更不能认定其他内核对象都已覆盖。

任务后单／双组分别有3／4个命令缓冲设备，合计12／16 KiB。基线阶段服务已经存在，没有保存当时设备及配置，因此不能用`2×12−16=8 KiB`冒称任务增量的节省；公共准备分配可能已被乘两次。须先核对各组基线，再计算分配变化。

## 推荐范围与下一步完成条件

当前可直接交付三个不同结果：轻量曲线、总记账相对线性参考的差、指定对象的物理驻留参考差。若增加组外补充，先固定对象清单和比较阶段，候选量定义为：

```text
T = 实验组current + 清单对象中已确认的组外驻留O + 已确认未记账分配U
ΔT = Δcurrent + (O结束−O基线) + (U结束−U基线)
减少量参考 = N×ΔT单沙箱 − ΔTN沙箱
```

这是待取得同阶段证据的“补充已知遗漏后的记账”定义，不是已算出的整体物理量。只有覆盖完整、加项不重叠、时间可比时才能进一步解释成所定义范围的物理总量；现有数据不满足这些条件。O和U任一关键项未知时不生成总数或整体节省率，不能用0代替。

公共准备只计一次；没有必要为此改变后端，继续使用用户已选择的单沙箱线性参考并标明其含义。相对线性参考的减少不等于实测不共享后端的因果收益。若某对象两端实际组外量相同，它的ΔO为零；不能因其容量大就把整份旧缓存算成任务新增或共享节省。

**建议的下一段工作仍是离线修改，不立即实跑：**只在现有显式明细恢复入口补齐导入归档的基线／端点归属和ublkc基线分配明细，为归属查询另存前后直接计数及成本；保持原任务端点、普通轻量入口和旧字段含义不变。已有目标归档查询、超时回收和命令缓冲查询直接复用，不新建全局逐页平台。

完成条件：两个阶段能绑定同一对象与实际统计组；基线与任务后容量、读取时段、查询自身记账影响分别可见；未知不补零；旧数据兼容且不自动求和。这个改动只解决所列对象的同轮归属与分配变化，仍不承诺一次短实验即可补齐所有物理覆盖。其余设备、匿名和内核覆盖保持明细，不为追求漂亮总数无限追加采集。
