# 不暂停缓存测量：本阶段验证完成（2026-10-17）

**不暂停的缓存测量已在列明范围内完成验证，耗时对照也已完成。当前采用四来源物理去重和2页查询策略，保留未知量，不再追加本阶段实验。** 交付三个对应的量：每个guest的逻辑文件缓存、这些内容在host的已确认驻留物理量，以及跨guest去重后的物理量。

三任务完整单路径和Prettier完整恢复按各自版本交付；最新provider缓冲及2页策略另有短恢复和[真实双分支](PROVIDER_REAL_PAIR.md)证据。最新[关闭/开启耗时对照](PROVIDER_PAIR_TIMING.md)中，控制器生命周期增加6.610秒（23.27%），主要新增时间落在恢复/采集就绪与采集停止；任务执行阶段的负差值保留为一对观察，不解释为稳定加速。下文将覆盖、未知量和分阶段成本分开，旧运行不追溯补算。

## 交付的三个量

1. **每个guest的逻辑文件缓存容量。** 诊断guest内核从启动起用独立成员表记录普通文件和shmem（共享内存文件）缓存页的加入、移出及身份变化。每份表的成员数乘4096字节得到容量，即`guest_cache_after_bytes`；不是累计分配量。相邻读取的`/proc/meminfo Cached`是对照量，读取时刻不同，原曲线中的`Guest Cached`不改名为同一时刻的成员表容量。匿名应用内存、块设备缓存和只在交换区中的内容不在此文件缓存范围内。
2. **这些内容在host的已确认驻留物理量。** 先将guest页关联到虚拟机监控进程（VMM）的内存，再核对当前文件映射、快照内存设备、单个原始内存层及可归属的provider缓冲。设各来源确认的当前内容物理页号集合为`V、D、R、B`，则增强路径为`4096 × |V ∪ D ∪ R ∪ B|`；旧路径只使用当时实际采集的来源。相同物理页只计一次，不同物理副本分别计入，因此host数值可以大于guest逻辑容量。旧快照版本另列，不混入当前内容。
3. **跨guest去重后的物理量。** 对有重叠观测时间的两个guest再次取物理页号并集，不能直接相加各自占用。原三层真实双分支首对为`122.961 + 124.016 = 246.977 MiB`，去重后`176.738 MiB`，扣除重复物理页`70.238 MiB`。8对均满足逐字节的集合恒等式；这里的小数仅供阅读，最新四来源结果另见下表对应报告。

host数字是已确认来源的保守测量，不用整VMM的RSS/PSS或镜像层整文件驻留替代。物理页号只留本机，不放进共享报告。

## 保留未知，验证就有明确含义

采样不是原子快照。采集器核对前后guest身份、三次VMM页表项和前后来源结果；变化或缺少确认的页保留未知。独立成员表没有逐事件输出队列，仍须检查重复加入、遗漏移出、地址越界等计数，不能将“没有事件流”解释为永远不会漏记。短恢复26份导出的这些累计异常计数为0；第2点后表32条身份失效记录在归属前被拒绝，128 KiB已计入该点256 KiB未知容量，不重复加一次。

短恢复10点未确认guest容量依次为`468、44、256、4580、0、0、0、0、0、0 KiB`。最大4580 KiB由1580 KiB新增成员和3000 KiB映射变化组成；所有通过身份和映射检查的成员都有来源确认。这个结论只适用于本批稳定成员，变化页仍为未知。独立逐页分类与原总量一致，见[分类结果](GUEST_UNCONFIRMED_GAP_TWO.md)。

短恢复中provider每点完整缓冲有4040 KiB驻留，另有21张混合边界页。完整页分为当前副本、旧副本、尚未用于请求、来源前后均不在缓存表、混合来源和剩余未知六类，互斥且合计一致；其中当前副本8–732 KiB，剩余未知52–424 KiB。边界页不按完整页强行归属。当前副本已纳入物理并集，不再加一次。

**未确认guest容量与未知缓冲物理量是两种量，既不记为零，也不相加成host总量。** guest未知为0的采样点，仍可能有未知缓冲或未覆盖来源。

provider可靠归属依赖私有只读设备显式启用GET_DATA协议及下一次填充前失效的记录，不靠延迟请求扩大有效时间。最早槽位校准的3.9375 MiB未知驻留和23张边界页仍按当时证据保留，没有追溯改为当前副本。协议及其真实验证见[协议源码核对](PROVIDER_SLOT_PROTOCOL.md)、[GET_DATA验证](PROVIDER_GET_DATA_VALIDATION.md)。

## 准备、执行与收尾成本分别报告

以下只使用最新关闭/开启各一次的对照。单位为秒，四个分项是控制器内互不重叠的host时间区间；“其他阶段”由生命周期减去前三项得到，包括启动、保存、最终检查、官方评测和其他清理。

| 阶段 | 关闭采集 | 开启采集 | 差值 |
| --- | ---: | ---: | ---: |
| 两次恢复至采集/任务就绪 | 2.331 | 7.966 | +5.634 |
| 两个原后缀并行执行 | 4.267 | 3.677 | −0.590 |
| 停止缓存采集 | 未执行 | 1.816 | +1.816 |
| 其他阶段，按剩余时间计算 | 21.805 | 21.555 | −0.250 |
| 控制器生命周期 | 28.403 | 35.014 | +6.610 |

关闭组没有采集停止操作，“未执行”不是缺失测量补零。按原始纳秒值，四项差值之和恰为生命周期差值；表中显示值有舍入。恢复/就绪还包含普通监控准备和恢复状态检查，差值不全是纯BPF启动时间。生命周期不包含RAM输入镜像准备、私有服务准备和离线报告生成。

31个实际动作的工具耗时合计为6.322→5.550秒（−12.22%）；两个后缀的工具合计为5.353→4.577秒（−14.49%）。它们有并发和包含关系，不再加到上述分项中。两组原任务、补丁及进程恢复检查通过；先关后开仅各一次，运行波动与顺序影响未分离，因此23.27%是本对控制器变化，不是稳定的任务执行减速率。完整数值见[耗时证据](evidence/provider-pair-timing-20261017.json)。

两组均保留guest内核成员表、provider观测记录及常规监控；开关只改变guest元数据发布、host物理采集和BPF。保持项的独立成本未包含在差值中。

### 不同验证运行的采集自身成本

- 2页短恢复每点采集线程CPU平均294.529 ms、耗时327.133 ms；guest前后读取覆盖的host时间平均188.732 ms。两层BPF辅助进程整段另用0.480/0.450 CPU秒，不在单点线程CPU内。
- 批量接收数组容量6 MiB，观测驻留物理并集2.691–2.824 MiB；控制器整体RSS为97.414–109.398 MiB，后者不是采集器独立增量或任务缓存。BPF表与临时对象的完整内存峰值未单独测得。
- guest内核静态元数据为17039360字节（16.25 MiB），常驻匿名发布缓冲为16785408字节（约16.008 MiB），属于测量开销而非任务文件缓存；它们对完整任务的独立影响尚未分离。
- 三任务基础路径中，Prettier只做过一次先关后开的对照，工具/重放/控制器用时分别增加1.65%/0.96%/3.05%。这是旧基础版本的单对观察，不能当作最新增强、其他任务或稳定减速比例。
- 短恢复原生checkpoint暂停346.758–347.227 ms，采样空缺8.071秒；采集没有增加暂停，空缺不插值。当前52项查询回归、10项分类用例及成功运行的独立物理集合检查直接复用，本轮没有重跑。

最新真实双分支每点线程CPU A/B为393.401/385.627 ms，耗时421.994/415.087 ms；guest未知0–7172/4–6040 KiB、provider未知56–776/56–552 KiB和21张边界页另列。两边观测同一个provider的4040 KiB完整缓冲，不能把两份观察相加。54份导出只有A的一份出现1条身份失效，按原规则拒绝归属；功能、独立物理集合和清理通过。完整分项见[本轮报告](PROVIDER_REAL_PAIR.md)。

耗时对照开启组每点采集线程CPU A/B为396.416/413.755 ms、耗时425.078/446.974 ms，整段线程CPU为5.673/5.071秒。这是另一组运行的局部采集成本，不替换上面的正确性运行或短恢复成本，也不是任务减速比例。

## 使用现有入口，新增覆盖另定范围

统一配置的`live_cache_kernel`用于三任务完整单路径及Prettier第24步恢复；`platform-prettier6604-checkpoint-layer-cache.json`显式加上`live_cache_lower: true`，用于单个原始内存层。查看已有运行和配置见[统一入口](../USAGE.md#不暂停物理缓存采集的统一入口)。

`LiveTaskCache`的`lower_cache`、`provider_cache`、`batch_lookup`默认均关闭；统一配置尚无后两项开关。最新provider和2页策略通过私有校准或真实双分支入口显式启用；报告入口识别已有provider数据，不代表自动开启采集。继续保持私有服务及显式选项，不替换原服务。

**本阶段没有剩余必做校准。** 最新版单对采集耗时对照已完成；压缩或多个原始层、最新增强的完整单路径覆盖、Sphinx/Xarray恢复、稳定任务开销和测量内存完整峰值属于后续扩展，不改变本页已验证范围，也不写成已经完成。

阶段汇总已完成，当前没有必做的新实验。后续若要回答稳定减速比例、保持开启部分的独立成本或新增后端覆盖，应分别确定对应的最小对照和完成条件，不自动重跑三任务。任何未来24 GiB卷仍须启动前超过50 GiB可用，保留20 GiB保护量及6 GiB余量。
