## 从保存的查询日志读取五段成本

显式批量模式结束时，原`snapshot-query-result.json`新增顶层`query_costs`列表。直接后端日志在恢复会话目录，原始层日志在其`lower-query/`子目录。每条记录用`query`号与原`queries`中的统计对应；原`queries`内容、字段和含义保持。

每条计时记录含内部总量`cpu_ns`、`elapsed_ns`、host单调时钟起止时间、`stages`和未分项差额。五段按执行顺序为：

| 字段 | 计时范围 |
| --- | --- |
| `prepare` | 文件身份/探针状态检查、查询号发布、偏移去重和连续区段切分索引 |
| `mincore_scan` | 分成连续区段、分配驻留位接收缓冲、全部mincore调用及驻留字典整理 |
| `batch_lookup` | 一次批量库调用，包括参数求值、库分派和内核返回/数据复制 |
| `batch_filter` | 对返回范围取视图、按当前查询号和请求偏移筛选、构建PFN字典 |
| `result_restore` | 数组结果还原及原查询统计写入 |

`mincore_scan`是整个驻留查询循环，不是纯内核CPU；`batch_lookup`也不是内核内部独立计时。每次完整查询固定读取11次CPU时钟和11次单调时钟，不随连续区段数增加，避免在每个mincore请求周围插入计时。

内部总量从身份检查前计到结果还原阶段记录完成，尚未包含最后整理和追加`query_costs`记录的工作。`unmeasured_cpu_ns`和`unmeasured_elapsed_ns`分别为内部总量减五段之和，包括计时记录操作、批量参数准备、返回信息整理和返回码/条数校验等间隔。

原外层查询计时仍覆盖完整`query`调用，包含新增计时记录整理；原单点计时和完整线程CPU范围也保持。内部五段用来拆解查询，不再与外层查询成本相加，避免重复计算。新增计时的真实成本须由后续实测记录。

## 默认入口、错误和物理归属保持

默认逐项查询不读取新增时钟，日志不增加`query_costs`字段。批量模式的`query_statistics`和`BatchEntries.last_statistics`也没有增加计时字段；计时独立保存，不改缺失结果含义。

身份变化、探针退出、查询号更新失败、mincore失败、批量错误或结果还原失败仍向上传递异常，不追加成功查询计时，也不逐项回退。批量读取失败后只保留本次已完成调用的内部计时，不复用前次筛选计时；失败数据不作为成功采样。

偏移换算、查询号、全部mincore和一次批量读取的先后关系保持。请求偏移和当前查询号筛选、PFN为0与缺失的区别、重复/未知偏移、旧快照副本及未知物理量的处理均保持。源码结构核对确认：去掉计时语句后，查询及批量读取的计算语句与修改前一致；数组还原函数、偏移换算、物理归属函数和外层采集器原样保留。
