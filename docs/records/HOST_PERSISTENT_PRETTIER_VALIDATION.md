## 新文件来源、顺序和一次驻留核对通过

固定备份在组外恢复为完整预留的20 GiB临时镜像；组内新建并填充105个普通文件，记录新设备号＋inode等身份，原完整性校验及逐文件／目录fsync保持。临时来源先正常卸载、分离并删除，才分配8 GiB运行卷。导入结束、自有卷同步、服务就绪／无guest基线、隔离运行结束、查询起止的实际顺序与同组身份均通过。

一次mincore查询只检查普通输入的已有缓存是否驻留，不读取数据页。它发生在原隔离运行及自有清理完成后、普通输入删除前，保存为`AFTER_ISOLATED_RUNTIME_CLEANUP`：

file比输入驻留多2.438 MiB，不是二者完全相等。检查差额的定义是`max(0, 驻留−前后file较大值)`；本轮没有出现驻留大于file的不足。`ownership=NOT_QUERIED`仍表示未逐页查询组内／组外归属，差额0不是组外占用实测为0，也不修正历史约1.7 GiB问题的数据。

这是**结束后的输入驻留**，不代表任务运行中各时刻驻留。查询不计入工具、回放和任务控制程序时间，计入外层流程；host周期采样仍覆盖这一收尾段。原全文件扫描为NOT_REQUESTED，与独立的新输入查询区分，没有PSS、周期mincore或BPF。
