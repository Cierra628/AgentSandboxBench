**已实现`light_skip_boundary_vmstat`可选开关，默认关闭。** 仅在“先全部创建再准备”的轻量GRPO开启组中，将逐步`sample_vmstat`变为空操作；仍保留表头、原边界内存、0.1秒周期采样和阶段标记。本轮46项相关离线检查通过，没有启动服务或沙箱，尚无候选模式真实性能数据。

后续[两组真实任务及离线报告恢复](LIGHT_BOUNDARY_VMSTAT_PAIR.md)已完成：378动作、1976点，创建后窗口+8.16%；原自动报告漏参已修复，16 GiB失败卷已获用户授权并定向删除，清理完成。下文保留离线实现阶段范围。

## 用原入口生成候选配置

下一次真实验证可用下列调用，本轮没有执行：

```bash
bash scripts/run-grpo-light-pair.sh \
  --grpo-create-before-setup \
  --light-skip-boundary-vmstat \
  --order off-on \
  --output .artifacts/grpo-light-no-boundary-vmstat-pair-new
```

关闭组仍关闭全部采样；开启组的自有派生配置增加`light_skip_boundary_vmstat: true`。原配置文件不改，不带新参数仍走原入口。配置字段可选且必须为布尔值；缺少先全部创建模式、关闭采样、单角色、BPO／TVCache、完整采集、host或缓存诊断等不符合范围的组合，会在资源分配前拒绝。

新参数通过`platform_tasks.py`的检查和实际命令、`validate_isolated_agentenv.py`两处参数重建，再传入任务执行器。配对入口只给开启组加新字段，并在每组结束后核对实际选项与请求一致，发生不一致即停止。

## 只减少当前三项曲线不用的读取

[`boundary_runner`](../../scripts/sandbox_runtime_monitor.py)新增默认关闭的`skip_vmstat`参数，只替换vmstat函数体；它的调用位置、输出表头及其他执行脚本内容保持。

保留项包括：

- 原命令、原计时、退出码、stdout／stderr和补丁。
- 动作前后及段开始／结束的meminfo记录，以及由这些记录计算的原分支峰值。
- 阶段标记、0.1秒周期meminfo、首点就绪和采样进程回收。
- 原并发创建／准备／任务、官方结果检查、失败收齐与清理。
- AgentENV默认回收，不新增清缓存、暂停、预读或锁页。

在现有七guest、35段、189动作配置中，新候选预期保留448行边界内存，vmstat仅有表头、0行数据。相应减少448次`/proc/vmstat`读取和896次`date`／`awk`调用，是按执行次数得到的数量，不是已测得的秒数收益。

## 审核没有把“未采集”当成零值

任务执行器和离线审核都继续调用原`verify_path`。候选组额外严格检查每段内存行数为`2+2×动作数`，vmstat表头完整且没有数据；原动作、退出码、清单及峰值校验不放宽。

候选结果、有效配置和轻量报告均记录`light_skip_boundary_vmstat: true`；任务结果与报告另保存：

```json
{
  "status": "NOT_MEASURED",
  "reason": "explicitly skipped boundary vmstat",
  "row_count": 0,
  "boundary_memory_rows": 448
}
```

该段位于`boundary_vmstat`字段，`row_count`指文件行数，不是页故障或I/O计数为0。只有原任务及候选行数检查通过，才生成任务成功结果。

原整轮、创建后窗口、工具累计和动作／下载窗口定义不改。原三对、十对及保留边界vmstat的新调度三对汇总入口，均拒绝混入本候选；候选配对报告依据保存计划核对开启／关闭两组的选项，不把旧统计当作候选数据。
