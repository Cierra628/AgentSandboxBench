## 用实际映射反查，不猜测匿名区域的原偏移

原候选准备从采样起点的guest缓存页出发，按VMM映射换算内存后端偏移。缓冲则会保留其他内存页的内容；这些来源不一定仍属于guest缓存，所以“没有候选”本身不能决定归属。

本次沿反方向检查：

1. 用既有分类器选出唯一原因是“来源偏移缺少起点候选”的完整驻留物理页。仍要求四份512字节段记录一致、代次为偶数、来源已知、分配和物理页稳定；原当前/旧副本和其他未知类别不混入。
2. 对每个来源页，在该点保存的前后VMM映射中查找相同后端设备、inode和`rw-p`私有文件映射。将文件偏移换算成VMM地址，再通过已核对的KVM内存布局换算成guest物理页号。
3. 前后必须得到同一个、唯一的guest页。检查所有匹配映射，不任选一个别名；匿名映射、缺失、身份不符、越界、前后变化或多个guest别名都保留未解。本批目标来源均通过，不需要推测匿名区域原来的文件偏移。
4. 在同一点两份完整guest表中核对这个页号。前后都缺失、仅后表出现、前后身份相同、身份变化及代次0未知记录分别处理；不会把代次0当作非缓存。

反查使用的关系是原正向换算的逆运算，正向源码为`scripts/snapshot_cache_residency.py:offsets`及`measure_file_physical.py:ram_address`：

```text
VMM地址 = 映射起始地址 + 后端来源偏移 − 映射文件偏移
guest地址 = KVM区域guest起点 + VMM地址 − KVM区域host起点
```

均按实际地址区间核对完整4096字节来源页，正确处理guest地址中的设备空洞。两份guest表由`kernel_cache_metadata.decode`检查格式、计数和异常；内核位图及身份记录的来源仍为已验证的`patches/agentenv-cache-metadata/linux-6.1.175.patch`。表中缺失表示对应成员快照不包含该页，不进一步推断它是空闲页、匿名页或内核页。

如果未来反查缺失、别名不唯一或身份发生变化，分类脚本会保留未解；当前数据没有这些情况，不为它们新增通用采集路径。反查本身只定位来源，不能替代当前/旧版本所需的页映射检查，也不自动准入新的缓存物理页。
