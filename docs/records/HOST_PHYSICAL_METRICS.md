# 以内核实测的host物理内存指标为主

2026-11-08：本次只优化测量口径并核对已有数据，不启动沙箱，不增加采样。目标是让主结果确实反映host内存，而不是guest配置容量、文件长度或累计分配量。

## 主结果保留四类量，各自回答一个问题

| 主结果 | 测量方法 | 物理意义与统计范围 |
| --- | --- | --- |
| 整组内存成本 | cgroup的`memory.current`，普通周期0.1秒 | host内核记在该组及后代的当前内存分配量；包含匿名、文件和内核内存，不是虚拟地址空间大小。用于比较同范围整组成本 |
| 整组文件缓存成本 | 同组`memory.stat:file`，普通周期0.1秒 | 记在该组的文件数据缓存页容量，包含tmpfs和共享内存。它是物理内存相关记账，不是磁盘文件总长度 |
| 每个VMM的比例驻留量 | 已绑定沙箱身份的VMM进程`smaps_rollup:Pss` | 内核根据实际映射页及其映射次数分摊共享内存。七VMM的和除7表示平均VMM分摊量，不是每guest独占量或完整沙箱平均成本 |
| 指定对象的host缓存页容量 | 普通文件`mincore`；块设备`cachestat:nr_cache × PAGE_SIZE` | 直接查询目标对象的host缓存。普通磁盘文件mincore统计已准备好内容的驻留页；cachestat统计缓存条目对应的页数，包括内容尚未准备好的页。二者保留各自名称、状态和查询时间 |

这些量都有实际内存分配、驻留或缓存页的内核依据；**统计范围不完整，不等于量本身是逻辑容量。** `current`是物理内存的记账口径，PSS是比例分摊口径，两者都不是逐物理页去重后的全host精确并集。内核批量更新、顺序查询及运行中回收会带来时间差，不宣称瞬时精确一致。

`anon`、`kernel`、`shmem`、`file_dirty`和`file_writeback`仍用于解释current/file变化，不增加新的周期查询。`shmem`已在file中；dirty/writeback是状态分类，也不能再次相加。没有同频保存的字段只作为终点值，不能画成已有周期曲线。

## guest数据保留，但不用于host物理内存结论

- guest `Cached`仍保留为guest视角缓存统计；它描述guest管理的页，不能直接说明这些页在host是否驻留、是否共享。
- guest `MemTotal−MemAvailable`是guest可用内存的估算差，不能替代host实际占用。
- 配置的4 GiB guest RAM、设备容量、文件长度、映射长度，只描述容量或查询范围，不算已占用内存。累计分配、`nr_evicted`和refault次数也不算当前内存容量。
- 换出到磁盘的`Swap`、`SwapPss`和`memory.swap.current`另作背景，不加到物理驻留；若启用zswap，压缩后仍在RAM中的实际内存与压缩前逻辑容量也要分开。
- 任务耗时、工具累计和采集CPU仍单独报告；它们是计时量，不与内存量混算。

不停止现有guest采样，不删除原始字段。新报告的host内存主图只选上表指标，guest曲线单独标明“guest视角，不能当作host物理占用”。旧图与历史数值保持。

## 用最少操作保证测到的不是容量推算

1. **current/file读取实际cgroup文件。** 保存组路径和采集窗口；分别列全采集窗口峰值、可识别的执行阶段峰值和终点值。不能把全窗口峰值改名为执行峰值。
2. **PSS读取实际VMM，不读取配置内存。** 保留sandbox ID、PID、启动时间、cgroup和读取时间。周期PSS保持已有1秒，终点再查一次；普通host-current轻量入口仍默认不开PSS，不为统一报告强行启用。
3. **mincore只统计返回位图的驻留位。** 文件大小只决定查询范围；按实际页大小换算，末页按整页计。先确认host-root权限及CAP_FOWNER，防止内核对无权限查询返回全1；普通文件按设备号:inode去重。身份、大小、前后元数据及查询窗口状态沿用现有检查。
4. **cachestat只使用nr_cache作为当前缓存页数。** 不把nr_evicted、设备长度或历史成功值补进当前容量；设备按活跃rdev去重，保留实际FD、容量和来源检查。RAM独立查询与原严格查询是两个时间窗口，不相加。
5. **保留未知。** UNKNOWN／PARTIAL、完整量null、观测小计和实际0分别列出。未采集的层不填零；登记后变化与查询中变化继续分开记录。

现有采集器已执行这些核心换算与身份检查，本次不改运行代码、不增加PFN扫描（逐物理页编号查询）、周期mincore或广泛文件扫描。默认回收保持，不暂停、不预读、不强制驻留。

## 比较共享收益时只比较同一量、同一范围

- 整组记账差：`independent.current − shared.current`。必须使用相同任务、N、组范围、起点条件及阶段；准备缓存、任务运行和回收影响分别解释。它回答组内成本，不自动证明能多放多少沙箱。
- 指定文件缓存差：比较同类目标对象、同阶段的去重mincore或同方法cachestat；结论写“这批目标文件／设备缓存”，不写“全部沙箱内存”。
- 不把`current`、`file`、PSS、mincore以及不同缓存层相加作总内存；不把`current−file`当作anon。文件缓存和PSS可能已经包含在current中，组外缓存又可能不在其中。
- 同一任务范围不变时报告重复均值、中位数和波动；不同统计组、不同查询范围、单次方法验证和正式重复分开，不靠重新命名消除差异。

当前三调度是**私有服务cgroup**，不含组外RAM输入准备及外层控制；八任务中除Prettier外是**整个实验组cgroup**。二者都是有效host记账，不能直接混排绝对值。实际组外容量仍需要页记账归属证据，不能拿mincore减file的差额加回current。
