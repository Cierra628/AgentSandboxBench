## 解决旧页消失后无法跟踪重读的问题

旧双沙箱校准保存的是第一次写入时的 PFN（物理页号）及生命周期。它们消失不等于文件当前缓存为零：重读可能把同一文件偏移装入另一页。

新增显式查询以“打开文件的设备号、inode（文件编号）、inode generation”和“实际缓存映射的同类身份”为依据，返回当前页偏移、guest PFN、生命周期。虚拟文件身份与实际缓存映射身份分开保存，不假定 overlay 文件系统中两者相同。

每个采样对使用当时的文件页集合，不依赖第一次写入的页清单。前后文件身份、大小、修改时间不一致，或查询记录与前后全 guest 生命周期不一致时，保留未知。页在两个查询之间换了 PFN，本对不确认；下一对若新页保持稳定，可确认新页。不能据此得出具体由谁回收了页面。

## 显式采集接口与输出

`LiveTaskCache(..., file_cache_path='/workspace/asb-child-cache.bin', expected_kernel=<新内核版本>)` 才开启；默认关闭，仅支持私有校准会话，不用于原恢复路径。普通实验入口、采样间隔、闭合规则不变。现在校准入口支持显式`--dynamic-file --kernel <新内核>`，通过`--guest-cache-dynamic-file`传入隔离入口。原固定初始页检查保留，新检查独立为`dynamic-file-calibration-v1`。

`guest_cache_exporter.py --file-cache-path` 在每次发布全 guest 元数据前查询文件，并在独立的 `file-query/` 目录保存 `file-NNNN.bin/json`。不改变原二进制发布格式。每份 JSON 记录发布编号、沙箱 ID、guest boot ID、文件状态、查询时间和运行期 DAMON 状态；文件尚未创建时记 UNAVAILABLE，不记零。采集器退出异常时仍尝试下载已有附加文件，下载失败追加到原错误。

`report_dynamic_file_cache.py` 校验这些附加文件与原发布编号、沙箱、boot ID、查询窗口一致，再与同一点的全 guest 元数据及三次 host pagemap 读数合并。内核映射枚举前后页数与记录数不符，或有未知记录时，当前文件缓存量留空；已观察条目容量另列。host 只确认前后生命周期及物理映射一致的页，并按 host PFN 去重；未确认、非驻留、swap 分列。

这些是非原子查询。在两个端点之间增删又恢复的变化不能全部排除，确认物理量仍是稳定页下界，不能当成任一瞬间的完整值。原始 PFN 只留本地。

DAMON 复用现有采集器的七个状态/计数名称：`enabled`、`kdamond_pid`、`nr_reclaim_tried_regions`、`bytes_reclaim_tried_regions`、`nr_reclaimed_regions`、`bytes_reclaimed_regions`、`nr_quota_exceeds`，并保存回收配置。只读 sysfs，不启停回收；缺字段逐项留空并记原因。计数回退不算增量。这些是全 guest 的区域操作统计，不是指定文件的回收原因，也不是 host 实际释放字节。

附加文件放在guest的tmpfs中，也会占用内存并进入全guest缓存统计。本次已单列查询耗时、匿名导出缓冲区与附加文件逻辑长度；元数据自身的物理驻留和开关性能差仍未量化，不能把新增成本算作任务本身。

37项启动前模拟回归通过，随后离线未知项解释与空slice收尾增加3项回归，最终相关8项通过；测试只使用模拟数据。新路径在控制程序退出后确认专属slice无人再停止该单元，其他路径不变。日志及本次定向收尾回执在报告的上级目录。
