# 七支查询成本拟合：可估总工作量，不能可靠拆出每段和每页的单价

**证据文件。** 上一轮报告在本地提交 `24905e9:docs/records/seven-query-granularity-20261119/REPORT.md`，不在基线标签中。本轮数值从原始目录 `.artifacts/storage-isolated-service/20261118T131857Z-610591/guest-cache/` 读取：`page-rounds.jsonl`；每个 `live-cache/restored-{1..7}-pages/` 下的 `samples.jsonl`、`pair-0000-{backend,lower}.bin`、`snapshot-query-result.json` 和 `lower-query/snapshot-query-result.json`。14 个“分支 × 来源”组合全部可读，两遍均有记录。

**选择线程 CPU，而不是 9.904 秒墙钟拟合。** 每个观测取一个分支、一个来源在两遍查询调用内的线程 CPU 之和。这反映该线程实际执行的工作，不把其他线程运行时本线程的阻塞算成 CPU。两层查询共 **14.072082 核·秒**，占本轮七个读线程 **16.116435 核·秒**的 87.32%；不是所有线程阶段之和，也不是 tracer 进程 CPU。七路同时读取的共同窗口 9.904312 秒、整轮墙钟 10.264852 秒，均不作为回归因变量。

**判断。** 指定的无截距最小二乘给出 **a = −67.980 µs/次，b = 25.614 µs/页次**。负的固定开销没有物理解释。虽然总体 R² 为 0.931，这批数据没有可靠区分“每次调用主导”还是“每页主导”。整段保留 10% 时，两项期望工作量同时降到 10%；独立逐页保留 10% 时，期望 mincore 调用反而增至 **58,455.76 次（原来的 1.521 倍）**。后者省多少时间，对不能稳定估出的 a 极为敏感。以下给有条件的墙钟推算，不把它当作实测性能。

## 为什么 R² 高，参数却不能当单价

对表中 14 行等权，以微秒为单位求 `min Σ(y−aC−bP)²`，不加截距。RMSE = 71.063 ms/行；常规中心化 R² = 1 − SSE / Σ(y−均值)² = **0.9311**（无截距软件常给出的非中心化值为 0.9953）。按无约束系数分解，段数项为 −2.613 核·秒，页数项为 +16.527 核·秒。它们只是共同拟合出来的项，不是两种操作实际花掉的 CPU。

- **规模与来源混在一起。** C 与 P 的相关系数 0.9865，两列分别除以自身二范数后，设计矩阵条件数为 32.96。每行平均段长仅在 15.53–19.95 页之间；直接后备 7 行的 P 更是都落在 60,088–60,396。两遍使用相同布局，不是两次独立改变段数的实验。就原始模型而言，外推到随机逐页 10% 时的平均段长仅 1.10 页，远出样本范围。
- **残差不是均匀噪声。** 实际减拟合：直接后备平均 −24.69 ms，下层平均 +47.23 ms；跨层残差与 P 的相关系数 −0.52。第 6 支直接后备 −131.41 ms、下层 +99.34 ms，一支占全部残差平方和的 **38.38%**。这说明存在来源/分支差异，不足以归因给某个内核操作。
- **对单支敏感。** 每次留出整整一个分支、用其余六支两层重拟合，a 从 −138.53 到 +101.00，b 从 15.66 到 29.73；去掉第 6 支时 a 翻正。分层各拟合七行时，直接后备为 (49.30, 18.04)、下层为 (119.04, 16.51)，但层内中心化 R² 分别仅 0.001 和 0.362。没有足够的独立布局和单独计时来确定两种单价。
- **b 不是单条 BPF 查表延迟。** 查询调用还包含偏移去重、组段、逐输入行组装结果（含跳过下层无映射行）、查询身份检查等。CPU 不含阻塞等待；没有证据把这些工作全部归入 a 或 b，更不能把共同窗口分摊值当作单次调用延迟。

## 三种情形：先算工作量，再讨论秒数

原始 C = 38,434，P = 645,238。以下分别在**各层实际查询的偏移布局**上计算，不模拟抽样，也不假定两层的段边界相同。若必须用一个共同 guest 候选掩码在两层同时保留完整段，“每层均按段取 10%”只是理想情形，未验证这种掩码存在。

1. **按段保留 10%。** 每个原段以相同概率 q=0.1 保留整段；不改变所选段的长度，不延伸到未选页。段数、页次期望分别为 3,843.4、64,523.8。线性模型中查询 CPU 的期望比值为 **0.1**，不依赖 a、b 如何拆分。按已测 CPU 比例标定，查询约 1.407 核·秒。
2. **按页独立保留 10%。** 每页保留概率 q，两遍用同一选择。段首被保留的概率为 q；段内其余位置成为新段首的概率为 q(1−q)。所以 E[C′] = qC + q(1−q)(P−C) = **58,455.76**，E[P′] = **64,523.8**。无需抽样即可得到这个期望。不是所有“取 10% 页”的方式都有此段数：连续选取或按文件成块选择不等于独立选页。
3. **只去掉第二遍。** C 和 P 各减半，查询 CPU 模型给 **50%**。原记录中末遍实际用了 **7.084 核·秒**（首遍 6.988），占查询 CPU 的 50.34%。这是能够直接核实的工作量，不是可直接节约的关键路径墙钟。去掉末遍会丢失前后物理驻留一致证据，**不满足原口径**，仅作成本反事实。

### 墙钟换算是一项单独假设

两层查询在共同窗口内的阶段交长，七支求和除 7，得到 Q = **8.539335 秒**。共同窗口其余占用为 **1.364977 秒**；从共同窗口到整轮另有 **0.360539 秒**。设查询 CPU 比例 r = (aC′+bP′)/(aC+bP)。为使推算可复核，给一个**保持原并发效率、原时间重叠关系，且非查询部分墙钟不变**的情形：

- 共同窗口 W′ = 1.364977 + 8.539335r 秒；
- 整轮 T′ = **1.725516 + 8.539335r 秒**。

这不是用 CPU 拟合墙钟，也不是关键路径模型。其他阶段包括依赖页数的位置转换和依赖到达时序的共享屏障，**1.725516 不是不可省的实测固定下限**。不同布局下的每段/每页耗时、等待与临界分支均没有新增观测，真实墙钟无法唯一推出。

### 参数敏感性：哪些秒数能信，哪些不能

直接套无约束 OLS，逐页 10% 的 r = **−0.167**，竟得出负查询时间，必须弃用此项预测。以下非负参数不是四次测量：分别指定 a，令 b = Σ[P(y−aC)]/ΣP²，在原 14 行重新拟合最优 b。a=0 行也是非负最小二乘的边界解，不是测得 mincore 免费。R² 均为中心化值；“段项占比”按 aC/(aC+bP) 计算；倍数比较的是**整轮**墙钟。

## 距离 1 秒：只对有证据的路径排名

- **按段抽样**是可计算且保留两遍的情形中最接近目标的：条件整轮 **2.579 秒，差 1.579 秒**，还需在整轮上再快 2.58 倍。即使查询已缩至 0.854 秒，1 秒预算也只给其他部分留下 **0.146 秒**，而本情形保留了 1.726 秒。它衡量的是成本，不是对抽样精度的验收。
- **去第二遍**只把查询工作量减半，按半量模型仍差 **4.995 秒**，且不合格。两层前后物理页证据不能省成一遍。
- **单支内部并发**在这批数据里从未发生，实测只有支内串行、支间七路并行。没有支内加速比、可用并行资源、竞争和屏障变化数据，**不能给真实秒数，也不能声称它在三条路径中排第几**。仅在同一“其他不变”情形下，若查询部分加速 k 倍，则整轮为 1.725516 + 8.539335/k 秒；任何有限 k 都达不到 1 秒，即使 k 趋于无穷也差 0.726 秒。这个算式不证明实际调度的硬下限。

**最终判断：** 砍完整段能按模型同时省段数与页次；砍离散候选页只确定省页次，不保证省调用。基于这七支，不能可信地给出固定调用开销和逐页开销各自的物理单价，不能把 10% 候选直接换算成 1 秒墙钟，也不能用单支内部并发的未知收益补足差额。
