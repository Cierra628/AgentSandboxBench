# 并发启动时轻量采样的三对验证（2026-10-26）

**六组全部完成，共创建42个新guest、执行0个原任务动作，取得2537个采样点。** 早返回guest的采样部署和实际采样，确实与其余guest尚未返回的创建请求重叠。冷启动耗时的配对变化为−24.64%、+318.52%、+136.85%；长等待主要出现在服务的“开始创建沙箱”日志之前，现有记录还不能确定其中多少由采样引起。

本次没有普通任务准备、仓库检查或任务负载上传与创建请求重叠。结果说明启动前置等待仍明显波动，不能给出稳定的“采样使冷启动增加多少”比例；也不从此前完整GRPO的整轮+2.60%中扣除本次差值。

## 只切换创建返回后的采样

每组使用一份新私有服务和16 GiB隔离卷，七个新guest并发创建，每个为2 CPU／4096 MiB。使用同一源镜像、普通guest-only GRPO的镜像环境和现有冷启动客户端；不复用预启动池。这里的“冷启动”指创建新guest，**不表示清空host文件缓存**。

- 开启组：每个创建命令返回后立即上传原两文件采样包，启动0.1秒轻量采样，等待首点就绪；不等其他guest创建完才部署。
- 关闭组：完全不部署或启动采样器。
- 两组：所有创建命令结束后才查询七个guest的身份、VMM绑定和启动ID，随后并发清理；没有原任务、仓库检查、任务负载上传、保存／恢复或官方评估，也不额外等待取点。
- 默认回收保持；没有host周期内存采样、PSS、mincore、预读、强制驻留或主动释放缓存。

执行顺序固定为关闭→开启、开启→关闭、关闭→开启。每组独立准备并释放原只读镜像种子；第一组同时作为新入口真实验证，通过后完成剩余五组，没有失败、重试或额外组。

旧入口默认行为保持；只有显式`--startup-sampling on|off`跳过原任务检查和任务运行，输出标记为`NOT_RUN_STARTUP_ONLY`，不生成虚构的任务结果或任务曲线。
