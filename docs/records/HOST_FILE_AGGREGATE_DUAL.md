## 本轮任务中的快速增长已有直接来源记录

后缀开始后2.500250—2.800489秒，三个连续采样间隔内file增加134.515625 MiB。完全落在该窗口内的0.1秒事件段记录到：

- loop后备镜像在测量组内净加入134.234375 MiB，在测量组父组另加入1.050781 MiB；没有对应移出。
- 共享内存设备净加入0.042969 MiB，私有卷内文件净加入0.019531 MiB。
- 与窗口边界相交的事件段另存，没有按比例分配；其中不含额外loop后备镜像事件。

本轮快速增长主要来自loop后备镜像缓存，而不是共享内存设备缓存。后备镜像加入事件的栈包含`ext4_buffered_write_iter → ext4_file_write_iter → lo_rw_aio → loop_process_work`。栈针对整个观测期累计，不逐笔绑定到组外事件。file存在统计汇总延迟，134.234375 MiB与134.515625 MiB不作为严格逐点相等验证。

整个探针期间，已记录的后备镜像加入中，**4.558594 MiB在测量组外**：父组1.050781 MiB、根组3.507812 MiB。完全位于任务后的事件段中，后备镜像另有721.714844 MiB加入。它们是事件字节量，不是全部当前驻留；不能直接补到file曲线或抵扣最终1.167969 MiB净差。

此前另一轮约515 MiB的增长没有逐文件事件，本轮没有追溯改写其来源；两轮准备及背景写回时机不同，不把曲线差异当优化收益。

## mincore发现了独立的覆盖缺口

探针在第一次恢复前约12秒已就绪。按实际设备号关联共享内存设备，记录到的该设备加入和移出总量均为508.636719 MiB，整个已记录生命周期净变化为零。

在设备mincore查询时，已记录事件推算为**391.183594 MiB**，mincore实际驻留为**392.203125 MiB**，差**1.019531 MiB，即261个4 KiB页**。与查询相交的0.1秒事件段内没有该设备的已记录变化，因此不能用这部分时间段的边界误差抵消差额。完整计数只检查同一个筛选范围内的总计，无法发现被条件过滤掉的事件。

源码`host_file_trace.py`的筛选条件为`$owned || $dev==VOLUME_DEVICE || $backing`。`$owned`表示页实际记账组在本轮测量组内；后两个条件明确覆盖私有卷文件和指定loop镜像。共享内存块设备不属于这两项，**其组外页会被排除**。这是已确认的覆盖限制；当前数据还不足以确定261页的实际归属，不能将它们全部记为组外、零占用或加入已确认物理并集。

这里的1.019531 MiB是运行时共享设备的覆盖差额；最终普通文件1.167969 MiB是另一个清单和窗口的记账净差。两者不能相抵、相加或互相解释。整体host物理节省率、guest缓存对应的物理页并集继续未测得。
