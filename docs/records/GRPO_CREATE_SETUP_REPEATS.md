# 先全部创建再准备：GRPO三对采样开销（2026-10-26）

**三对约定实验完成。** 本轮新增开启→关闭、关闭→开启两对，28个新guest、756个原动作、3803个采样点；连同[首对](GRPO_CREATE_SETUP_PAIR.md)，共六次完整GRPO、42个guest、1134动作、5625点。

全部创建完成至控制程序结束的配对耗时变化中位数为**+7.76%，范围+5.15%～+11.22%**；原控制程序整轮为**+12.59%，范围+7.92%～+25.64%**。三对创建后窗口均增加，动作及下载窗口也均增加，采集影响不只表现为冷启动波动。

## 三对保持同一执行方式

顺序依次为关闭→开启、开启→关闭、关闭→开启。原七路径、189动作／次、2 CPU／4096 MiB guest、16 GiB私有卷、源镜像、0.1秒guest-only轻量采样及默认回收保持。没有host采样、PSS、物理驻留查询、服务指标或缓存控制，也没有额外预读、锁页或暂停。

三对都使用[显式新模式](GRPO_CREATE_SETUP_IMPLEMENTATION.md)：七个创建并发且立即登记；全部创建完成后，七个准备并发，每guest仍先采样再检查／上传；全部准备完成后执行原任务。三份配对源码、六次实际执行器及三次实际采样代码副本一致，本轮没有修改执行器或采样器。

各组均通过原任务动作／顺序／退出码／关键输出／补丁核对、两组一致性、采样开关、阶段顺序及清理检查。官方每实例仍为0通过、2失败，采集通过没有改写任务结果。全部42个沙箱ID不同，无平台或采集失败、重试、额外组。

## 哪些差值已经定位，哪些仍需分析

三对创建请求跨度分别为2.859→8.026、3.453→4.504、2.716→3.419秒。该阶段尚未部署本项目采样器，所以这段差值不是运行中的周期采样与创建重叠造成的；本批没有服务分段指标，不指定具体等待位置。

创建后的增量分别为1.916、1.394、2.799秒。三对任务派发／下载阶段均增加约0.938～1.577秒，检查后的工作与清理增加约0.229～0.305秒；准备阶段变化则有正有负。完整且互不重复的阶段分解见JSON，每组之和精确等于原整轮。

当前判断：采样器自身CPU成本较低，但本配置的七沙箱批任务仍有可见的完成时延影响。报告开销时应同时给原整轮、创建后窗口和全部范围，而不是只给CPU或工具累计。三对用于说明本批重复结果，不作为所有任务的固定减速率，也不用于比较新旧调度谁更快。

每个开启组35次阻塞控制调用：每guest上传包、首点就绪、阶段标记、停止／回收及下载各一次。后台采集命令的存活时间不计入这35次阻塞累计。这些操作已在上述阶段里，并集也可能与其他guest的操作重叠，不再加到整轮上。

第三对的七次上传累计4.494913秒，前两对为0.302542／0.310240秒；首点就绪累计2.195202秒，前两对为1.368966／1.049766秒。第三对上传、就绪分别取自身并集为1.097013／1.238479秒，两者还会互相重叠，不能再相加。这解释了第三对直接控制累计较大主要落在哪些调用，尚未区分API、传输和服务调度的内部等待。
