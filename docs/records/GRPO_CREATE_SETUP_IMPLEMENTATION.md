# GRPO先创建后准备：离线实现完成（2026-10-26）

已增加显式的“七个沙箱全部创建后，再并发准备”模式。旧默认顺序保留；本页记录离线实现阶段的32项检查，该阶段没有启动服务或沙箱。

后续已完成[同一新模式的一对真实验证](GRPO_CREATE_SETUP_PAIR.md)：14个新沙箱、378动作、1822点；整轮+25.64%，创建后窗口+7.76%。下文保留本阶段离线实现范围。

## 新模式怎样执行

原入口不带新参数时，仍是每个沙箱创建返回后立即启采样、检查和上传。新模式按以下顺序执行：

1. 七个创建并发进行，每个返回后立即登记沙箱ID，供失败时清理；等七个创建全部结束。
2. 七个准备流程并发进行。开启组每个沙箱仍先部署采样器、等首点就绪，再检查源码、上传检查程序、运行基线检查、上传任务；关闭组跳过采样。
3. 等全部准备完成，按原七条路径执行189个动作，保留原结果检查和清理。

创建失败时，等待其他在途创建结束，不开始准备；准备或采样失败时，等待其他在途准备结束，不开始任务。所有创建成功的ID都在原清理清单中，不只删除准备成功者。原`RuntimeMonitor.stop`对未启动采样的ID直接返回，再由原删除操作清理沙箱。

不串行创建、不加入固定等待、不暂停沙箱、不清缓存、不预读任务文件或强制驻留。默认后台回收保持。

## 使用原一对入口

以下是下一次真实验证的调用方式，本轮没有执行：

```bash
bash scripts/run-grpo-light-pair.sh \
  --grpo-create-before-setup \
  --order off-on \
  --output .artifacts/grpo-create-before-setup-pair-new
```

入口从原开启、关闭配置各生成一份自有配置，保存于该结果目录的`configs/`，其中增加可选布尔字段`grpo_create_before_setup: true`。原配置文件不改，省略字段或设置为`false`时保持旧行为。

新选项依次通过`platform_tasks.py`的输入检查和实际命令、`validate_isolated_agentenv.py`的后端检查及真实任务参数重建，最后传给`run_prettier6604_grpo.py`。后端参数为`--prettier6604-grpo-create-before-setup`，任务执行器参数为`--grpo-create-before-setup`。不符合范围的组合在资源分配前拒绝。

本阶段只支持普通Prettier七沙箱GRPO的0.1秒轻量开启／完全关闭对照。不能与host查询、快照恢复、缓存控制、单角色、完整CPU／I/O采集或启动专用诊断合用。旧BPO、TVCache和恢复入口仍调用原`start(role, template=..., parent=...)`，原先的创建及准备操作按相同顺序连接。

## 计时不扣掉冷启动

`result.json`、有效配置和报告保存`grpo_setup_schedule`：

- `per-guest-setup`：旧顺序；旧文件没有此字段时按原顺序解释。
- `create-all-before-setup`：新顺序。

原工具累计、动作及下载窗口、创建请求跨度、rollout窗口和`controller_elapsed_ns`全部保留。新模式另存实际host单调时钟时间：

| 字段 | 意义 |
| --- | --- |
| `all_created_monotonic_ns` | 七个创建均成功返回且登记完毕 |
| `all_prepared_monotonic_ns` | 七个准备流程均完成 |
| `controller_end_monotonic_ns` | 原控制程序整轮计时的结束位置，在最终清理之后 |
| `create_to_setup_ns` | 全部创建完成至全部准备完成 |
| `created_to_controller_end_ns` | 全部创建完成至控制程序结束，含准备、任务、检查、采样收尾／下载和删除 |

后两个窗口由上述实际时间点计算，不从旧结果中扣除冷启动再改名。创建之前及创建过程的耗时仍在原控制程序整轮中。开启、关闭两类报告都保留这些字段；关闭组仍不产生内存曲线或零值样本。

一对检查器还核对七个创建结束早于创建完成标记，28个源码／检查／上传操作处于两个阶段标记之间，七个采样会话开始不早于全部创建完成。第一组实际调度与请求不符时即停止，不再运行第二组。配对汇总拒绝混用两种调度；原三对／十对汇总入口只接受旧调度。

## 曲线范围有明确变化

新模式仍覆盖准备、原任务、最终检查和删除前的采样阶段，但不覆盖早创建沙箱等待其他创建完成的区间。报告标明这一变化，不补0、不插值，也不将旧曲线平移为新曲线。

默认回收在等待时继续运行，初始Cached可能变化。新模式可排除创建窗口内本项目准备活动的重叠，长创建等待是否仍出现及实际开销多少，要由新实跑回答。[原十对](GRPO_LIGHT_TEN_PAIRS.md)的全部数值继续保留。
