# Prettier无代理采样开关对照：方案与离线实现

## 结论：离线接入和两对四次正式对照均完成

2026-10-31先离线定位了“本地无代理＋持久化输入＋关闭采样”的七类阻挡，随后经用户授权完成六个运行脚本的定向接入。复用原host／guest关闭实现及报告，没有重写采样器或任务执行器。92项相关离线回归通过；之后按固定顺序完成四次新guest正式实验，功能、真实开关、共同查询及清理通过。

离线接入阶段只使用小文件和模拟服务，没有恢复或启动沙箱。正式阶段沿同一路径执行原任务，不下载或回退17891。既有三任务单轮继续使用[统一汇总](../../results/local-no-proxy-three-tasks-20261031/REPORT.md)，本批四次单独报告，旧批次不混入。

## 使用已有关闭配置，不新增采样模式

本批关闭组使用以下入口；以后复跑仍需对应实验授权、固定源服务就绪及资源检查：

```bash
bash scripts/run-host-file-monitor.sh \
  configs/platform-prettier6604-host-current-off.json \
  --persistent-input --local-no-proxy
```

开启组只换为`platform-prettier6604-host-current.json`。两组原任务、评测、本地镜像／无代理检查及结束后输入查询保持一致。关闭组不启动host线程或guest采样器，边界函数为空操作、没有guest采样阶段标记；创建前计数为None，运行内存和采样CPU保留未测，不产生假曲线。结束后输入驻留及其查询成本仍真实记录，不计成运行曲线。

本批关闭放行适用于显式无代理、持久化输入、默认回收的Prettier完整单任务。后续[Sphinx／Xarray关闭也已离线接通](PYTHON_LOCAL_NO_PROXY_SAMPLING_PLAN.md)，真实对照待运行；本报告Prettier结果不改写。短创建检查与关闭组合、冲突host-on、混合恢复／精细分析仍拒绝。未启用新选项的旧持久化关闭仍拒绝，旧非持久化关闭及三个任务的开启路径保持。

验证覆盖真实配置→平台参数→原生解析→任务执行器参数、原工具计时片段一致；模拟工作流验证导入→原生清理结束→一次输入查询→报告→成功后释放。缺本地材料、缺guest代理证明、错误基线、查询失败／容量不足、报告及清理失败均保留输入，不重跑原生任务。真实工具报告检查关闭内存为未测、保留原官方失败、无内存图，并附加同阶段输入查询／成本。原有报告检查继续拒绝周期／边界／host采样残留。

92项检查包括新增12项和80项相关旧回归。三个旧测试因早先新增外部任务分支而缺少模拟变量或使用过期源码定位，已只修正测试输入／定位；未改生产行为迎合测试。首轮日志保留，最终92项通过；语法、帮助和文档链接另做离线检查。[脱敏实现证据](evidence/prettier-local-no-proxy-off-implementation-20261031.json)及`.artifacts/prettier-local-no-proxy-off-implementation-20261031/`保留修改前代码、日志和本段差异。

## 对照整套轻量采样，不单独称为0.1秒读取开销

当前开启组不仅有后台0.1秒采集，还保留原任务脚本的边界采样，即每条命令前后及每个任务段首尾的读数。最近一轮真实Prettier结果中有：

| 任务段 | 内存边界行 | 内核事件计数边界行（vmstat） |
| --- | ---: | ---: |
| read_repo | 12 | 12 |
| read_typescript | 14 | 14 |
| core_patch | 16 | 16 |
| core_verify | 14 | 14 |
| backbone_finish | 12 | 12 |
| 合计 | 68 | 68 |

`sandbox_runtime_monitor.boundary_runner()`保留原边界meminfo／vmstat读取，并写guest采样阶段标记；`task_metrics_prefix.without_sampling()`将两个边界函数置为空操作，同时移除原逐步后台监控。现有关闭方式因此会一起关闭周期采集、这些边界读取和guest采样阶段标记。工具命令及其起止计时片段保持一致，已离线比较。

推荐直接复用这套关闭方式，回答“开启当前整套轻量采样链，任务用时变化多少”。不另造仅关闭后台0.1秒读取、仍保留边界采样的新模式。原记录的guest采样进程CPU及五次管理调用不包含这些Shell边界操作；新对照可以覆盖它们对任务和控制程序用时的综合影响。

## 离线发现的阻挡及本次接入位置

两份原配置仅差`monitor_mode: off`；解析后关闭组的`light_monitor`也会变为false。修补前离线调用及实际入口片段确认了以下拒绝；本次沿表中方向接通：

| 位置 | 修补前条件 | 本次接入 |
| --- | --- | --- |
| `prettier_no_proxy.require_mode()` | 只接受continuous＋light | 仅为固定Prettier完整单任务增加显式关闭条件；Sphinx／Xarray关闭仍拒绝 |
| `host_persistent_input.single_config()` | 持久化配置只接受开启采样 | 对新显式用法定向放行，不放宽旧默认合同；覆盖外层、平台commands和run的调用 |
| `host_persistent_input.native_option()` | 要求开启的普通current任务及light | 接受对应新Prettier关闭参数，仍检查完整任务、持久化来源和默认回收 |
| `run_host_file_workflow.py` | 持久化输入再次要求host采样on | 保留原双端开关联动，显式新关闭组可通过；冲突的host-on仍拒绝 |
| `validate_isolated_agentenv.py` | 无代理模式要求light | 放行上述Prettier关闭模式，仍走原同步、归属、代理检查和资源边界 |
| `run_prettier6604.py` | 无代理leaf要求light | 允许完整关闭重放，沿用runtime=None及原无代理创建／guest检查 |
| `platform_tasks.run()`运行后检查 | 持久化输入无条件要求创建前内存基线非空 | 开启仍要求真实基线；关闭要求明确off且基线为None，不添加一次假基线读取 |

修补前的平台命令生成器也会调用`single_config()`而拒绝关闭组；早期核对脚本只能从已接受的开启参数构造拟接入参数。本次回归改用修补后的真实命令生成器和原生解析器，确认原生参数仅变化`light_monitor`和`prettier6604_monitor_mode`，不再依赖拟接入参数证明成功。

可以直接复用的实现包括：平台在host-off时不构造`HostFileMonitor`，guest在monitor-off时不构造`RuntimeMonitor`；原工具报告能保留步骤／退出／时延，并将guest内存和host基线／峰值／增量标为未测。无需新建报告框架。

关闭组的`before_guest_counters=None`必须保留。统计组身份、I/O记账、无预启动池、同步成功和创建时间仍检查；不能为了通过持久化检查而在关闭组偷加内存采样。`--local-no-proxy-check`与新关闭模式不可组合，旧开启短检查行为保持。

## 固定两对四次，只有采样链不同

正式顺序固定为：**关闭→开启、开启→关闭**，共四次新guest、116个原动作。每次从准备开始建新统计组、新105文件输入、新私有服务、4 GiB／2 vCPU guest和8 GiB运行卷，避免复用旧进程或旧文件记账。不是在同一guest上中途开关，也不将已有单次开启结果插入新配对。

| 项目 | 两组共同保留 | 开启组 | 关闭组 |
| --- | --- | --- | --- |
| 原任务 | 固定29步、原退出／输出／补丁和原评测 | 相同 | 相同 |
| 本地输入及代理 | 同一固定备份、版本、本地元数据白名单和两端代理检查；缺项就停止 | 相同 | 相同 |
| 准备和回收 | 原导入／完整性检查／同步、默认回收，无额外预读、暂停或强制驻留 | 相同 | 相同 |
| 资源统计 | 从准备前建组，内存／I/O记账和池关闭 | 相同 | 相同 |
| host周期计数 | — | 0.1秒 | 不创建采样线程，无运行曲线或创建前内存基线 |
| guest采样链 | — | 0.1秒进程、原边界读取和采样阶段标记 | 不上传／启动采样器；边界函数为空操作 |
| PSS及精细扫描 | 两组均不请求 | 关闭 | 关闭 |
| 结束后输入核对 | 隔离运行及自有资源清理后、输入删除前，对105个唯一文件做一次mincore及前后file核对 | 相同 | 相同 |
| 资源边界及收尾 | 实际写文件、只读根、固定卷、自有清理与失败保留 | 相同 | 相同 |

关闭的是运行时采样链，不是内存记账机制或所有内存查询。关闭组的guest内存和host运行峰值未测；共同的结束后输入驻留仍是一次真实观测，单列阶段和成本。现有报告已能在工具报告之后附加持久化输入收据；继续禁止旧的全文件收尾驻留扫描，不将它与这次输入查询混为一项。

主要对比工具累计、冻结重放和控制程序整轮；组内流程及组外准备作为上下文。每对报告`开启−关闭`秒和`(开启／关闭−1)×100%`，正负都保留，两对分别列出，不承诺两对能确定稳定总体减速率。控制程序减去冷创建调用的剩余时间仍包含准备、执行、评测及清理，不能当纯采样时间；慢创建或慢评测不剔除、不替补。

第一轮正式关闭组同时验证新路径，通过后做剩余三次，不再加一次仅创建验证。四次均须满足：

- 原29步顺序、退出及关键输出不变，第2步缺rg的127保留，最终补丁及负向／修复后独立检查通过。
- 原最终32组／66项通过，官方仍1组／2项失败且签名与参考一致；输入／镜像／后端版本及无代理证据对应。
- 开启组真实覆盖任务且采集器已回收；关闭组没有周期数据、guest边界数据行、运行内存基线或假图。原表头文件和空通用目录可保留，不把它们当残余采样。
- 两组都有同阶段的105唯一输入驻留核对、查询成本与成功后输入释放；缺检查或查询失败不记通过。
- 原实际写边界、只读根、固定卷、源服务状态恢复及全部自有清理有证据。

实际任务或平台失败就保留首个现场并停止批次；检查器失败先用原结果离线修正，不因检查器失败重跑成功任务。不为缩小百分比自行增加轮数。

## 本阶段结束；推广前先离线核对

离线接入及两对四次已完成，停止追加Prettier轮次。若要覆盖另两个标准任务，下一步建议只离线核对Sphinx／Xarray关闭入口和结束后输入查询能否复用，保持各自原退出政策、独立检查和评测，再确定单任务最小开关范围。不直接复制Prettier开销数字，不自动实现或实跑。

Prettier每次实际运行沿用准备前磁盘严格>54 GiB、MemAvailable>64 GiB；20 GiB来源、8 GiB输入预算，来源释放后分配8 GiB运行卷前严格>34 GiB，原运行中20 GiB停止线和余量、单写入锁、实际超时及失败保留不变。本批未删除旧资料；以后运行仍须重查实际资源，不将本批空间作为未来保证。
