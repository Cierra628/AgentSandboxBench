# host驻留查询开关：离线核对（2026-10-26）

**核对时的入口尚无P0／P1独立开关；后续[实现和一对真实验证](HOST_QUERY_CONTROL.md)已完成。** 本页保留实现前的源码依据：该次仅核对源码、保存结果和参数拒绝路径，没有修改运行代码、启动服务或沙箱，也没有执行新的驻留查询。

建议保留guest及host周期采样、准备和文件身份检查，仅关闭两个阶段的驻留查询。不要复用现有`--host-sampling off`，也不要通过移除整个文件观察器来实现关闭。

## 现有入口为什么不能直接用

实际入口为`run-host-file-monitor.sh → run_host_file_workflow.py → run_host_full_rootfs.py group → validate_isolated_agentenv.py → run_prettier6604_grpo.py → FullRootfsControl`。

- `run_host_file_workflow.py:38–39`拒绝在完整副本组使用`--host-sampling off`；`validate_isolated_agentenv.py:205–207`还有第二层限制。以不存在的配置及daemon路径验证，参数解析先返回2，尚未读取配置或调用服务。此开关原本用于其他实验，不能将它改成“两次查询开关”。
- `run_host_full_rootfs.py:66`始终启动host周期计数线程，并关闭PSS。新对照两组均须保留这个线程；关闭它会同时改变周期采样成本。
- `FullRootfsControl.before()`核对准备文件清单，`after()`核对七个VMM实际引用、层顺序、共享使用者及daemon分配记录，并在查询后复查身份。删除整个观察器会删掉这些正确性证据。
- `run-host-full-rootfs.sh`的原`pair`是共享／独立副本比较，不是查询开启／关闭比较。新对照应两次都用`shared`，不改变原共享／副本入口。

相关实现：[外层入口](../../scripts/run_host_file_workflow.py)、[完整组执行](../../scripts/run_host_full_rootfs.py)、[文件观察器](../../scripts/host_full_rootfs_control.py)。

## 两次查询所在的时间范围已经确认

核对时保存的`run_prettier6604_grpo.py:825–871`按下列顺序执行：

1. P0：准备文件清单完成后、创建guest之前查询驻留。
2. 记录创建至全部分支检查的计时起点，执行七条原路径。
3. P1：全部原动作和结果下载结束后，核对实际文件清单并查询驻留。
4. 执行原结果及官方检查，记录该窗口终点，然后收尾。

| 计时量 | 包含P0 | 包含P1 |
| --- | --- | --- |
| 原工具累计及原动作／下载窗口 | 否 | 否 |
| 创建guest前至全部分支检查结束 | 否 | 是 |
| 控制程序整轮 | 是 | 是 |

因此，对照主指标应保留**控制程序整轮**，同时记录P0／P1各自的直接成本。不能只比较工具累计来估计查询成本，也不能将两个查询耗时都从创建至检查窗口中扣除。原有计时起止不移动，额外阶段计时只用于解释差值。

## 最小改动应保留什么

建议新增独立参数，例如外层`--rootfs-residency on|off`，传到后端时使用`--host-full-rootfs-residency on|off`。默认`on`，第一版仅允许在显式`shared`完整GRPO中关闭；旧共享／独立副本和BPO默认路径保持。

| 修改位置 | 需要完成的事 |
| --- | --- |
| `run_host_file_workflow.py` | 解析专用参数，只传给完整组，不改变`ASB_HOST_FILE_SAMPLING` |
| `run_host_full_rootfs.py` | 组入口和`member_command`传参；仍启动相同host计数，关闭组不进入共享收益计算 |
| `validate_isolated_agentenv.py` | 在预检查及实际任务参数两次重建时均保留选择；原导入、同步、cgroup、daemon和48 GiB卷不变 |
| `run_prettier6604_grpo.py` | 向观察器传递选择并保存；不改变原任务、guest采样、官方检查或计时边界 |
| `host_full_rootfs_control.py`、`host_private_files.py` | 仅按选择跳过`mincore_file`；保留对象集合、身份检查、首尾计数、实际使用者和前后复查。原`query_objects`默认行为保留 |
| `report_task_overview.py`及上层结果检查 | 区分“身份核对通过但未测驻留”和实际观测；原路径仍必须取得完整观测 |

关闭组的P0／P1须明确为`NOT_MEASURED`，`resident_bytes=None`，保留实际执行的元数据核对成本，不能伪造0字节或0查询开销。外层观察器可用独立的`VALIDATED`状态表示文件身份核对通过，但接受它必须同时满足显式关闭参数和完整身份检查；`FAIL`仍拒绝成功。现有共享收益汇总继续只接受实际`OBSERVED`结果，不接收关闭查询组。

目前`run_prettier6604_grpo.py`会保存文件观察器的失败并继续原结果检查；`validate_isolated_agentenv.py:1121`、组执行和报告层再要求`OBSERVED`。新增关闭状态时不能将这些检查一概放宽成“非空就通过”，否则会把真正的测量失败也当成功。
