## 已关闭原描述符，不等于后备对象无法访问

当前采集器只遍历目标进程的`/proc/<pid>/fd`，没有匹配描述符就把已删除对象的完整元数据保留未知。最新两组有2／4个此类对象；它们仍有映射，映射地址和身份已保存。因此可以尝试另一个入口：

```text
目标PID、启动身份和实际映射范围
→ /proc/<pid>/map_files/<start>-<end>
→ O_PATH引用，核对设备号、inode、普通文件类型和TMPFS后备
→ 从该引用只读重新打开，复核身份
→ cachestat(off=0, len=0, flags=0)
→ 再核对目标映射及PID身份，关闭全部引用
```

这里的TMPFS是Linux普通共享内存使用的文件系统类型，不把名字中的`/dev/zero`当成要重新打开的字符设备。

源码依据：

- `fs/proc/base.c:2253–2289`的`map_files_get_link`按精确地址范围查找VMA（进程的一段虚拟内存映射），直接从`vma->vm_file`取得文件路径并增加路径引用；没有要求目标进程仍有对应fd。
- `base.c:2300–2317`及`include/linux/capability.h:200–210`要求初始用户命名空间中的CAP_CHECKPOINT_RESTORE或CAP_SYS_ADMIN；`base.c:1799–1820`另做目标访问权限检查。实际映射消失、PID变化、权限失败都应保留未知，不更改权限或回退为零。
- `fs/open.c:904–925`中O_PATH只建立身份引用，不调用普通文件的open；只允许后续已核实的普通TMPFS文件重新以O_RDONLY打开，不向字符设备或未知后备扩展。
- `mm/shmem.c:2990–2994`的普通shmem打开只设置模式并调用`generic_file_open`；`fs/open.c:1607–1613`只检查大文件兼容条件。这条打开路径不读取文件数据。

打开的引用可能暂时延长已删除对象的存活时间，必须在一次有限时长查询后立即关闭；它不是给数据页加锁或禁止回收。身份核对期间发生变化时，本次查询不能用于归并对象。相同后备对象的多段映射仅计一次。

### O_PATH不能直接传给cachestat

`mm/filemap.c:4707–4746`使用普通`fdget`，`include/linux/file.h:82–86`及`fs/file.c:1174–1212`表明它过滤FMODE_PATH。直接把O_PATH传入会得到EBADF，而不是缓存为零。

因此需要先安全核对对象类型，再取得O_RDONLY句柄。这个步骤只适用于上面核实的普通TMPFS对象；原来的ublkc O_PATH身份查询保持，不改变其设备打开方式。

## cachestat能补的是整个后备缓存观察，不是所有者

`include/uapi/linux/mman.h:46–58`只定义缓存、脏页、写回和移出等五个计数，没有PFN（物理页编号）、文件页索引列表或内存组字段。`mm/filemap.c:4563–4660、4707–4746`直接遍历文件缓存索引表并返回计数，不调用读取文件或建立数据页映射的路径。

| 查询情况 | 可以报告的量或状态 |
| --- | --- |
| 普通TMPFS，查询成功，`nr_evicted=0` | `nr_cache×实际基本页大小`，标为整个后备缓存的顺序观察量；包含原进程未映射的缓存，不是映射PSS |
| 普通TMPFS，`nr_evicted>0` | 缓存计数照实保存，完整物理驻留保留部分未知；交换条目可能对应仍在RAM的交换缓存，不能按零处理 |
| hugetlb后备 | 源码返回EOPNOTSUPP，本路径未覆盖，继续使用未知状态 |
| 访问失败、对象变化或系统调用不可用 | 保存实际错误和未知量，不用文件大小、映射长度或零代替 |

`off=0,len=0`在本地源码中令末端为ULONG_MAX，遍历整个缓存索引表，不按映射长度截断。它也不以`st_size`作为缓存索引遍历上界；不能将一小段映射或逻辑文件大小直接解释成整个对象的驻留量上限。

有三个使用条件：

1. **交换条件。** `xa_is_value`分支先把页数记入nr_evicted；对shmem会检查交换相关记录，但不返回交换缓存中的物理驻留计数。现有内核启用了SWAP，不能跳过这一分支。即使nr_evicted为零，结果仍只是遍历过程的观察，不提供原子时刻总量。
2. **与mincore含义有差别。** `mm/mincore.c:59–146`还能查询shmem交换缓存，并检查页是否uptodate（内容是否准备好可读）；cachestat的nr_cache主要按缓存索引条目计数。两者不能无条件要求逐字节一致，更不能把不一致立即归为采集错误。
3. **有测量成本。** cachestat会调用`mem_cgroup_flush_stats_ratelimited(NULL)`，可能刷新内存组统计并在遍历中让出CPU；不改变数据内容，也没有预读，但不是零开销。只建议任务后的显式明细查询，不增加到默认0.1秒循环中。

实际权限还由`can_do_cachestat`检查，失败会返回EPERM。后备对象缓存可能已进入cgroup的file／shmem及PSS；新计数单列，不直接加入current。该接口不补约1.7 GiB归档的页归属，也不改变旧实验的未知字段。

## 旧缓存页归属：现成接口仍接不上完整链条

| 接口 | 已有能力 | 缺少的部分 |
| --- | --- | --- |
| mincore／cachestat | 文件或后备缓存的驻留状态／计数 | 不返回页的记账组，cachestat也不返回PFN |
| `/proc/<pid>/pagemap` | 已有用户页表映射的PFN，权限满足时可读 | `fs/proc/task_mmu.c:1894–1936`对没有实际页表映射的位置输出非present记录；新建PROT_NONE映射不会自动给出缓存PFN |
| `/proc/kpagecgroup` | 按已知PFN查询页记账组 | `fs/proc/page.c:64–106`按PFN寻页，不提供“文件索引→缓存页”的枚举 |
| 当前加入／移出事件探针 | 事件时的实际页记账组 | 探针开始前的已有页不发加入事件，过滤范围也不是所有组外文件；不能倒推出旧初始归属 |

`mm/memcontrol.c:263–291`还明确：`page_cgroup_ino`返回最近仍在线的记账组祖先，且结果本身存在并发变化；不能把它当作永久页身份或原分配组。原事件探针的memcg指针解析与这个用户接口也不是完全相同的归属口径，需要分别处理组的存活期。

不能通过“摸一下页面以建立PFN”补这条链：缺页时可能读取负载或把已移出的页重新带回内存，违反当前测量条件。也不建议全机PFN扫描、为此暂停guest或加载新内核模块。

内核内部存在可用于进一步研究的路径：`mm/filemap.c:2220–2240`的`filemap_get_folios`能够遍历已有缓存并取得临时folio引用（folio是内核管理一页或多页内存的单位）。但它不是现成用户态接口，取得普通引用也不自动稳定memcg归属；`include/linux/memcontrol.h:466–503`另外列出归属稳定条件。新增专用内核查询还需要处理并发移出、共享内存交换条目、页归属和查询时间，这超出现有轻量方案的最小改动。

**本次没有找到能够直接拼接、且完整覆盖任意旧未映射缓存页归属的现成接口。不建议把这条较重路径作为当前轻量成果交付的前提。** 指定对象驻留、组内记账增量继续可用，整体物理量和guest Cached对应物理集合仍未测得。
