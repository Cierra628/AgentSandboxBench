## 编译结果暴露了首次创建汇总键的并发风险

本机bpftrace版本为0.20.2。此前针对本轮同一候选代码保存的编译中间结果显示：`count()`和`sum()`先查表，键不存在时，用标志1，即`BPF_NOEXIST`插入；插入返回值没有检查，也没有在`EEXIST`后重新查表并累计。

如果两个CPU同时首次遇到同一个新分组键，两次查表都可能得到“不存在”；其中一次创建成功，另一次因键已存在而失败，后者的更新会被跳过。这是编译结果中可以确认的机制风险，与本轮差1次相容；本轮没有保存插入返回值，**尚未证明这就是本次差额的原因**。独立总计也使用同类计数操作，修补时应同时处理总计和分组表，不能只修改某个数字让两者相等。

依据为`.artifacts/host-file-device-coverage-offline-20261020/compile.log`中`lookup_failure155`至`lookup_merge156`，摘录保存为本轮核对目录的`counter-insertion-ir.txt`。标志及`EEXIST`含义对应本机源码`/home/yxli/linux-6.19.9-ioctl/include/uapi/linux/bpf.h:189–220,1373`。没有为此挂载额外探针或启动额外负载。
