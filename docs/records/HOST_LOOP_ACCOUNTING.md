# loop后备缓存的I/O记账对照（2026-10-20）

**已确认：在本次层级结构中，仅开启内存记账会把新增64 MiB的loop后备缓存记到测量组外；同时开启I/O记账后，这部分进入测量组。** host测量入口已补`IOAccounting=yes`；后续[真实沙箱大卷短恢复](HOST_FILE_IO_RESTORE.md)已完成，清单26.622 GiB、file约26.973 GiB，没有再检出此前GiB级不足。本页的小loop初始化差额仍保留。

本次只运行一组关闭／开启I/O记账的对照，没有启动沙箱、AgentENV服务或任务。两组的文件驻留增量均为128 MiB，改变的是记账归属，不是物理缓存减少了64 MiB。

## 怎样构造对照

loop设备是将一个普通文件当作磁盘使用的Linux设备。每组创建独立的128 MiB逻辑镜像，格式化为ext4并挂载，在其中写一个64 MiB合成文件。只操作本次文件，不读取任务文件、不清理host全局缓存、不锁页。

两组都在创建镜像之前建立新的统计组，层级与host测量入口一致：

```text
本次独有的外层组
└─ 当前测量组
   └─ 实验进程及其子进程
```

两组都开启`MemoryAccounting=yes`；第一组`IOAccounting=no`，第二组为`yes`，不设置I/O限速。记录实际控制器文件及systemd属性，不只检查传入参数。第一组测量组及进程组没有`io.stat`；第二组两者都有，外层组向下启用了io控制器。

镜像初始化完成后先同步自有文件系统和镜像，再固定等待2.2秒记录基线；写入合成文件并同步后，分别立即查询、再等待同样2.2秒查询。用已有`mmap(PROT_NONE)`及mincore查镜像和内部文件驻留，不访问文件内容。固定等待用于观察统计更新，两组相同，没有等待中的后端请求或沙箱。

## 新写入的记账差额得到修正

下表均为最后一次查询相对初始化基线的增量，单位MiB：

| 项目 | 关闭I/O记账 | 开启I/O记账 |
| --- | ---: | ---: |
| 镜像与内部文件的mincore驻留增量 | 128.000 | 128.000 |
| 测量组file增量 | 64.043 | 128.016 |
| 外层组独有的file增量 | **64.000** | **0.000** |
| 驻留增量−测量组file增量 | **63.957** | **−0.016** |

写入64 MiB文件产生了两层不同缓存：内部文件自身的64 MiB，以及后备镜像对应的64 MiB，所以总驻留增量为128 MiB。关闭I/O记账时，内部文件缓存进入当前组，后备镜像缓存落到本次外层组；开启后，两部分都进入当前组。开启组的file增量比清单多16 KiB；file也包含清单之外的日志等文件，原始差值照实保留。

外层计数本身包含内层，因此“外层独有增量”按两者file增量之差计算，不把外层和内层直接相加。两个外层组均为本次独有，没有混入其他任务。

这个结果与实际host `6.19.9+`构建源码一致：`drivers/block/loop.c:1878–1885`从请求的blkcg（I/O统计组）取得memcg（内存统计组），`1914–1924`在后备文件I/O期间使用它。内存组与I/O组的层级不一致时，loop页不一定记在最初写文件进程所在的内存组。源码摘录沿用`.artifacts/host-file-restore-validation-20261020/host-loop-source.txt`。

## 初始化差额仍保留，旧大卷不追溯修正

| 全量检查，不减基线 | 关闭I/O记账 | 开启I/O记账 |
| --- | ---: | ---: |
| 写入合成文件前，mincore超过file | 1.105 MiB | 1.141 MiB |
| 写入并等待后，mincore超过file | 65.063 MiB | **1.125 MiB** |

开启组剩余差额在合成负载开始前就已经出现，没有随新增64 MiB数据扩大。初始化阶段的页归属及统计差异尚未细分；这部分不记零，也不将1.125 MiB直接作为大卷的修正系数。新增写入的对照通过，不等于全量记账已经完全覆盖。

此前真实恢复实验的4.232 GiB差额继续保留为原观测。本次确认了一个会造成大量组外记账的机制。后续新设置的大卷复验已未检出不足，旧大卷逐页贡献没有追溯核对；旧报告及`SHORTFALL_REQUIRES_RESOLUTION`状态不变，仍不计算共享节省比例。

## 接入host测量入口的改动

- `run_host_file_workflow.py`现在同时设置`MemoryAccounting=yes`与`IOAccounting=yes`，只影响新建的host测量组，不修改原服务或普通guest轻量配置。
