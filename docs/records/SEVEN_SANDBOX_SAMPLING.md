## 补齐证据后怎样评分

- 每点把查询前有效记录按 `guest_pfn` 排序，等概率、不放回抽 `n = ceil(N × 比例)` 条。拟用 Python 3.12 的 `random.Random(20261118 + 100 × 点号 + 整数百分比)` 分别初始化每点每档的随机流，各连续执行 200 次 `sample(range(N), n)`。各次抽中的候选其物理观测均来自本点，基线的前后身份和驻留校验随样保留。主表所列是计划抽数，本轮完成 0 次重放。
- 单条 guest 记录可对应多个有效物理副本，先用该记录各来源 **host PFN 的集合**合并。同一物理 PFN 若被多条候选命中，样本中全局只计一次，但它的入样概率更高。若同一 PFN 可由全表中 `m` 条候选中的任一条独立确认，`π = 1 − C(N−m,n)/C(N,n)`。在所有计入的 PFN 都有正入样概率且遵守原确认规则时，可用 Horvitz–Thompson 估计 `T̂ = Σ(1/π)`，对抽中并确认的不同 PFN 求和。直接用 `样本 PFN 并集 × N/n` 会把有多个独立命中的 PFN 按过大的权重计入。
- provider 同一 PFN 可能要联查多个来源偏移及其候选才能确认整页，漏抽状态冲突的别名也可能造成误归属。若恰好要求 `k` 条指定候选全部入样，`π = C(N−k,n−k)/C(N,n)`，`n < k` 时为零。实际入样概率还需考虑其他可确认同一 PFN 的路径及其重叠。缺少任一必要验证时归属为 `UNKNOWN`，也要检查设计是否存在 `π = 0` 的全量确认页。依赖全量候选与 PFN 的反向关系或事后 provider 归属的去偏，**可用于离线分析，不能直接部署**。部署上述估计量需要正且可在现场取得的入样概率，例如先通过查询前可识别的关系设计必查对象，并保持跨来源去重。
- 对每次估计与该点全量 `T` 比较，令 `e = (T̂ − T) / T`。报 `|e|` 中位数、`|e|` 的最近秩 P95（200 次中的第 190 小值）、`e` 的均值作为有符号偏差，以及最近秩 `P95(|T̂ − T|)/256` MiB。比例必须在五点分别满足 `P95(|e|) ≤ 5%`，并同时有依据地满足七路整轮 `< 1 s`。这里的 5% 衡量估计精度，原 `segments_v3` 规则继续适用。

复用原四来源口径时，同一 host PFN 无论出现在多少层或分支都只计一次。provider 保留按共享设备归属及批级去重，分支输出不可相加。原规则未确认的部分保持 `UNKNOWN`，包括只有 guest 容量、缺失 PFN 或缺失有效身份的记录。PSS 与 guest 缓存容量各自测量不同的量。

## 时间预算

`HANDOFF.md` 的约 9 µs 来自约 26 万个**已确认物理页**的工作量换算。阶段报告里点 1 的保留耗时 `336.388 ms / 37,514 ≈ 8.97 µs`，分子还包含四来源查询及归属。旧系数无从代表稀疏查询的边际代价。

主表将 9、12、16 µs／确认 PFN 等价量作为**可变部分的独立敏感性假设**。用每点全量行数及确认数把单位换成 `c × T/N` µs／候选，再算 `V(n) = c × T × n/N ÷ 1000` ms。这个工时换算假设两层查询工作量随候选数线性变化。表中的“两层实测均摊”来自两层完整查询墙钟除以候选行数，反映全量工作负载。三档模型将该假设的可变成本和实测阶段的保留成本相加，`n=N` 时也可能与原整点时间有差异。

只让直接后备和快照下层的首末四次物理查询随 `n` 缩放。阶段报告中两者之外的整点开销，扣除 provider 的首末物理查询调用后，全部保留为每分支 `F`。`F` 包含两次 guest 导出、解码、全部定位、三次 VMM `_bulk`、各分支归属（含用共享帧做匹配）和未分项时间。按基线代码，`_bulk` 目前全读 KVM 槽位，减少候选行不减少读入范围。证据包只有分组的定位和归属耗时，预算用全量组耗时作为保留成本。`P` 为单实例历史阶段报告中的 provider 首末两次完整调用，作为共享设备每轮一次的两帧采集的成本代理，包含槽元数据、页表和结果构造。七路仍各做匹配，但共享观测只计 `P` 一次。

设 `L = F + V(n)`。单实例为 `L + P`，七份同规模本地工作串行合计为 `7L + P`。七实例理想并发情景为 `max(L₁, …, L₇) + P`，这里七份取同一点负载，数值恰好等于这个单实例预算。实际整轮还受执行资源竞争、共享帧屏障、批级去重及读数留证影响。主表把它们在模型中的额外墙钟取零，给出理想情景，无法给出实际墙钟上界。例如点 0 的 25%／16 µs 档，`P≈196.7 ms`、`L≈268.9 ms`，若批级额外开销取零，本地阶段的有效耗时需低于该 `L` 的 2.99 倍才有机会满足整轮 1 秒。点 0 即使在 1%／9 µs 档，七份串行仍为 1.0564 秒。

线性假设尤其需要核对偏移的连续段。历史点 0 的两层各有 2,117 段，首末两次共 8,468 次 `mincore`。抽得更少但更分散时可能拆开原连续段，逐条候选均摊会改变。现有包缺完整偏移表，不能从总页数推算样本的实际分段数。历史首轮 10.264852 秒同时包含不随抽样比例缩放的工作和并发竞争，整轮墙钟不能按抽样比例缩放。

历史七路立即查询的首轮线程 CPU 合计为 16.116435 秒，`guest_before` 至 `guest_after` 的查询起点间距为 5.065–5.069 秒。guest 前表为 30,044–30,228 条，后表为 2,519–6,502 条，最后各分支确认 2,299–6,003 个 host PFN。另一次 60 轮实跑中，后 59 轮墙钟中位 1.269411 秒、56 轮超过 1 秒，六十轮的分支确认页数范围为 982–8,029。两次实跑的读数均不能校准五点抽样方案的七路墙钟。时间预算针对读窗，分支并发完成仍无法保证严格同刻。
