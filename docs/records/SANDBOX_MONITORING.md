复用`guest_memory_collector.py`的计数读取器，每个沙箱只运行一个100毫秒周期采样进程。工具通道可用并安装采集器后启动，覆盖准备、工具、等待、最终检查和测试，到删除实例前停止并导出。原逐工具周期采样改为保留工具前后的边界采样，冻结命令、顺序、退出码判定和工具计时边界不变。

记录实际sandbox_id、逻辑角色、采样会话、系统时间、单调时钟、阶段和步骤。单调时钟记录经过时间，避免只凭系统时钟变化判断采样间隔。checkpoint前停止并导出，恢复后用新实例ID和新会话启动；BPO/TVCache保存后也为继续运行的父实例重新启动。暂停期间无法读取guest指标，启动前和保存/恢复周围的空缺不插值。宿主机服务cgroup曲线单独保留。

`Cached`来自guest `/proc/meminfo`，是逻辑缓存计数，包含与Shmem重叠的部分，不是跨VM去重后的物理量。原始字段为KiB，图为MiB。非空闲内存为MemTotal−MemFree，峰值为采样观测最大值。guest、VMM和服务cgroup不得相加；服务cgroup合计不能替代各VM指标。采样器CPU时间与maxrss只描述采集器自身，不能当作沙箱CPU或私有内存。当前没有新增统一的沙箱CPU/I/O或各VMM PSS曲线。

## 使用和未验证项

上述任务通过`validate-isolated-storage.sh`成功运行后，在运行目录的`report/`自动生成`memory.svg/png`、`guest-<sandbox_id>.svg`、`runtime-metrics.json`和输入哈希。JSON保留原始控制器阶段耗时，完整任务报告保留原正确性检查。离线生成内存报告：

```bash
python3 scripts/report_sandbox_runtime.py <原始数据目录> <新的报告目录>
```

该报告只验证指标，明确列出source_run_status，不把原运行FAIL改成任务PASS。输出目录不能在原始目录内，也不覆盖已有报告。

短验证入口：`bash scripts/validate-runtime-monitor.sh`。固定16 GiB写卷，要求主机空闲超过42 GiB；先查空间，再准备有界RAM缓存，预算不足时在准备之前退出。本入口使用512 MiB小VM，只验证功能，不比较4096 MiB正式配置的性能，也不运行固定4 GiB布局的物理页探针。成功资源自动回收，失败卷保留。

尚未验证：新采样下BPO/TVCache父实例连续保存后的采样、七实例或其他任务的监控开销、逐VMM宿主机指标及CPU/I/O曲线、三完整任务的统一物理去重缓存量。三任务持续曲线、七实例GRPO和五对Sphinx开销已有本轮证据；严格Xarray仍FAIL，模型任务失败也未改变。暂停扫描仍属独立分析模式，不能当作无干扰日常采样。
