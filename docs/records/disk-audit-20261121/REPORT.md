# 根盘审计：优先迁移一份历史实验卷，不必停 Docker

**主要差额在 /home，不在 Docker。** root 从根挂载点读到 /home 实占 712.15 GiB，其中 yyxie 自己的目录约 292.8 GiB，其余用户合计约 419.4 GiB。Docker 全目录仅 29.91 GiB。最合适的腾空间对象是项目自己的 40 GiB 旧失败卷：迁到独立的 /data 后保持旧路径可读，预计根盘可用 **101.25 GiB**。相比之下，即使整个 Docker 目录移走，预计也只有 **91.16 GiB**，比门槛多 1.16 GiB。

## 1. 806G 用到哪里

## 5. 两条利用 /data 的路径

**方案 A（推荐）：只把上述 40 GiB 历史卷迁到 /data。** 不改 Docker、实验入口或卷的字节内容。目标在独立 ext4 上；先确认 /data 实际已挂载、可用容量足够，旧卷仍无打开者、无 loop。复制为保留权限、属主、时间戳的稀疏文件，逐字节比对，检查逻辑长度以及目标实际占用。从已测全零段看，需扫描 40 GiB 逻辑数据，目标非零部分至多约 6.98 GiB（另有元数据）。仅在校验通过后切换旧路径为指向新文件的链接并验证已有只读入口，再经授权释放旧副本；不动同级回执、其他卷或种子。今后 /data 未挂载时应报缺失，不得在空挂载点下写入。**服务停机 0 分钟**；复制校验需维护时间，但只暂停这个历史卷的使用。回滚：释放旧副本前直接换回；之后要先确保根盘有足够空间，从 /data 复制还原并比对，再换回常规文件。旧副本释放后，按审计时可用量预计 **101.25 GiB**。仅复制、不释放旧块则不增加根盘空间。

**方案 B：全量迁移 Docker data-root 到 /data/docker。** 需该机 Docker 所有者共同授权。保留现有 registry-mirrors，只增加 data-root；确保 Docker 单元依赖 /data 已挂载，否则拒绝启动。记录容器原启停状态、镜像/卷清单、挂载和网络；在维护窗停止 Docker 及 socket 激活，确认无写入或残余挂载。用支持硬链接、稀疏文件、所有者、ACL、扩展属性及特殊文件的复制方式传输约 **29.91 GiB 实际分配**，不可把 overlay2 逐层当普通目录随意复制；容器绑定的宿主路径和独立 /var/lib/containerd 不在迁移范围。校验副本，再用新配置启动、核对 DockerRootDir、86 个镜像、2 个停止容器、4 个卷和绑定路径，勿擅启实验源容器。验收后才能释放根盘旧树。**计划停机约 10–30 分钟，非实测**：按有效 50–150 MiB/s，一遍约 3.4–10.2 分钟，另加校验、碎文件及启停，慢盘可能更久。回滚：未释放旧树前停 daemon 和 socket、回退配置并从旧目录启动；新根已有写入时先停写并同步新增状态。旧树释放后须有独立可读副本和回迁空间，不能只改配置。根盘预计 **91.16 GiB**，浮动很容易吃掉余量。

**为什么门槛会或不会通过。** scripts/isolated_storage.py 的 available(path) 取 statvfs(path) 的 f_bavail × f_frsize；七支入口传入由脚本真实路径确定的仓库 ROOT，不是 DockerRootDir。当前 ROOT 位于根分区。严格门槛是 64 + 20 + 6 = **90 GiB**。A/B 都靠释放根盘旧块过线，不是因为预算改读 /data；保留两份时均不过线。B 只有实际释放超过当前缺口才过线；若迁后仍不足，优先用 A，或把实验工作区和实际写卷位置一起放到 /data 并验证各写入路径与各盘保留预算。**仅将 .artifacts 链到 /data、而 ROOT 不动，现有检查仍看根盘**。任何方案完成后以原入口同一 statvfs 重新判定，不用预计值代替放行。
