# N=10：在受控内存压力下核对共享收益

本次固定Prettier #6604，十个guest执行同一29动作路径，A共享无压力、B独立无压力、C共享有压力、D独立有压力各一次。A／B新跑，不复用旧批：宿主缓存、MemAvailable及其他负载已变化。

问题是：准备缓存是否在压力下回收，以及独立组是否因此增加任务延迟或文件页重新进入缓存的次数。执行阶段memory.current和指定文件mincore分别计算差距压缩比，不拼成总物理量；不以一次记账差证明最大部署数量。

## 只在创建guest前分配，运行中固定持有

复制／同步和副本检查完成后，协调程序在P0及任何guest创建前请求加压。外层控制程序在独立`asbpressure.slice`启动单个匿名分配进程，每128 MiB映射一块，每页写一次，不锁页、不持续触碰。每块后读取MemAvailable，达到MemTotal约20%后停止增加，任务及收尾完成后才释放。压力进程的PID、启动身份及cgroup由内外两侧核对，拒绝位于实验cgroup内部。

固定分配后不追踪目标动态增减；若实际可用内存偏离20%，按采样实值报告。分配最多为总内存80%，压力服务自身MemoryMax另留2 GiB开销，OOMScoreAdjust=1000优先释放本进程，最长1800秒自动停止。独立恢复方式：从`systemctl list-units 'asbpressure-*'`找到本次单元，再执行`systemctl stop <单元名>`；实际服务路径也在压力进程cgroup记录中。

宿主MemAvailable低于32 GiB、压力进程提前退出或超时会中止条件，先释放自有压力进程并正常清理自有服务。这是失败收尾，不作为有效的中途调整或成功压力点。原分卷前>106 GiB磁盘／>64 GiB MemAvailable、运行中20 GiB磁盘保护保持。

## 普通采样不变，只显式增加所需计数

实验组0.1秒读取current、原file／anon／kernel／shmem／file_dirty／file_writeback，并显式追加workingset_refault_file、workingset_activate_file。宿主另以0.1秒读取MemAvailable／SwapFree、pgscan／pgsteal各项及压力进程RSS、RssAnon、VmSwap。不读取PSS，不周期查询mincore，不广泛扫描文件。运行中的回收策略不变。

准备／同步前后不新增缓存操作；原精确文件P0冷起点及一次P1保留。加压位于准备之后，因此全流程峰值可能出现在加压前；差距压缩比的current使用执行阶段峰值。加压前后和P0的组current另列，便于判断准备缓存是否已经回收。refault是缓存重新进入计数，不等于物理盘读取字节。

工具累计、动作及下载窗口、创建跨度和协调程序整轮沿用原定义。协调程序整轮不含此前输入复制，含新增加压等待；宿主观察跨度另覆盖组导入至压力释放。逐guest跨度使用原边界timestamp_ns中首次before至末次after，包含间隔与边界记录，不作为纯工具累计。超过本组或对应无压力组中位数1.5倍只加描述性标记，不剔除。

[完整报告、机器摘要、40个guest跨度表和17张图](../../results/host-density-pressure-20261102/REPORT.md)已交付。四组共40guest／1160动作，无失败重跑；原官方每实例0通过2失败、身份、19／190个目标文件、独立副本、P0=0／P1、任务期间压力归属和收尾通过。

执行阶段current峰值：A共享无压力22846.684、B独立无压力62856.734、C共享有压力8493.727、D独立有压力25898.824 MiB。差距从40010.051降至17405.098 MiB，保留43.50%，即缩小56.50%；指定文件驻留差距保留93.45%。D准备current从98118.199降至25639.902 MiB，确认原差距有大量可回收的准备缓存。

独立相对共享的动作／下载窗口增量从1.663秒（8.06%）变成5.866秒（29.30%），相对增量再多4.203秒。工具累计对应多9.334→45.115秒，差值再多35.781秒。此次记账差缩小22.075 GiB，对应任务窗口相对延迟多0.190404秒/GiB；这是本轮对照的描述性换算，不作跨N预测。D执行窗口refault增量63715，无压力两组及C均为0；该计数不等于物理盘I/O字节或耗时。

压力进程实际匿名驻留最大C为373.250、D为372.375 GiB，分别在独立asbpressure服务中。准备后的MemAvailable降至100.594／100.612 GiB，任务窗口中点为93.572／95.175 GiB（总量18.59%／18.91%）；分配后固定持有，不中途调节。SwapTotal／SwapFree及进程VmSwap均为0。释放后MemAvailable回到473.786／473.184 GiB。

本次支持“回收可以压缩部分记账差距，但独立组相对共享更慢”；共享在该压力点仍更少记账且任务更快。旧无压力current差不能直接换算为不可回收的部署密度收益；最大能多放几个guest仍需固定延迟预算另测。历史数值不改写。
