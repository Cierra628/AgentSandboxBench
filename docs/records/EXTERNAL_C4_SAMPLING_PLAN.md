# C4采样开销对照：建议两对、四次独立运行

后续已获用户同意，完成入口修补、离线检查及固定四次验证；见[实际对照结果](EXTERNAL_C4_SAMPLING_CONTROLS.md)。下文保留当时确定的范围，不替换其原始数据。

## 先测整个轻量方案，不拆更多组合

推荐最小范围：**关闭→开启；开启→关闭，共两对、四次**。每次新建一个2 vCPU／8192 MiB guest，完整执行原36步，共144步。每次使用新的私有服务、统计组及32 GiB运行卷，串行执行；上一轮清理成功后才创建下一轮。

两对的执行先后相反，用于减少自然缓存和运行顺序的偏向。只测两个条件：host与guest的内存采样一起开启，或一起关闭。它回答“完整轻量测量增加多少耗时”，不单独分出host、guest各自造成的减速；本阶段不增加四组合矩阵。

关闭的只是两端内存采样。两组均保留相同的逐步计时、原输出下载、功能验收、cgroup资源记账及磁盘保护，不将关闭组描述为完全没有测量代码。

本次完成的是离线范围与入口核对，没有修改运行代码、启动服务／guest、联网或查询数据页驻留。四次实跑在用户确认这个范围、完成最小入口修补后执行。

C4主要处理镜像内9898文件样本，适合比较本地工具执行。原第5／29步虽然调用`uv sync`，但原`pyproject.toml`为`dependencies=[]`；保存的真实输出都只解析了本地项目，没有下载输出。比Cython多次Git／pip安装少一项明显的动态依赖来源，但首次镜像获取仍会联网，不能视为整轮无网络。

## 当前入口不能直接关闭采样

源码核对发现四处约束：

1. `run_host_external_workload.py`的`main()`固定传`ASB_HOST_FILE_SAMPLING=on`；仅在外部设置环境变量为off会被覆盖。
2. 同脚本的`grouped()`无条件创建`HostFileMonitor`，并在成功后要求host及guest内存报告。
3. `run_external_workload.py`无条件创建、启动和停止`RuntimeMonitor`；仅关host线程仍会留下guest采样。
4. `validate_isolated_agentenv.py`要求外部任务带light选项，其现有host关闭条件只适用于其他已核对的任务模式。直接删掉`--light-monitor`或强传off均被现有校验拒绝。

因此不能用当前命令简单换一个环境变量就宣称“关闭组”。旧Prettier／GRPO开关对照的计时及报告方法可参考，但它们的任务身份和验收入口不能套到C4。

## 最小改动只覆盖C4的新关闭模式

建议在以下三个现有脚本新增显式采样选项，默认仍为开启：

- **外层入口**：关闭时不创建host采样线程，向systemd和内层传递一致的off状态；保留相同新统计组、服务和资源记账。关闭组不调用内存绘图，不伪造内存峰值或零CPU。
- **隔离验证入口**：只为明确指定的C4关闭模式放行，转发同一选项；保留身份、I/O记账和创建前检查，以及原卷边界／清理。不得放宽其他任务的既有条件。
- **guest控制程序**：关闭时不创建`RuntimeMonitor`，不复制／上传采样程序，也不执行其就绪、停止、采样下载等调用。两组的45份业务输入、计时程序、生成的业务runner及全部验收不变。

用一个小型C4对照脚本复用既有服务生命周期，顺序运行上述四次并汇总保存结果，不新增另一套沙箱后端。必要离线检查覆盖默认开启不变、仅C4可关闭、两端状态一致、关闭组无采样调用／样本、开启组完整采集，以及各失败阶段的清理。

关闭组收据应明确“内存未测量”，不存在内存曲线；不能记为0 MiB。计时和任务结果两种模式都必须完整。

## 主要比较工具耗时，冷创建单列

每对分别计算：

`变化率 = (开启采样用时 / 关闭采样用时 - 1) × 100%`

主要指标为guest原36步的工具累计用时。另列整段CLI、冷创建和控制程序整轮，避免315秒级镜像获取把45秒级业务差异掩盖。冷创建是新guest的创建请求，本轮不保证host缓存为空，也不主动清理host或guest缓存。

从保存事件再列采样阻塞控制调用累计，排除与业务重叠的`monitor-collect-*`存活墙钟；开启组同时保留host线程CPU、guest进程CPU、实际样本数及最大采样间隔。CPU和墙钟分开报告，不相互替代。

交付两对的原始变化、两种模式的平均用时，以及配对变化中位数和范围。负值保留；不事后剔除慢的一轮、不为了得到更小百分比追加轮数。两对用于本次最小验证，不给一般场景的统计误差上界。

## 资源和完成条件不变

四次**串行使用32 GiB卷，不同时分配四份**。每次分配前严格>58 GiB可用磁盘、MemAvailable>64 GiB；本次离线核对时约63.092 GiB可用，后续实跑仍重查。默认回收不改，无PSS、mincore、冻结、业务预读或强制驻留。

C4原预算保持：整段业务240秒、控制程序720秒、隔离等待1050秒、外层1200秒。旧单轮控制程序约6分钟只作耗时量级参考；超时上限不是预计耗时或主机独占窗口。

第一轮正式关闭组就是新路径的必要验证，不再另加相近短测；通过后完成剩余三次。每轮需同时满足：

- 原36步和预期非零退出保持：第3步=2，11／12／16／18步=1，其余0，时间戳有效。
- 9898文件样本、33／34步内容往返／目录结构及分片约束、原语法检查通过。保留原动态输出，不用旧整段日志逐字相等代替功能验收。
- 关闭组确实没有两端内存采样；开启组0.1秒样本覆盖完整业务，采样器正常退出并回收。
- 卷边界、guest／私有服务及成功卷清理通过，源服务结束恢复停止；四轮证据和比较报告完整。

实际任务／平台失败先保留现场并定位；检查器失败先利用原始结果离线修补，不重跑已成功任务。新失败卷仍需定向删除授权，不能因后续轮次空间不足自行删除。
