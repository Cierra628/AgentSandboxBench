## 最小候选只在一次批量查询内复用

现有`scripts/snapshot_cache_residency.py:220–238`在每个区段创建一个`ctypes.c_ubyte`数组，每页对应一个返回字节。候选只做两处局部调整：在`scan_started`之后将`vector`置为`None`、容量置为0；随后仅在当前跨度超过容量时新建数组，并在分配成功后更新容量。

```python
if length > capacity:
    vector = (ctypes.c_ubyte*length)()
    capacity = length
assert self.libc.mincore(self.address+start*PAGE, length*PAGE, vector) == 0
residency.update((offset, vector[offset-start]) for offset in map(int, run))
```

调用长度仍是当前区段跨度，不是保留数组的容量。较短请求只使用本次写入的有效前缀；更长数组的旧尾部不读取、不清零，也不计入结果。中间空隙页仍可被查询，但只有原请求偏移进入驻留字典。返回字节完整保留，不只保存最低驻留位。

容量不跨查询保留，没有新增对象字段、配置或线程。默认逐项入口仍逐段创建数组，不增加时钟读取或批量接口前提。查询号发布、所有mincore调用、一次整表读取、筛选和结果还原顺序不变；分配或接口失败直接中止，不追加成功统计或计时，也不回退。

离线脚本从保存的实际查询源码提取整个函数，仅替换以上两处；保存副本与当前在线源码逐字一致。候选全文件与在线文件的其余部分一致，包括原`BatchEntries`和物理归属判定。真实接口的既有条件复用[内核源码核查](PROVIDER_MINCORE_MERGE_REVIEW.md)，本轮未另做真实调用验证。
