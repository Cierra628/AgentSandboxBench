历史宿主机每秒采样的监控证据覆盖原始 runner 的控制器工具调用：AgentENV 关闭 DAMON（guest 的内存回收机制）后，宿主机每秒采样的平均差值为 −0.94%，95% 区间为 −2.63% 至 +0.78%；TrEnv-X 为 +0.63%，区间为 −0.69% 至 +1.97%。新 100 ms 持续采集的两后端完整轨迹影响已有独立对照；TrEnv-X 全程数字只覆盖协议中的局部采集，保存/恢复生命周期仍未验证。AgentENV 官方默认配置仍不能作出开销达标结论。

目前最重要的缺口是文件内容的计数范围。TrEnv-X 真实任务现已验证三个明确文件的驻留映射；upper（可写文件层）与 base 的三文件联合计数现已通过；未映射的宿主机文件缓存和其他任务文件没有完整计数。AgentENV 普通 guest 文件页也有未归因部分。不能据此报告整个任务的共享收益。

继续复用学长仓库的冻结动作、运行脚本、checkpoint 控制器和探针，以及本项目已有适配和报告；不新写沙箱运行时。源码保持[固定版本](../configs/source-revisions.json)，Cloud Hypervisor 保持 `9e0056eb750096f3bf8ed491c345ef9241fd527e`。第一阶段资源保持每 VM 2 CPU、4096 MiB、4 KiB 页；改变内存布局前重新验证地址映射假设。

## 阶段一：冻结比较条件，补齐文件页计数

**工作内容：**

1. 为下一批实验保存独立配置，明确任务、源码与补丁哈希、镜像 digest、模板内容清单、动作清单、cwd、环境变量和会话语义。记录实际生效的 host/guest 内核、CPU 绑定、频率、DAMON、balloon/free-page reporting（气球内存与空闲页回报）、I/O 模式和缓存条件。配置文本不足以证明功能实际开启或关闭。
2. 将 [TrEnv-X 单文件采集](../scripts/trenvx_file_diagnostic.py)改为接收命名文件清单，支持多个封存层，并处理文件覆盖、删除标记和整文件复制到 upper 的情况。先支持明确、可核对的文件集合，不默认为整个文件系统已覆盖。
3. 复用[物理页采集器](../scripts/measure_file_physical.py)，补 AgentENV 命名文件与 guest 页、host PFN 的归属核对。PFN 是物理页编号，用于判断多个 VM 是否实际使用同一页；只接受本次真实 RAM 映射证据，不猜地址或复用历史 PID。
4. upper、未映射缓存和无法归属的页分别报告。不能可靠计数的项目标为 NOT_MEASURED 或 PARTIAL；不以零替代。若全任务归属暂时做不到，先形成两后端一致的命名文件子集指标，并明确不能外推全部任务。
5. 补针对性回归检查：多层覆盖与删除、重复 PFN、匿名副本、未知页、进程身份变化、文件哈希变化、不支持的 extent 和离线结果篡改。先离线验证，再分别执行一次使用新采集器的 VM 短验证。

**通过条件：** 对声明的已知文件集合，计数与独立检查一致，未知页为零，原始观测可复算，清理通过；复杂任务允许 PARTIAL，但这时不能进入“全任务内存收益”验收。已经通过且未受改动影响的旧校准不重复运行。

**交付：** 生效配置、文件清单、范围说明、回归结果和两后端新短验证证据。扩展当前物理页报告，不再增加重复交接文档。

## 阶段二：用已知文件确认共享收益和写入隔离

采用 16 MiB 确定性非零文件，先运行一个 VM，再运行两个同时存活的 VM。每个后端分别比较以下条件：

| 条件 | 目的 | 必须核对 |
| --- | --- | --- |
| 两 VM 使用同一不可变文件 | 测共享文件的实际驻留量 | 内容相同、映射归属正确、跨 VM PFN 去重 |
| 两 VM 使用内容相同的独立副本 | 提供同一后端的对照 | 独立 backing；不能仅凭文件名或模板 ID 认定物理页独立 |
| 热缓存读取 | 测已驻留文件的共享 | 在实际读取前记录驻留状态 |
| 冷缓存首次读取 | 检查匿名副本等额外成本 | 在实际读取前确认目标文件冷，而非仅在 VM 启动前检查 |
| 仅一个分支写入 | 验证隔离和复制成本 | 另一个分支内容不变，写入后的页分类和 copy-up 范围可解释 |

冷缓存操作只针对本次拥有的文件，使用已有定向回收和驻留检查；不执行 host 全局 `drop_caches`。读取、挂载或内容校验可能使缓存变热，必须记录顺序。匿名页内容核验安排在规定分析边界，避免影响后续性能窗口。

**轮数：** 先做共享/独立副本 × 冷/热四种条件的短验证，每后端各一次，共八次条件运行；单侧写入另做必要短验证。短验证通过后，热缓存主比较每后端做五对“共享与独立副本”，两个后端共二十次条件运行；一对内条件前后顺序平衡。冷缓存五对作为独立扩展，仅在真实冷条件可控制且有新增研究问题时执行，不自动加入主比较。

如后端无法构造可靠的独立副本对照，明确报告该能力不支持，不随意修改运行时来强造对照，不宣称已隔离共享机制的因果效果。

**通过条件：** 读写内容、隔离、页归属、复算和清理全部通过；共享程度允许小于理想值，按实际页面报告，不能用理论页数替代观察。已有 AgentENV 双实例并非所有目标页完全共享，此现象保留。

## 阶段三：Exp1 同一步骤保存，两个分支真实续跑

两后端统一在 **第 022 步结束后保存**，该位置已包含源码修改。父实例执行冻结动作 001–022，两个恢复实例分别从 023–026 继续；每条逻辑路径仍是原来的完整 26 步。AgentENV 需要将现有第 013 步入口参数化；TrEnv-X 需要将当前单恢复实例控制器扩展为两个实例。复用原接口，不重写生命周期。

**顺序：** 先分别验证一个恢复实例，再验证两个同时存活的实例。为内存分析在指定边界保持两个实例存活；性能实验保持正常并发，不为扫描串行化所有工具调用。正式扫描边界为：保存前、恢复后尚未续跑、续跑结束后。主内存结果预先指定为两个分支续跑结束、仍存活时的同一分析边界；其他边界用于解释变化。

每条路径检查动作哈希、顺序、原始 HEAD、008/016 两个预期失败、关键 stdout、已修改源码、最终 patch、官方任务四个断言与预期输出快照，并检查全部本次资源。非零退出码不自动判平台失败，patch 一致不替代任务测试。两后端恢复语义分别判定，不能要求文件恢复组保持父进程，也不能将其描述为进程级 fork。

比较前核对任务文件内容、依赖和镜像来源一致。固定资源和缓存策略，CPU 绑定与频率使用本次拥有的 VMM 线程并核对归属；TrEnv-X 的对应控制尚需适配。保持历史配置记录，新配置另命名，不沿用旧监控验收结论。若涉及共享服务重启或扩大系统调频修改范围，先讨论影响。

**正式轮数：五对。** 一对为 AgentENV 两分支运行一次、TrEnv-X 两分支运行一次，共十次后端实验、二十条恢复后的分支路径；短验证不计入。每对独立重新创建父实例与 checkpoint，不把同一个 checkpoint 的多个分支当作多次独立重复。预先固定顺序与随机种子，使后端在前/在后的次数尽量平衡。

失败记录和重试均保留。协议发生变化时新建实验批次，不能悄悄替换失败或较慢的运行。没有有效关闭采样对照或计数覆盖不足时，停止相应性能或全任务收益结论，继续可独立完成的正确性检查。

**交付：** 五对逐轮结果、任务级或明确子集的物理页曲线、guest/host 内存曲线、阶段时延、正确性与清理汇总。跨后端结果属于完整实现的比较；要将差异归因于共享文件层，需结合阶段二的同后端对照。两个分支稳定后才考虑四个分支，先做一次试运行、重新测空间峰值；暂不直接扩到八个分支。

## 阶段四：按新范围验证监控和阶段耗时

区分两种运行模式：

- **性能模式：** 宿主机每秒采样、异步事件和轻量时间戳；guest 周期采样默认关闭，不进行精细物理页扫描。
- **内存分析模式：** 指定边界扫描物理页，记录扫描、guest 元数据读取和内容验证各自耗时，以及可能改变缓存的操作。

逐项记录模板构建、创建至工具可用、guest 工具执行、控制器工具调用、checkpoint、本机可恢复、restore 至工具可用、传输、测量、删除和归档。远端持久化未验证就单列为未验证。全部路径实际完成时间直接测量，不把并发调用耗时之和当端到端耗时。

历史 ≤5% 判据只保留在原实验范围，PPT 没有规定性能阈值。新资源配置或新的“创建至删除，包含采样启停”范围，先做关闭/开启采样和关闭/关闭采样的平衡短验证，再按预先确定的五组方案量化增幅及区间，同时报告关闭采样之间的自然波动。需要拆分 host 与 guest 时，每组采用六种条件各两次的 12 次方案；比较保存/恢复时另定阶段边界和留存预算，不直接沿用普通重放协议。不能仅因区间包含零就宣称无影响，也不为得到满意结果不断追加相同长测。

此项扩大开销验收是条件任务，不先于文件页主比较，也不要求重复配置完全相同的已验收组。guest 周期采样另行验证。精细扫描只报告实测成本，不预先承诺 ≤5%。采样最大值统一称“观测峰值”。

## 阶段五：扩大任务与调度，补部署和异常路径

按以下顺序推进，每项先单次正确性验证，通过后才另行确定正式统计批次：

1. 验证[第一版组合入口](../scripts/47-closeout-v1.sh)的一次完整执行。其组成步骤已有证据，入口整体尚只做过语法检查；此项可在前述代码改造期间穿插，但必须满足磁盘条件。
2. 选择学长 Exp3 的 Prettier #6604，先 GRPO，再 BPO、TVCache，核对七条逻辑路径的输出对应。使用 Exp3 自己的入口，不误走公共 `run.sh` 的旧 Exp5 路由；生效配置、模板名和输出路径逐项检查。
3. 接入 Exp2 的四轮保存/恢复。它的动作是整理后的固定命令，不能称为原始轨迹逐字重放；其 TrEnv-X 内存快照加块设备恢复路径与 Exp3 文件层重建不同，需独立判定状态恢复能力。
4. 再增加 Xarray、Sphinx，保持任务镜像与冻结动作版本；已有学长报告没有 raw 的地方标为证据缺失，不能当成本机复现结果。只运行一次的历史对照不能提供方差估计。
5. 补与新增代码相关的保存、封存、恢复失败路径，核对 guest 解冻、VMM 恢复和资源清理。已有复制抛错与子进程超时结果不无故重测。
6. 在独立环境补从固定镜像开始的模板准备与全新机器部署。当前新目录复现复用已有服务、运行时和模板，不能替代此项。

GRPO/BPO/TVCache 仍只是既有调度形状，没有训练 RL 策略。BPO 不自动按策略熵选点，TVCache 不等于完整线上并发缓存。在线模型采集、更多调度变体和展示界面放在这些验证之后。

## 统一指标和结论规则

| 指标 | 报告方式 | 不允许的替代 |
| --- | --- | --- |
| Guest 内存 | 每 VM 的文件缓存、匿名内存、slab 等 | 与 host VMM 内存相加 |
| Host 内存 | 本次实例 cgroup、VMM PSS、共享服务与整机压力分列 | 服务 cgroup file 当单 VM 文件缓存 |
| 文件内容物理量 | 跨 VM 的目标文件页及经验证匿名副本按 PFN 合并去重；未知单列 | DAX 映射容量、映射 PSS、文件大小当驻留量 |
| 阶段耗时 | 原始起止事件与独立墙钟时间 | 并发调用总和当全部任务完成时间 |
| 正确性与清理 | 每条路径、每次运行逐项报告 | 缺失、跳过、超时计作 PASS |

对已完整归属的目标集合，物理量为 `4096 × 所有 VM 的目标驻留 PFN 并集大小`。各 VM 单独计数之和减去该并集，是这些映射之间的重复驻留量；它不是整个宿主机的净内存节省。共享组与独立副本组的物理量差值，才是同后端、同条件、同范围的实测收益。未映射缓存仍未测时，指标必须带上“目标 VMM 映射”范围。

逐轮原值和配对差值全部展示；均值或几何平均按指标含义选择，区间计算方法随脚本固定。五对用于第一批估计，不保证显著性或精确尾部时延；区间宽或包含零就报告不确定。保留配置、输入哈希、事件、样本、stdout/stderr、退出码、正确性、归档校验和清理结果，离线可复算。敏感日志与镜像留本机，Git 仅保存代码、配置及脱敏摘要。

## 磁盘与资源预算

2026-10-01 制定计划时只读检查空闲约 **51.6 GiB**。以下是规划值，尚不是新双实例代码验证过的峰值，也不是磁盘配额：

| 工作 | 开始前建议空闲量 | 依据与限制 |
| --- | --- | --- |
| 离线实现与已知文件小验证 | 使用各入口原门槛；现有小负载为 22/26 GiB | 不代表完整服务或新多实例实验都能使用该门槛 |
| 现有完整恢复/组合入口一次 | 至少 54 GiB，另留失败和非恢复运行结果余量 | 保留一次恢复归档按 6 GiB 规划，结束仍能满足下一次 >48 GiB 门槛；不是组合入口全部写入量上界 |
| 新两分支试运行一次 | 暂按 56 GiB 工作余量，归档留存另计 | 临时写入先按 32 GiB、停止线 20 GiB、额外余量 4 GiB；32 GiB 待试运行验证 |
| 五对两后端正式比较 | 暂按至少 86 GiB，外加 AgentENV 快照和其他新增留存 | 56 GiB 工作余量 + 五次 TrEnv-X 恢复归档各 6 GiB；试运行后按两后端实际分配量提高预算 |
| 四分支及更多任务 | 待两分支试运行后确定 | 不按两个分支线性外推磁盘峰值 |

该次检查的约 51.6 GiB 足够推进离线改造和符合既有门槛的小负载；不足以启动上述完整批次。86 GiB 规划值至少还差约 34.4 GiB，AgentENV 持久快照留存可能进一步增加需求。不能将普通非恢复运行的 40 GiB 预算直接套到 checkpoint 实验。

具体控制：

- 同一时间仅一个本项目磁盘写入实验，所有新目录共用 `.artifacts/trenvx-disk-writer.lock`，并保留每 0.25 秒检查、20 GiB 停止本次进程组的保护。该轮询不是硬配额，不能保证其他任务突然写入时仍有余量。
- 每次运行前重新读空闲量、其他实验进程和主机压力；归档后更新下一次预算。正式批次预算必须同时包括 AgentENV 持久快照、TrEnv-X 镜像、失败现场和原始数据。
- 首次两分支试运行测实际磁盘最高分配量、归档大小和归档耗时；若超出规划值，停止扩展并上调门槛。不能降低停止线强行跑完。
- 成功且无 checkpoint 的普通运行，可使用已有显式选项删除本次私有镜像，保留日志和镜像哈希。checkpoint、失败现场和关键参考归档不使用该选项；归档经完整校验后才移除本次解包目录。
- 空间不足时先列出确无新增参考价值的重复归档，或选择经检查的新存储位置；不在本次制定计划时删除数据。改变恢复镜像的留存规则须单独讨论，不能默默抛弃可恢复性。
- VM 启动、工具、保存、扫描、归档均使用有限超时和定向清理；新增阶段在短验证中核对超时值。失败先定位首个边界，不自动重复完整批次。

## 下一次开始时的具体顺序

1. 检查其他工作负载、磁盘与代码改动，生成下一批的生效配置和空间预算；不修改共享服务。
2. 实现阶段一的文件清单和归属扩展，运行离线回归；保留“只覆盖子集”的限制。
3. 使用新采集器完成两个后端的已知文件短验证，确认独立副本对照可用。
4. 依据实际空间先运行阶段二的五对热缓存比较；同时准备第 022 步两分支适配代码。各小负载的归档预算也须逐次检查。
